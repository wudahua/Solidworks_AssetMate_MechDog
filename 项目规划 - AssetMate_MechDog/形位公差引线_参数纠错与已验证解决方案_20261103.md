# 形位公差引线：参数纠错与已验证解决方案

> 针对 `形位公差引线-交接.zip`。
> 日期：2026-11-03。实测环境：SOLIDWORKS 2024 SP4（32.4.0）· Python + pywin32。
> 结论：**问题真实，根因是 `SetLeader3` 参数用错；正确参数已实测返回 0，并在 PDF 中显示引线。**

---

## 1. 交接中的关键错误

原调用：

```python
SetLeader3(1, True, 2, 0, True, True)
```

交接把它解释为：

```text
LeaderType, UseDocLeaderStyle, LeaderStyle, ArrowSize, UseDocArrowSize, LeaderBent
```

这不是官方签名。

### 官方签名

```text
SetLeader3(
  LeaderStyle,
  LeaderSide,
  SmartArrowHeadStyle,
  Perpendicular,
  AllAround,
  Dashed
)
```

因此原调用实际变成：

- `LeaderStyle = 1`（直线，不是转折）
- `LeaderSide = True`
- `SmartArrowHeadStyle = 2`
- `Perpendicular = 0`（关闭垂直转折）
- `AllAround = True`
- `Dashed = True`

返回值 `-2` 的官方含义是：

> **Leader attachment side setting is invalid（引线附着侧设置无效）**

所以 `-2` 不是成功，也不能用 `GetLeaderCount=1` 证明引线已正确生成。

---

## 2. 正确枚举与参数

本机 `swconst.tlb` 读取结果：

### LeaderStyle

```text
swNO_LEADER = 0
swSTRAIGHT  = 1
swBENT      = 2
swUNDERLINED = 3
```

### LeaderSide

```text
swLS_SMART = 0
swLS_LEFT  = 1
swLS_RIGHT = 2
```

### 国标转折引线推荐调用

```python
status = call_method(
    gtol_annotation,
    "SetLeader3",
    2,      # LeaderStyle = swBENT
    2,      # LeaderSide = swLS_RIGHT
    True,   # SmartArrowHeadStyle
    True,   # Perpendicular = True（垂直转折）
    False,  # AllAround = False
    False,  # Dashed = False
)
```

实测：

```text
SetLeader3 = 0（成功）
GetLeaderCount = 1
PDF 中出现指向目标边的引线
```

---

## 3. 附着关系仍然是前置条件

`SetLeader3` 只设置引线样式和特性，**不负责创建附着关系**。

本次实测采用：

```text
选中目标边
→ 对 GTol 调用正确的 SetLeader3
→ 重建并导出 PDF
```

如果要让框格指向实际被测要素，必须同时处理几何上下文：

- 创建 GTol 前先选中目标边/面，或；
- 对已有 GTol，先选中目标边，再设置引线；
- 不要只在空白位置创建框格，然后期待 `SetLeader3` 自动找到目标。

如果目标边无法选中，先修几何选择/附着问题，而不是继续改引线参数。

---

## 4. 推荐的工具实现

```python
# 前提：已经选中目标边/面，或 GTol 已附着到该几何
status = call_method(
    gtol_annotation,
    "SetLeader3",
    2, 2, True, True, False, False,
)

if status != 0:
    return {
        "ok": False,
        "error": "leader_style_failed",
        "status": status,
        "hint": "检查 LeaderSide 和 GTol 的几何附着关系",
    }

call_method(doc, "ForceRebuild3", False)

# 最后必须导出 PDF 验证引线实际可见
```

返回状态应这样解释：

| 返回值 | 含义 | 处理 |
|---:|---|---|
| 0 | 成功 | 继续做 PDF 验证 |
| -1 | 未知错误 | 检查对象和上下文 |
| -2 | LeaderSide 无效 | 改为 `swLS_RIGHT=2` 或检查附着关系 |
| -3 | 该注解不支持引线 | 确认对象确为 GTol |
| -4 | 该注解不能禁用引线 | 检查样式 |
| -5 | 不能禁用转折引线 | 检查样式 |
| -6 | 不允许下划线引线 | 不使用 `swUNDERLINED` |

---

## 5. 验收标准

必须同时满足：

```text
SetLeader3 返回 0
GetLeaderCount >= 1
PDF 中实际存在引线和箭头
```

只有 `GetLeaderCount=1` 不够；它可能在参数无效或几何退化的前提下出现。

建议在 `delivery_check` 中增加：

```text
leader_style_failed
leader_attachment_missing
leader_not_visible
```

---

## 6. 与圆柱度评审意见的关系

- 圆柱度属于形状公差，**不需要也不应引用基准**。
- 但形位公差框格需要指向被测要素时，**引线必须存在并指向正确边/面**。
- 不能因为圆柱度不需要基准，就接受悬空框格。

---

## 7. 最终结论

- 问题真实，但不是 `SetLeader3` 接口不可用。
- 根因是交接中的参数解释错误，并误读 `-2` 返回值。
- 正确调用为：

```python
SetLeader3(2, 2, True, True, False, False)
```

- 同时保留目标边/面的选择或附着关系。
- 本机已验证：返回 0，且 PDF 中实际显示转折引线。
