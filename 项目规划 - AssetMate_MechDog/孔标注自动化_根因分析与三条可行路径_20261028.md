## 1. 结论速查

### 1.1 三句话结论

1. **`0x100000` 常量是对的**，官方枚举 `swInsertholeCallout = 1048576`，失败报告的"假设 1"可以关闭。
2. **失败根因是入口选错**：`InsertModelAnnotations3` 只负责"把模型里已有的注解搬进图纸"，而孔标注是图纸侧按孔几何**现场生成**的注解，模型里没有源对象，所以必然零产出。
3. **即使走通，原来的统计方法也看不到孔标注**：`AddHoleCallout2` 返回的是 `DisplayDimension`，`IAnnotation.GetType = 4`（尺寸），不存在独立的 `swAnnotationType_HoleCallout`。判定必须用 `IDisplayDimension.IsHoleCallout`。

### 1.2 路径速查表

| 路径 | 适用 | 是否扫边 | 主要风险 | 建议级别 |
|---|---|---|---|---|
| **A. `AddHoleCallout2`** | 所有孔（光孔 / 沉孔 / 螺纹孔） | 只扫视图可见边 | **可能弹模态对话框** | 主路径，先过弹窗实测 |
| **B. `InsertThreadCallout`** | 有装饰螺纹线的孔（Hole Wizard 螺纹孔） | **零扫边** | 只覆盖螺纹孔 | 螺纹孔首选 |
| **C. 模型项目孔向导尺寸位** | Hole Wizard 孔，接受"原生 Ø/深度/位置尺寸"而非孔标注 | 零扫边 | 产出是尺寸不是孔标注 | 无人值守保底 |
| D. 模型侧预置孔标注再搬运 | 仅用于证明根因 | — | 要改模型 | 只做一次实验 |

### 1.3 优先级

```
第 1 步：AddHoleCallout2 弹窗实测（5 分钟，决定 A 是否可用于无人值守）
第 2 步：方案 C 落地（改动最小、零风险，先让孔信息能自动上图）
第 3 步：方案 B 落地（螺纹孔零扫边，代码量小）
第 4 步：方案 A 落地（通用孔标注，含性能预算与弹窗处置）
```

## 2. 根因分析：不是常量问题，是入口与检测方法问题

### 2.1 常量核查：官方枚举确认无误【官方】

| `swInsertSurfaces` | 4096 | 0x1000 |

| `swInsertHoleWizardProfileDimensions` | 65536 | 0x10000 |

**结论**：`0x100000` 与官方一致。失败报告第五节"假设 1（常量错）"排除，无需再读 `SolidWorks.Interop.swconst.dll`。

> 附带收益：`swInsertGTols = 0x20`、`swInsertSFSymbols = 0x80`、`swInsertDatums = 0x2`、`swInsertDatumTargets = 0x4` 也在同一张表里。v0.5 的形位公差可顺带做一次"模型侧已有 Gtol 时能否搬入图纸"的验证（见 §11 开放问题 Q4）。

### 2.2 语义根因：模型项目只"搬运"，不"生成"【官方 + 推断】

`InsertModelAnnotations3` 官方定义：

> **Inserts model annotations into this drawing document's currently selected drawing view.**
> （把**模型注解**插入到图纸视图中。）

签名与参数【官方】：

```text
InsertModelAnnotations3(Option, Types, AllViews, DuplicateDims, HiddenFeatureDims, UsePlacementInSketch)
  Option   : swImportModelItemsSource_e，0=整个模型 / 1=所选特征 / 2=所选组件 / 3=仅装配体
  Types    : swInsertAnnotation_e 按位或
  AllViews : True=所有视图；False=仅当前选中视图
  返回值   : 插入的 IAnnotation 对象数组   ← 此前实验未使用
```

孔标注的性质【推断，与实测完全吻合】：

- 孔标注的文本（`Ø5 通孔`、`M6×1 - 6H`、`沉孔 Ø11 深 6`）是 SolidWorks 在**图纸环境**里依据孔特征几何与 `calloutformat.txt` **即时拼出来**的。
- 普通零件（无论拉伸切除孔还是 Hole Wizard 孔）的模型里**并不存在"孔标注"这个注解对象**。
- 因此 `Types` 里带不带 `swInsertholeCallout`，都没有可搬运的源对象 → 产出为零 → 两组实验逐类型完全相同。

**这解释了全部实测现象**，包括"B 组是标准 Hole Wizard 孔也没有孔标注"。零件因素、视图选择、版本差异都不是主因。

> 失败报告的"假设 2（该 API 不处理孔标注）"方向正确，但更准确的说法是：**该 API 处理孔标注，但只能搬运模型中已存在的孔标注**。

### 2.3 检测方法失效：孔标注是 DisplayDimension，不是独立注解类型【官方】

`IDrawingDoc.AddHoleCallout2` 官方定义：

```text
Function AddHoleCallout2(X As Double, Y As Double, Z As Double) As System.Object
  X/Y/Z : 孔标注位置，单位米（图纸坐标）
  返回值 : Display dimension representing the hole callout   ← 关键
  可用性 : SOLIDWORKS 2001Plus FCS, Revision 10.0
```

由此推出对象模型：

```
IDrawingDoc.AddHoleCallout2(x, y, 0)
        │  返回 IDisplayDimension
        ├─ .IsHoleCallout                → 是否孔标注【官方】
        ├─ .GetHoleCalloutVariables()    → CalloutVariable 数组（SW2016+）【官方】
        ├─ .GetText(swDimensionTextAll / Prefix / Suffix / CalloutAbove / CalloutBelow)
        ├─ .GetNameForSelection          → 供 SelectByID2 使用的名字【官方】
        ├─ .GetDimension2                → 关联的模型尺寸（若有）
        └─ .GetAnnotation.GetType        → 4（Dimension）
```

**因此对失败报告第三节统计方法的修正**：

| 原做法 | 问题 | 改为 |
|---|---|---|
| 遍历 `view.GetAnnotations`，按 `IAnnotation.GetType` 计数 | 孔标注会被计入 `4`（尺寸），与普适尺寸混在一起 | 遍历视图尺寸对象，用 `IsHoleCallout` 区分 |
| 期待出现 `swAnnotationType_HoleCallout` | 该枚举值在这条路径上不会出现 | 用 `IsHoleCallout = True` 作为唯一判定 |
| 忽略 `InsertModelAnnotations3` 返回值 | 放弃最直接的证据 | 先读返回数组，再决定是否需要二次扫描 |

`GetHoleCalloutVariables()` 返回 `CalloutVariable` 数组，元素按 `VariableType` 分为三类接口【官方】：

| VariableType | 接口 | 可读属性 |
|---|---|---|
| `swCalloutVariableType_Angle` | `ICalloutAngleVariable` | `Angle` |
| `swCalloutVariableType_Length` | `ICalloutLengthVariable` | 长度值 |
| `swCalloutVariableType_String` | `ICalloutStringVariable` | `String` |

每个变量还有 `VariableName`。这是**把孔标注与模型孔径/深度做对账**的官方数据通道，比解析文本可靠，应作为 `add_hole_callout` 回读校验的主用手段（SW2016+ 可用；更早版本退化为文本比对）。

### 2.4 真正的拦路虎：模态对话框【官方】

`AddHoleCallout2` 的 Remarks 原文：

> **When you call this method, the user must click OK in the dialog that shows the system-generated hole callout.**

含义：

- 该 API 在设计上是"半交互"的——选边后调用，SolidWorks 弹出孔标注对话框，需人工点确定。
- 该备注自 2001Plus 起就存在，**是否在 SW2026 仍然如此，官方文档没有更新说明，必须实测**。
- 如果仍弹窗，那么"孔标注无人值守"的瓶颈**不是扫边 400 秒，而是这个对话框**。之前所有性能优化都解决不了它。

处置策略见 §3.5。

### 2.5 环境前提：`calloutformat.txt`【实战】

孔标注的格式由孔标注格式文件驱动：

- 中文版典型位置：`C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\lang\chinese-simplified\calloutformat.txt`（另有 `calloutformat_2.txt`）。
- 英文版：`...\lang\english\`。
- 设置入口：系统选项 → 文件位置 → **孔标注格式文件**。
- 文件缺失或路径指向旧版本时，症状是**孔标注能插上但螺纹规格等字段缺失**，并可能弹"找不到 calloutformat.txt"。

因此 `add_hole_callout` 必须把"格式文件路径存在且可读"列为 preflight，否则会出现"API 返回成功但内容不对"的假完成——正是本项目设计原则第一条要防的事。

## 3. 方案 A：AddHoleCallout2（通用孔标注主路径）

### 3.1 适用范围与前置条件

| 项 | 要求 |
|---|---|
| 孔类型 | 光孔、沉孔、锪孔、螺纹孔均可（只要有可选圆形边） |
| 图纸状态 | 目标视图已生成、已重建；**新建图纸先保存一次**（既有坑：SW2026 未保存时插入 API 可能返回 True 但实体回读不到） |
| 视图状态 | `ActivateView` 成功，且已 `ClearSelection2(True)` |
| 格式文件 | `calloutformat.txt` 路径有效（§2.5） |
| 交互 | 弹窗实测结论已知（§3.5） |
| 线程 | 所有 COM 调用在同一 STA 线程 |

### 3.2 为什么选边方式要改

失败报告沿用的思路是"扫全模型边 → 拿精确点位 → `SelectByID2` 选边"。两处都该改：

| 项 | 旧 | 新 | 理由 |
|---|---|---|---|
| 扫描范围 | 全模型边（260 条，>400 s） | `view.GetVisibleEntities2(comp, 1)`，只扫该视图可见边 | 数量级下降，且孔标注本就只需要视图内圆边 |
| 选取方式 | `SelectByID2("", "EDGE", x, y, z, ...)` 依赖精确点位 | `IEntity.Select4(Append, Data)`，直接选边对象 | 不需要点位，避免坐标变换误差 |
| 候选过滤 | 无 | `IsCircle` + 完整圆 + 半径与台账孔径匹配 | 进一步砍掉绝大多数边 |

`Select4` 在公开实战宏里就是用于"选圆边 → 孔标注"这一场景的【实战】；官方 VBA 示例用 `SelectByID2`【官方】。两条路径都保留，`Select4` 为主、`SelectByID2` 为降级。

### 3.3 完整流程（12 步）

```
0  preflight：calloutformat.txt 存在；图纸已保存；视图清单就绪
1  ActivateView(target_view)
2  ClearSelection2(True)
3  comps = view.GetVisibleComponents                 （属性）
4  对每个 comp：edges = view.GetVisibleEntities2(comp, 1)   （1 = swViewEntityType_Edge）
5  过滤：curve.IsCircle 且为完整圆
6  取 CircleParams → 半径 r（米）；与 build_feature_ledger 的孔径清单匹配，得到候选孔集
7  对每个候选孔（超时预算内）：
     a. ClearSelection2(True)
     b. entity.Select4(False, None)                  （单选该圆边）
     c. disp = drawing.AddHoleCallout2(x, y, 0)       （米，图纸坐标；含弹窗处置）
     d. 回读：disp 非空 → IsHoleCallout → GetHoleCalloutVariables / GetText
     e. 与模型孔规格比对（孔径 / 深度 / 螺纹），不一致记 fail
8  统计 inserted / failed / skipped，超预算立即中止并报告
9  ClearSelection2(True)
10 EditRebuild3 + GraphicsRedraw2
11 导出 PDF/PNG 供证据链使用（verify_drawing_rendering）
```

### 3.4 参考实现【待测】

> 以下为结构参考，需在真机调试。所有长度单位注意：COM 用**米**。

```python
import time
import win32com.client

M_TO_MM = 1000.0
EDGE_TYPE = 1                 # swViewEntityType_Edge
SCAN_BUDGET_S = 25.0          # 单视图扫边+标注硬预算
RADIUS_TOL_M = 1e-4           # 0.1 mm，孔径匹配容差


def _full_circle_radius_m(edge):
    """返回完整圆半径（米）；非圆或圆弧返回 None。"""
    try:
        curve = edge.GetCurve
        if not curve.IsCircle:
            return None
        if edge.GetStartVertex is not None:      # 有起点 = 圆弧
            return None
        return float(curve.CircleParams[6])      # 半径在索引 6，单位米
    except Exception:
        return None


def _collect_candidate_edges(view, target_radii_m):
    """只扫该视图可见边，按半径预筛。返回 [(edge, radius_m)]。"""
    found, seen = [], set()
    try:
        comps = view.GetVisibleComponents
    except Exception:
        return found
    if comps is None:
        comps = []
    for comp in comps:
        try:
            edges = view.GetVisibleEntities2(comp, EDGE_TYPE)
        except Exception:
            continue                              # 必须传 comp，传 None 会 DISP_E_TYPEMISMATCH
        if edges is None:
            continue
        for edge in edges:
            r = _full_circle_radius_m(edge)
            if r is None:
                continue
            if target_radii_m and not any(abs(r - t) <= RADIUS_TOL_M for t in target_radii_m):
                continue                          # 与台账孔径不匹配，直接跳过
            key = round(r, 6)
            if key in seen:                       # 同半径去重（同孔上下两条圆边）
                continue
            seen.add(key)
            found.append((edge, r))
    return found


def add_hole_callouts(drawing, view, target_radii_m=None, text_anchor=None):
    """drawing: IDrawingDoc；view: IView；text_anchor: (x_m, y_m) 标注文字落点。"""
    t0 = time.time()
    drawing.ActivateView(view.Name)
    drawing.ClearSelection2(True)

    results = {"inserted": [], "failed": [], "skipped": [], "budget_exceeded": False}
    candidates = _collect_candidate_edges(view, target_radii_m)

    for idx, (edge, radius_m) in enumerate(candidates):
        if time.time() - t0 > SCAN_BUDGET_S:
            results["budget_exceeded"] = True     # 不再出现 400 秒无反馈
            break
        try:
            drawing.ClearSelection2(True)
            entity = win32com.client.Dispatch(edge)
            if not entity.Select4(False, None):   # False=单选；True=追加
                results["failed"].append({"index": idx, "reason": "Select4 returned False"})
                continue

            x, y = text_anchor or _default_anchor(view, idx)
            disp = drawing.AddHoleCallout2(x, y, 0.0)   # 可能弹模态对话框，见 3.5
            if disp is None:
                results["failed"].append({"index": idx, "reason": "AddHoleCallout2 returned None"})
                continue

            if not disp.IsHoleCallout:            # 判定孔标注的唯一正确方式
                results["failed"].append({"index": idx, "reason": "not a hole callout"})
                continue

            results["inserted"].append({
                "index": idx,
                "radius_mm": round(radius_m * M_TO_MM, 3),
                "text": disp.GetText(0),           # swDimensionTextAll，索引值待真机核对
                "name_for_selection": disp.GetNameForSelection,
            })
        except Exception as exc:                   # 含弹窗未处理导致的超时/异常
            results["failed"].append({"index": idx, "reason": str(exc)})

    drawing.ClearSelection2(True)
    drawing.EditRebuild3()
    results["elapsed_s"] = round(time.time() - t0, 2)
    return results


def _default_anchor(view, stack_index):
    """简化落点策略：视图右外侧纵向堆叠，避免圆心坐标变换（见 3.6）。"""
    outline = view.GetOutline                     # [xMin, yMin, xMax, yMax]，米
    return (outline[2] + 0.015,                   # 右边界 +15 mm
            (outline[1] + outline[3]) / 2 - stack_index * 0.010)
```

配套的回读对账（SW2016+）：

```python
def read_callout_variables(disp):
    """把孔标注拆成结构化变量，用于与模型孔规格比对。"""
    out = {}
    try:
        variables = disp.GetHoleCalloutVariables()   # 返回 CalloutVariable 数组
    except Exception:
        return out
    for v in variables or []:
        name = getattr(v, "VariableName", None)
        vtype = getattr(v, "VariableType", None)
        value = None
        for attr in ("String", "Angle", "Length"):   # 依 VariableType 只有其一有效
            if hasattr(v, attr):
                try:
                    value = getattr(v, attr)
                    break
                except Exception:
                    pass
        out[str(name)] = {"type": vtype, "value": value}
    return out
```

### 3.5 弹窗处置（决定 A 能否无人值守）

**第一步：5 分钟实测**。在 SW2026 上打开一张含孔图纸，手工选一条圆边，执行一次 `AddHoleCallout2(0.2, 0.2, 0)`，观察：

| 实测结果 | 结论 | 处置 |
|---|---|---|
| 不弹窗，直接生成 | 官方 Remarks 已过时 | A 可无人值守，标 `verified` 候选 |
| 弹孔标注对话框，点确定后生成 | 半交互 | 见下面三条 |
| 弹窗且返回前一直阻塞 | 强交互 | A 只能有人值守，无人值守走 B/C |

若弹窗，三条处置路线：

1. **pywinauto 自动点确定**（本机有界面、可接受 UI 自动化时）
   - 监听 SolidWorks 主窗口下的孔标注对话框，出现即点"确定"。
   - 必须加超时与窗口标题/类名白名单，防止点错对话框。
   - 能力标 `pilot`，文档注明依赖 UI 状态、远程/锁屏/最小化场景不可用。
2. **有人值守模式**：`add_hole_callout` 增加 `interactive=True` 参数，弹窗由操作员点，工具负责选边、定位、回读与对账。这是**最诚实且立即可交付**的形态。
3. **无人值守降级**：检测到弹窗即中止 A，自动改走方案 B（螺纹孔）或方案 C（孔向导尺寸），并在结果里写明降级原因。

禁止做法：用 Note 文本伪造孔标注、或把"调用了 API"当作"已生成孔标注"。

### 3.6 坐标与单位的三个坑【推断，需真机核对】

1. **`AddHoleCallout2` 的 X/Y/Z 是图纸坐标（米）**，不是模型坐标，也不是视图内相对坐标。
2. **`CircleParams` 的圆心是模型空间坐标**。若想把标注引线精确落在某个圆旁，需要做模型→视图→图纸的坐标换算（`IView` 的变换对象），不能直接拿圆心当 X/Y。
3. **简化策略**：参考实现用"视图右外侧堆叠"落点，完全绕开坐标变换，先保证标注生成正确；精确贴孔放置作为后续增强，单独验证换算链路。

### 3.7 性能预算

| 项 | 旧方案 | 新方案 |
|---|---|---|
| 扫边范围 | 全模型 260 条 | 单视图可见边，且只处理完整圆 |
| 候选数 | 全部圆边 | 半径与台账匹配 + 同半径去重后 |
| 超时 | 无（实测 >400 s） | 单视图 25 s 硬预算，超时结构化返回 |
| 选取 | 每条边一次点位 `SelectByID2` | 每条候选边一次 `Select4` |
| 主要残余成本 | — | `AddHoleCallout2` 逐孔调用 + 可能的弹窗 |

孔特别多时（如配电箱 80 个圆柱面）：**不要逐孔全标**。按出图规划（plan_drawing）给孔标注配额，同规格孔只标一处并写 `n×`，其余靠中心标记与孔位尺寸表达。这既符合真实图纸习惯，也把调用次数压到个位数。

### 3.8 验收标准

- A 组（拉伸切除光孔）：至少 1 个孔生成 `IsHoleCallout=True` 的标注，文本含正确 Ø 值。
- B 组（Hole Wizard M6）：生成含 `M6` 的孔标注；若文本缺螺纹规格，优先检查 `calloutformat.txt` 而不是改代码。
- 单视图总耗时 < 30 s；超预算必须返回 `budget_exceeded=True` 而非挂起。
- 重复执行不产生重复标注（幂等，见 §8.4）。
- `delivery_check` 中"0 处孔标注 / 模型 N 个圆柱面"类 blocker 能据此正常解除或保留，且有据可依。

## 4. 方案 B：InsertThreadCallout（螺纹孔零扫边）

### 4.1 原理【官方 + 实战】

- `IDrawingDoc.InsertThreadCallout()`：无参数，向图纸插入螺纹标注，作用于**当前选中的装饰螺纹线**（可用性 SW2001 起）【官方】。
- `IView.GetCThreads` 可直接拿到该视图的装饰螺纹线对象集合，**完全不需要扫边**【实战】。
- 选中方式：`SelectByID2(完整名称, "CTHREAD", 0,0,0, False, 0, Nothing, 0)`，名称由三段拼成【实战】：
  `装饰螺纹线注解名 @ 根 DrawingComponent 名 @ 视图名`。

### 4.2 参考实现【待测】

```python
def add_thread_callouts(drawing, view):
    """为视图内所有装饰螺纹线生成螺纹标注。零扫边。"""
    drawing.ActivateView(view.Name)
    results = {"inserted": [], "failed": []}
    try:
        threads = view.GetCThreads
    except Exception:
        threads = None
    if not threads:
        return results                              # 无装饰螺纹线：光孔走方案 A/C

    try:
        root_comp_name = view.RootDrawingComponent.Name
    except Exception:
        root_comp_name = None

    for ct in threads:
        try:
            ann_name = ct.GetAnnotation.GetName
            full_name = f"{ann_name}@{root_comp_name}@{view.Name}" if root_comp_name else ann_name

            drawing.ClearSelection2(True)
            ok = drawing.Extension.SelectByID2(
                full_name, "CTHREAD", 0, 0, 0, False, 0, None, 0)
            if not ok and root_comp_name:           # 降级：只用注解名@视图名
                ok = drawing.Extension.SelectByID2(
                    f"{ann_name}@{view.Name}", "CTHREAD", 0, 0, 0, False, 0, None, 0)
            if not ok:
                results["failed"].append({"thread": ann_name, "reason": "select failed"})
                continue

            drawing.InsertThreadCallout()           # 无参数
            results["inserted"].append({"thread": ann_name})
        except Exception as exc:
            results["failed"].append({"reason": str(exc)})

    drawing.ClearSelection2(True)
    drawing.EditRebuild3()
    return results
```

### 4.3 回读与对账

- `InsertThreadCallout` 无返回值【官方】，**不能**以"没报错"作为成功证据。
- 回读方式：比较调用前后视图的注解/尺寸集合差集，取新增项，读其文本，检查是否含 `M6`、`M6×1` 等期望规格。
- 与 `build_feature_ledger` 的螺纹孔特征对账：数量与规格不一致即记 `pending`，不放行。

### 4.4 局限

| 局限 | 影响 |
|---|---|
| 只覆盖有装饰螺纹线的孔 | 光孔、沉孔无螺纹时仍需 A 或 C |
| 模型未生成装饰螺纹线（被关闭/简化） | `GetCThreads` 为空，需提示开启或改路径 |
| 产出是"螺纹标注"而非"孔标注" | 图面表达不同，但制造信息等价；`delivery_check` 应按"孔信息是否完整"判定，而非"必须存在孔标注对象" |

### 4.5 与 A 的组合策略

```
view.GetCThreads 非空 → 先走 B，把螺纹孔全部解决
剩余光孔/沉孔        → 走 A（或 C）
```

这样 B 组（M6 螺纹孔）可以**零扫边**完成，A 只处理真正的光孔，整体调用量与弹窗次数都最少。

## 5. 方案 C：模型项目孔向导尺寸位（零风险保底）

### 5.1 思路

放弃"必须有孔标注对象"，改为**让孔信息以原生尺寸的形式自动上图**。这些尺寸是真正的 `DisplayDimension`，能过 `verify_dimension_attachments`，不存在伪造问题，也没有弹窗风险。

### 5.2 位掩码组合【官方】

| 位 | 值 | 作用 |
|---|---|---|
| `swInsertDimensionsMarkedForDrawing` | 0x8000 | 已标记为工程图用的尺寸 |
| `swInsertHoleWizardProfileDimensions` | 0x10000 | **孔向导轮廓尺寸**（孔径、沉孔径、深度等） |
| `swInsertHoleWizardLocationDimensions` | 0x20000 | **孔向导定位尺寸**（孔位） |

推荐组合：`0x8000 | 0x10000 | 0x20000 = 0x38000`，十进制 `229376`。

### 5.3 参考实现【待测】

```python
MASK = 0x8000 | 0x10000 | 0x20000     # 229376

def insert_hole_dimensions(drawing, all_views=True):
    drawing.ClearSelection2(True)
    inserted = drawing.InsertModelAnnotations3(
        0,          # swImportModelItemsFromEntireModel
        MASK,
        all_views,  # True=所有视图；False 需先选中视图
        False,      # DuplicateDims：False=不允许重复（按官方语义真机核对）
        False,      # HiddenFeatureDims
        True,       # UsePlacementInSketch
    )
    drawing.EditRebuild3()
    # 返回值就是证据：插入的 IAnnotation 数组
    count = 0 if inserted is None else len(inserted)
    return {"inserted_count": count, "raw": inserted}
```

注意两点：

1. **必须用返回值做证据**，而不是事后按 `GetType` 猜（§2.3）。
2. 本次失败实验已证明：单独加 `0x100000` 不会多产出任何东西。所以方案 C 的掩码里**不要**再带 `0x100000`，避免误导后来者。

### 5.4 与 A 组零件的关系

A 组（拉伸切除孔，无 Hole Wizard 特征）不受 `0x10000/0x20000` 影响，仍只有模型尺寸。这类零件的孔信息保底靠现有 `add_drawing_dimension` 在圆边上标 Ø（已验证可用）。因此方案 C 的完整形态是：

```
Hole Wizard 孔 → 0x10000|0x20000 自动出孔径/孔位尺寸
拉伸切除孔     → add_drawing_dimension 标 Ø（必要时补深度）
```

### 5.5 验收

- B 组：相比只传 `0x8000`，新增孔径/孔位尺寸数量 > 0，且逐条可回读关联几何。
- A 组：不产生异常，孔 Ø 由 `add_drawing_dimension` 补齐。
- `reconcile_ledger` 的孔相关覆盖率提升，无缺孔 blocker 误报。

## 6. 方案 D：模型侧预置孔标注（仅作解释性验证）

目的：**用一次实验彻底关闭"是不是 API/版本不支持"的疑问**，不作为产品路径。

步骤：

1. 在 B 组零件（M6 螺纹孔）的**零件环境**里，手工为孔添加孔标注到模型注解视图。
2. 保存零件，回到图纸，执行 `InsertModelAnnotations3(0, 0x100000, True, False, False, True)`。
3. 观察返回数组与图纸变化。

判读：

| 结果 | 结论 |
|---|---|
| 这次能搬入孔标注 | 坐实"位正确、但只能搬运模型已有对象"，§2.2 根因成立 |

**不做进产品**：要修改客户模型，副作用大、不可批量。

## 7. 决策树与场景矩阵

### 7.1 决策树

```
需要孔信息上图
│
├─ 视图有装饰螺纹线（GetCThreads 非空）

│     │
│     └─ 无人值守保底

│           └─ 拉伸切除孔     → add_drawing_dimension 标 Ø
│
```

| 有界面、操作员在场 | A（`interactive=True`） | 工具选边定位，人只点确定 |

## 8. 统一验证规范（所有插入类功能通用）

### 8.1 三级证据

| 级别 | 证据 | 强度 |
|---|---|---|
| L1 | API 返回值（对象非空、返回数组长度） | 必要不充分 |
| L2 | 实体属性回读（`IsHoleCallout`、`GetText`、`GetHoleCalloutVariables`、尺寸关联几何） | 主证据 |
| L3 | 最终产物核验（PDF 文字/位置、PNG 目视） | 交付前最后一道 |

**任何"插入类"工具至少要拿到 L2，禁止只用 L1。**

### 8.2 孔标注专用判定

```text
是孔标注   ⇔ DisplayDimension.IsHoleCallout == True
内容正确   ⇔ GetHoleCalloutVariables 与模型孔规格一致（优先）
             或 GetText 含期望 Ø/深度/螺纹（降级）
不是证据   ⇔ IAnnotation.GetType 出现某个新枚举值（该路径不存在）
```

### 8.3 实验对照要求

- 每次实验用**新建图纸**或显式清空，避免上一轮残留被误计为新增（失败报告 §4.2 已踩过）。
- 统计必须**分类分解**，不允许只看总数。
- 变量唯一：同一零件、同一视图、同一掩码之外的其他参数保持一致。

### 8.4 幂等

- 执行前先枚举已有孔标注（`IsHoleCallout`）与其关联几何，已标注的孔跳过。
- 重复执行同一命令，第二次应返回 `inserted=0, skipped=n`，而不是标注翻倍。

| Q5 | `InsertThreadCallout` 是否也有交互 | 若有，B 的无人值守价值下降 | T4 时一并观察 |
| Q6 | 同半径去重可能漏掉"同径不同深度"的孔 | 孔信息不完整 | 去重键加入深度/特征 ID，而非只半径 |
| Q7 | 多实体/装配图下 `RootDrawingComponent` 命名差异 | B 的选择名可能拼错 | 已实现名称降级，需 T4 覆盖装配场景 |
