## 竞品调研（haunchen/solidworks-mcp 源码）
**关键发现，可直接解 v0.5 卡点 1（孔标注性能）：**
1. 该项目**没有**独立孔标注函数。孔标注走 `InsertModelAnnotations3` 位掩码 `SW_INSERT_HOLE_CALLOUT = 1048576 (0x100000)` 批量导入 → **零扫边成本**。这是本项目应改用的路径。
2. 若要手工定位圆边：`view.GetVisibleComponents`（属性，逐个 component）→ `view.GetVisibleEntities2(comp, 1)`（1 = swViewEntityType_Edge），只返回该视图**可见**边，远少于模型 260 条；传 None 会 DISP_E_TYPEMISMATCH。
3. 圆/弧判定：`edge.GetCurve.IsCircle` + `edge.GetStartVertex is None`（None = 完整圆）。
4. 取圆心半径：`curve.CircleParams` → (cx,cy,cz, ax,ay,az, r)，r 在索引 `[6]`，单位**米**，需 ×1000 转 mm。
5. 选边用 `view.SelectEntity(edge, append)`，**不要用 SelectByID2**（pywin32 late-binding 下类型问题）。选视图用 `SelectByID(name,"DRAWINGVIEW",0,0,0)` 5 参数版。
6. 建尺寸：`Extension.AddDimension(x,y,0,d)` 遍历 d=0..3，失败退化 `AddDimension2`。
7. 该项目无鉴权、默认绑 0.0.0.0:8080，仅 SW2021 实测 — 不采用其部署方式，只借鉴 COM 调用写法。

## 孔标注位掩码方案：已证伪（用户实测 + 官方文档复核）
- 用户做了 A/B 对照（拉伸切除孔 vs Hole Wizard M6 螺纹孔），`types` 加不加 `0x100000` 结果逐类型完全相同。
- **常量没错**：官方 `swInsertAnnotation_e` 确认 `swInsertholeCallout = 1048576 (0x100000)`。
- **语义错了**：`InsertModelAnnotations3` 是"把模型里已有的注解搬进图纸"，孔标注是图纸侧按孔几何现生成的，模型里没有源对象 → 必然零产出。§7.2 方案 1 应标记证伪。
- **检测方法也不对**：`IDrawingDoc.AddHoleCallout2(X,Y,Z)` 返回 **DisplayDimension**，`IAnnotation.GetType` = 4；判定孔标注要用 `IDisplayDimension.IsHoleCallout` / `GetHoleCalloutVariables`，不存在独立的 swAnnotationType_HoleCallout。
- `InsertModelAnnotations3` **返回插入的 IAnnotation 数组**，此前未读，应作为首选证据。
- **真正风险是弹窗**：官方 Remarks 明确 `AddHoleCallout2` 调用后"user must click OK in the dialog"（2001Plus 时期备注，需在 SW2026 实测是否仍弹）。弹窗处置 = pywinauto 点 OK（pilot）或改走替代路径。
- **螺纹孔零扫边替代**：`view.GetCThreads` → `ct.GetAnnotation.GetName` → `SelectByID2(name+"@"+RootDrawingComponent.Name+"@"+view.Name, "CTHREAD",...)` → `doc.InsertThreadCallout`。
- **保底零风险替代**：模型项目用 `0x8000|0x10000|0x20000`（Marked + HoleWizardProfile + HoleWizardLocation）出原生孔径/孔位尺寸。
- 选边官方/论坛两种写法：`SelectByID2("","EDGE",x,y,z,...)` 或 `IEntity.Select4(False, Nothing)`，后者更稳。
- 预检 `calloutformat.txt`（中文版 `...\lang\chinese-simplified\`），缺失会导致孔标注丢螺纹规格。

## 形位公差复核（16:02 用户第二轮验证报告）
- 用户四路径全失败：`doc.InsertGtol()`/`part.InsertGtol()` 在 **Invoke** 阶段 MEMBERNOTFOUND（has_member=True），`Extension.CreateGtolData` 在 GetIDsOfNames 阶段不存在，`swInsertGTols=0x20` 搬运零产出。结论"本环境无法创建"。
- **我方复核推翻三点**：① `CreateGtolData` 不是官方 API，路径 3 不构成证据；② "Invoke 失败 ⇒ 运行时未实现 ⇒ 早绑定也失败"推理断裂，vtable 根本不走 IDispatch，且可能是接口指针不对（IModelDoc2 vs IDrawingDoc）或 tlb 版本错配；③ 选面实际未成功（`face.Select2` False + `body.GetFaces` 少括号），前置条件未排除。
