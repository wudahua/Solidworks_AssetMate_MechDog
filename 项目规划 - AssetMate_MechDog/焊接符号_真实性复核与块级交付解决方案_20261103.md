# 焊接符号：真实性复核与块级交付解决方案

> 针对 `焊接符号-交接.zip`。
> 日期：2026-11-03。复核环境：SOLIDWORKS 2024 SP4（32.4.0）· Python + pywin32。
> 本文只给结论与解决方案，不修改项目代码。

---

## 1. 问题真实，且不是符号名写错

交接中的现象成立：焊接符号只有引线和数字，没有角焊三角形等图形。

本机进一步复核了以下调用：

| 尝试 | 结果 |
|---|---|
| `SetText(..., "FILL", ...)` | 文本可写入，图形未生成 |
| `InsertWeldSymbol(..., "<WELD-FILL>", ...)` | 文本可写入，图形未生成 |
| 官方 `BUTT` 示例参数 | 文本可写入，图形未生成 |
| `SPOT` 点焊圆 | 仍未生成预期图形 |
| `SetProcess(True, "135", True)` | 不改变图形生成结果 |

同时确认：

- `gtol.sym` 存在，且包含 `*FILL` 的三条 LINE 定义；
- `swDisplayWeldSymbols = True`；
- 当前焊接标准为 GB（7）；
- `GetLineCount = 3`、`GetTriangleCount = 0`；
- 导出 PDF 仍只有数字，没有预期符号。

所以问题不是简单的 `FILL` / `FILLET` 拼写、符号库缺失或 `SetProcess` 未调用。

> 注意：`FILL` 的三条边是 LINE，不是独立填充三角形对象。
> 因此 `GetTriangleCount=0` 本身不能证明角焊缺失，**最终必须以 PDF 图面验证为准**。

---

## 2. 当前可确认的故障层级

`SetText` 和旧版插入接口都能把符号名作为文本保存，但**符号库几何没有实例化**。

这属于 `IWeldSymbol` 原生对象生成问题，而不是普通的文字参数问题。
当前不能仅凭 `SetText=True`、`GetText` 回读或 `GetLineCount` 判定焊接符号已完成。

---

## 3. 交付优先方案：用原生草图/块生成标准角焊符号

如果目标是让图纸立即具备正确的角焊图形，建议使用**原生草图实体或块**生成，而不是继续等待 `IWeldSymbol` API。

### 3.1 方案性质

- 生成的是图纸中的真实线段、参考线和文字，视觉与标准角焊一致；
- 可以进一步封装成块，便于复用和整体移动；
- **它不是 `IWeldSymbol` 对象**，工具必须如实返回 `representation="sketch_block"`，不能声称是原生焊接注解。

### 3.2 角焊图形的几何组成

以插入点 `(x, y)` 为参考线左端，尺寸单位为米：

```text
参考线：(x, y) → (x + 0.020, y)

三角形：
  (x + 0.006, y) → (x + 0.006, y + 0.004)
  (x + 0.006, y + 0.004) → (x + 0.010, y)
  (x + 0.010, y) → (x + 0.006, y)

焊脚尺寸文字：放在三角形左侧，例如 (x + 0.001, y + 0.004)
引线：从参考线右端指向目标边/接头
```

这对应 `gtol.sym` 中 FILL 的三条 LINE，不需要依赖 `IWeldSymbol` 的图形实例化。

### 3.3 使用现有工具的实现方式

可复用项目的 `add_sheet_line` 和 `add_note`：

```python
def add_fillet_weld_representation(drawing_path, x, y, size_text="6"):
    # 参考线
    add_sheet_line(drawing_path, x, y, x + 0.020, y, save=False)

    # 角焊三角形
    add_sheet_line(drawing_path, x + 0.006, y, x + 0.006, y + 0.004, save=False)
    add_sheet_line(drawing_path, x + 0.006, y + 0.004, x + 0.010, y, save=False)
    add_sheet_line(drawing_path, x + 0.010, y, x + 0.006, y, save=False)

    # 焊脚尺寸
    add_note(drawing_path, str(size_text), x + 0.001, y + 0.004, save=True)
```

若需要引线，按目标边位置再添加一条线段。
正式使用时建议将这些实体封装为块，避免逐线管理和误移动。

### 3.4 交付验收

不能只检查 API 返回，应导出 PDF 后检查：

- 参考线存在；
- 三角形三条边存在；
- 焊脚尺寸文字存在；
- 引线指向正确目标。

`representation="sketch_block"` 必须在返回 JSON 和交付说明中保留。

---

## 4. 若必须使用原生 IWeldSymbol

### 4.1 保留的正确调用

官方 `SetText` 的符号名应直接使用：

```python
ws.SetText(True, "", "FILL", "6", "", 0)
```

旧版 `IDrawingDoc.InsertWeldSymbol` 的标准-类型格式应为：

```python
doc.InsertWeldSymbol(
    "", "<WELD-FILL>", "6",
    False, False, False, False, False, False, ""
)
```

`WELD` 是 `gtol.sym` 中的 ISO 焊接库名，**不要写 `<ISO-FILL>`，也不要写 `<WELD-FILLET>`**。

### 4.2 但当前环境不能把这些当成已验证修复

本机上述调用仍只生成文本，没有生成图形。
因此如果项目强制要求原生 `IWeldSymbol`，还需要继续做：

1. 在 UI 中手工插入一个角焊符号并录制宏，比较实际调用序列；
2. 用早绑定或 C# interop 跑同一个官方示例，排除 pywin32 绑定问题；
3. 在 SW2026 上复测，区分 SW2024 SP4 缺陷与环境问题；
4. 检查 SolidWorks 的焊接符号文档属性、图层和符号库文件位置；
5. 必要时用官方示例文件 `weldment_box3.sldprt` 排除当前模型/图纸因素。

只有 PDF 出现原生焊接图形后，才能把 `weld_symbol` 标为 `verified`。

---

## 5. 不建议继续投入的方向

| 方向 | 原因 |
|---|---|
| 继续换 `FILL` / `FILLET` 拼写 | 官方支持的是 `FILL`，拼写不是根因 |
| 继续尝试 `<ISO-FILL>` | 标准库名错误，应使用 `WELD` |
| 用 `SetProcess` 生成图形 | 该方法只设置工艺文本和参考框 |
| 只看 `GetTriangleCount` | FILL 是 LINE 组合，该计数不能替代图面验证 |
| 只看 `SetText=True` / `GetText` | 只证明文本写入，不证明图形生成 |

---

## 6. 最终建议

- **需要马上交付正确图纸**：采用第 3 节的原生草图/块方案，明确标注 `representation="sketch_block"`，并用 PDF 验收。
- **必须保留原生焊接注解语义**：按第 4 节继续做 UI 宏录制、早绑定/C# 和版本对照；在当前环境下不要宣称已修复。
- 无论采用哪条路径，都不能把“只有引线和数字”的符号当作合格焊接标注交付。
