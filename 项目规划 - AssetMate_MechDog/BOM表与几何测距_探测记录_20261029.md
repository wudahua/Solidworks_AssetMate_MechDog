# BOM 明细栏与实体几何测距：探测记录与结论

> 日期：2026-10-29 凌晨
> 目标：解决《v0.6.3 出图排版能力缺口与钣金 QC 空白》剩下两项
> 结论：**BOM 表签名已破解但返回 None，几何测距未开工**。两项都未完成，记录下探测过程，避免下次从错误签名重来。

## 一、BOM 明细栏

### 1.1 已破解的部分：真实签名是 10 个参数

此前所有 `DISP_E_TYPEMISMATCH` 的根因是**参数表从头就错了**。官方 2024 文档（`IView.InsertBomTable4`，2013 FCS 起可用）：

```text
InsertBomTable4(
  UseAnchorPoint        : bool      ← 第一个参数是 bool，不是模板路径
  X                     : double
  Y                     : double
  AnchorType            : int       (swBomConfigurationAnchorType_e)
  BomType               : int       (swBomType_e)
  Configuration         : string
  TableTemplate         : string    ← 模板在这里，第 7 位
  Hidden                : bool
  IndentedNumberingType : int       (swNumberingType_e)
  DetailedCutList       : bool
) → BomTableAnnotation
```

**我先前一直按 6 参数调，把模板路径塞在第 1 位**，等于让 bool 参数接收字符串——必然类型不匹配。

### 1.2 用正确签名后的结果：不再报错，但返回 None

```python
view.InsertBomTable4(False, 0.02, 0.02, 0, 0, '', tpl, False, 0, False)
# → None（无异常）
```

已排除的变量：

| 变量 | 试过的值 | 结果 |
|---|---|---|
| BomType | 0 / 1 / 2 | 全部 None |
| 模板路径 | 确认存在 `...\lang\chinese-simplified\bom-standard.sldbomtbt`（`os.path.exists` 为真） | 仍 None |
| 模板为空 | `''` | None |
| 图纸是否已存盘 | 先 `SaveAs3` 再插入 | None |
| 视图激活 | `ActivateView` 后调用 | 无差别 |
| UseAnchorPoint | False（用 X/Y） | None |

### 1.3 另一条官方路径：`IModelDocExtension.InsertBomTable3`

成员存在（`GetIDsOfNames` 通过），但参数表与 `IView` 版不同：

```
10 参数 → 类型不匹配（报在第 2 个参数位置）
 6 参数 → 类型不匹配（报在第 6 个参数位置）
 3 参数 → 「非选择性的参数」（参数太少）
```

签名未能确定，无进一步尝试价值——在不知道正确参数表的情况下试错，成本高且成功率低（这正是本月反复吃亏的模式）。

### 1.4 第二轮：`InsertBomTable5` 与正确的 `swBomType_e`

早上继续试的两条新线索，都没成：

**线索 A：`InsertBomTable5`**（文档标注 4 已 Obsolete，由 5 取代）

真实签名 **11 个参数**（比 4 多一个 `DissolvePartLevelRows`），可用性 **SOLIDWORKS 2024 FCS**——本机正是 2024 SP4，理应可用：

```python
view.InsertBomTable5(False, x, y, 0, bomtype, '', tpl, False, 0, False, False)
# → None，四种 BomType 全部 None
```

**线索 B：`swBomType_e` 的真实值不是 0/1/2**

我先前按 0/1/2 猜，实际枚举是 **1=TopLevelOnly / 2=PartsOnly / 3=Indented / 4=Flattened**。补测 1/2/3/4：

```
InsertBomTable5  bomtype=1 -> None
InsertBomTable5  bomtype=2 -> None
InsertBomTable5  bomtype=3 -> None
InsertBomTable5  bomtype=4 -> None
InsertBomTable4  bomtype=1..4 -> 全 None
```

### 1.5 第三轮：通用表格 `InsertTableAnnotation2` 也返回 None

反馈里说这个「能创建但 X/Y 相对锚点」，说明在他们那次是成功的。本机实测：

```
InsertTableAnnotation2(True,  0.02, 0.02, 0, '', 5, 3)   -> None
InsertTableAnnotation2(False, 0.02, 0.02, 0, '', 5, 3)   -> None
+ EditSheet / ActivateSheet 后再插                        -> None
+ 传模板路径而非空串                                       -> None
+ 先 ActivateView 再插                                    -> None
4 参数 / 3 参数                                          -> 「非选择性的参数」（参数太少）
```

### 1.6 结论：这个环境拒绝一切表格插入

累计试过的维度：

| 维度 | 试过的值 |
|---|---|
| API | `InsertBomTable4` / `InsertBomTable5` / `InsertTableAnnotation2` |
| 参数个数 | 3 / 4 / 5 / 6 / 7 / 10 / 11 |
| BomType | 0 / 1 / 2 / 3 / 4 |
| 模板 | 空串 / 确认存在的 `.sldbomtbt` |
| 上下文 | 视图激活 / `EditSheet` / `ActivateSheet` / 存盘后再插 |
| 锚点 | `UseAnchorPoint` True / False |
| 文档对象 | `IDrawingDoc` / `IView` / `IModelDocExtension` |

**全部返回 `None` 或参数错误，没有一次成功，也没有一次抛出业务异常。**

「返回 None 而非报错」意味着调用被接受、创建被静默拒绝。最可能的三个原因：

1. **文档属性禁止**（`Document Properties > Tables` 相关开关，或模板本身不允许表格）
2. **模板格式不兼容**——文件存在 ≠ 可用，`.sldbomtbt` 可能与当前版本/语言不匹配
3. **需要「编辑图纸格式」模式**——`EditSheet` 与 `EditTemplate` 是两个不同的状态，我试的是前者

### 1.7 剩余可能性（下次从这几条继续）

| # | 方向 | 说明 |
|---|---|---|
| 1 | **宏录制**（最优先） | 界面手工插入明细栏 → 录制 → 看真实调用序列。这是唯一能确定「本机到底支不支持」的办法，与形位公差那次靠怀疑派发方式突破是同一思路 |
| 2 | 界面手工试一次 | 直接在 SW 里插入 BOM 表，能否成功？如果界面也插不进，就与本工具无关 |
| 3 | 换 `.drwdot` 模板 | 当前用的是 `gb_a3.drwdot`；换 SolidWorks 自带的标准模板再试 |
| 4 | `EditTemplate` 而非 `EditSheet` | 两者是不同的编辑状态，表格可能只在图纸格式模式下允许 |
| 5 | 检查文档属性开关 | `GetUserPreferenceToggle(swOneConfigOnlyTopLevelBom)` 等，看是否被设为禁止 |
| 6 | `Configuration` 传真实配置名 | TopLevelOnly 时应留空，但若 BomType 判定被我搞错，空串会导致「不创建」 |

### 1.5 现状与替代

`check_capabilities` 里 `bom_table` 标 `unsupported`，workaround：

```
add_sheet_line 画表格网格 + add_note 逐格写文字
```

**能画出表格，但不是原生 BOM**：不随装配更新、无件号联动、无自动行号。对交付有实质影响，必须在交付说明里讲清楚。

## 二、实体几何测距

### 2.1 状态：未开工

`sheet_metal_qc` 里这三项仍是 `not_checked`：

| 检查项 | 需要什么 |
|---|---|
| 最小折弯边（≥ 4t + R） | 遍历折弯面 → 取外侧边 → 量长度 |
| 孔到折弯线距离（≥ 2t + R） | 取孔心坐标 → 取折弯线 → 算三维距离 |
| 折弯半径 vs 0.5t | 读折弯特征的圆角半径（`GetDefinition` 返回空，需换路径） |

### 2.2 技术路径（下次直接照这个做）

```text
1. 遍历 body 的所有面：IBody2.GetFaces()  →  [IFace2]
2. 筛圆柱面：face.GetSurface().IsCylinder  →  孔；取半径 + 轴线
3. 筛平面 + 相邻两个非平行面：定位折弯带的平面
4. 折弯线 = 两平面交线（IEdge 或面法向叉积求方向 + 一个点）
5. 孔到折弯线距离 = |(孔心 - 线上一点) × 线方向| / |线方向|
6. 最小折弯边：折弯面外侧边长度（IEdge.GetCurveParams2 取端点距）
```

**风险点**：`GetFaces()` 在 46 组件的装配上很慢（与 `GetVisibleEntities2` 同一量级，单视图可达 25–151 s）。**必须按视图可见面取，不能遍历整个模型**——这是 0.6.3 那次 82 秒零产出的同类问题。

### 2.3 为什么本轮没做

不是技术不可行，是**需要新的几何遍历代码 + 逐个验证**，预计 2–3 小时。凌晨三点做这个，写出来的大概率是要返工的代码。

`not_checked` 会继续如实报，不给假通过——这比匆忙实现一个算错的检查要好。

## 四、一句话建议

BOM 表这条**先做宏录制**（5 分钟），而不是继续在文档参数表上猜——形位公差那次就是靠"先怀疑派发方式"才突破的，而这次需要的其实更简单：**看界面手工插入时到底调了什么**。

几何测距则应单独排一轮完整时间，并从一开始就用「视图可见面」而不是全模型遍历。
