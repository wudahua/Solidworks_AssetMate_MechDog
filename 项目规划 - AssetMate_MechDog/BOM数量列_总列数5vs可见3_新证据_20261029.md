## 一、关键新证据：`TotalColumnCount = 5`，但 `ColumnCount = 3`

这是我此前完全漏掉的判据。

```
当前表：  RowCount=1   ColumnCount=3   TotalColumnCount=5
宏成功表：RowCount=10  ColumnCount=4   TotalColumnCount=5
```

**两边的 `TotalColumnCount` 都是 5。**

也就是说：

- 表格**定义了 5 列**
- 我的表只**显示 3 列**（缺 2 列）
- 宏成功的表显示 4 列（缺 1 列）

**所以「数量列」（以及另一列）不是「不存在」，是「没显示」。**

这解释了为什么此前所有参数调整都无效——**列一直在那儿，我在改的是数据源，不是可见性**。

方案 §2 的第一条判断成立，而且比我预期的更靠前。

## 二、但取消隐藏的操作把表格改坏了

### 2.1 先读隐藏标志：说「没隐藏」

```python
ole = table._oleobj_
disp = ole.GetIDsOfNames('ColumnHidden')      # → 131130

ole.Invoke(disp, 0, DISPATCH_PROPERTYGET, True, 3)   # → False
ole.Invoke(disp, 0, DISPATCH_PROPERTYGET, True, 4)   # → False
```

`ColumnHidden(3)` 和 `ColumnHidden(4)` 都返回 `False`——**按这个读法，它们本来就是可见的**。

但这与 `ColumnCount=3` 矛盾。

### 2.2 再写隐藏标志：列数反而减少

```python
ole.Invoke(disp, 0, DISPATCH_PROPERTYPUT, True, 3, False)
call_method(doc, 'ForceRebuild3', False)
# → ColumnCount: 3 → 2
```

**从 3 变成 2。** 我本想让它变 4。

### 2.3 三种调用形式的结果

| 形式 | 返回 | 列数变化 |
|---|---|---|
| `tb.ColumnHidden` 整体赋值 | `Property can no...`（不可写） | — |
| `call_method(tb,'SetColumnHidden', i, False)` | `未知名称`（方法不存在） | — |
| `call_method(tb,'ColumnHidden', i, False)` | ok（实为 propget，忽略第二参数） | 3 → 3 |
| `ole.Invoke(disp, 0, PROPERTYPUT, True, 3, False)` | ok | **3 → 2** |

**最后一种「成功」了，但效果与预期相反。**

### 2.4 我的判断

`TotalColumnCount` 与 `ColumnCount` 的语义我没搞清楚：

| 可能 | 含义 |
|---|---|
| A | `TotalColumnCount` = 模板定义的列数；`ColumnCount` = 实际渲染（有数据的）列数 |
| B | `ColumnCount` 是可见列，`TotalColumnCount` 含隐藏列，但 `ColumnHidden` 的索引与列索引不是一一对应 |
| C | 这个版本的 `ColumnHidden` 需要不同的索引基准（0-based vs 1-based） |

**我倾向 A**：列数差异反映的是「没关联上配置，所以那些列没有渲染」，而不是「被隐藏」——这也与「配置数量列未生成」的旧结论并不冲突，只是换了个解释角度。

若是 A，那正确解法不是改 `ColumnHidden`，而是**让配置关联生效**（回到 `SetConfigurations`，但那个调用我试了 3 种封送都无效）。
