## 1. 结论与优先级

### 1.1 工具封装差异：优先查“活动文档”，不是缓存

最可疑的执行序列是：

```text
工具已打开图纸并获取 doc/view
→ 工具发现装配没打开，调用 open_document(assembly)
→ SolidWorks 活动文档切换为装配
→ 工具继续使用原来的 view 调 InsertBomTable4
→ 图纸不是活动文档，插入返回 None
```

独立脚本之所以成功，是因为它的顺序不同：

```text
先打开装配
→ create_drawing
→ _open_drawing
→ 最后活动文档仍是图纸
→ 插入成功
```

**这与报告描述的“脚本成、工具败”高度一致。**

### 1.2 空表：先走官方 BomFeature 配置接口，不先查宏的 8 参入口

`SetConfigurations(['Default'])` 失败是因为签名不对。官方是：

```text
SetConfigurations(OnlyVisible: bool, Visible: object, Names: object)
```

并且是**三个参数**，需要同时传：

- 配置名数组 `Names`
- 对应的可见性布尔数组 `Visible`

空表时应先打印：

- `view.ReferencedConfiguration`
- `BomFeature.TableType`
- `BomFeature.GetConfigurationCount`
- `GetConfigurations(False, ...)` 返回的配置名与可见性

如果所有配置都不可见，`SetConfigurations` 才是直接解法；如果配置正常，则查组件抑制、轻化和视图引用。

### 1.3 建议时间分配

| 问题 | 建议 |
|---|---|
| 工具失败 | 先加“重新激活图纸”修复，预计 10 分钟可见分晓 |
| 空表 | 给 30 分钟查配置可见性与组件状态；仍无进展再暂停 |
| 宏 8 参入口 | 暂不作为阻塞项 |

## 2. 问题一：工具失败最可能是活动文档被切走

### 2.1 为什么 `doc.ActivateView` 不足以保证安全

工具持有的是：

- 一个图纸 `doc`
- 一个属于该图纸的 `view`

但如果中间调用了 `open_document(assembly)`，SolidWorks 的 UI 与命令上下文可能已切到装配。
此时对非活动图纸执行 `ActivateView`，并不能等价于：

```text
激活图纸文档 → 激活 sheet → 激活 view
```

插入类 API 往往依赖活动文档上下文，且失败方式可能正是静默返回 `None`。

### 2.2 必须在插入前确认的硬条件

```text
sw.ActiveDoc 就是目标 SLDDRW
doc 就是该活动文档
当前 sheet 就是 view 所属 sheet
view 是重新从该 sheet 获取的装配视图
插入前没有再次打开/激活其他文档
```

不要只打印 `doc.GetTitle`；必须打印 **`sw.ActiveDoc`**。

## 3. 工具侧修复：重新激活图纸并重新获取视图

### 3.1 修复原则

任何可能引起文档切换的操作之后，都重新建立图纸上下文：

- `open_document`
- `create_drawing`
- 激活装配查配置/组件状态
- 其他工具修改活动文档的操作

然后：

1. 重新激活图纸；
2. 重新获取 `doc`；
3. 激活目标 sheet；
4. 重新获取 `view`；
5. 立即插入，不再穿插模型操作。

### 3.2 参考结构【待测】

```python
import os


def insert_bom_in_tool(sw, drawing, drawing_path, assembly_path, template):
    # 1) 如确有需要，先打开装配
    if assembly_path:
        open_document(assembly_path)

    # 2) 关键：补开装配后，重新激活图纸
    # 优先复用项目已有的 _open_drawing/激活封装，不要在这里猜 ActivateDoc3 的标题格式
    doc = drawing._open_drawing(drawing_path)

    # 3) 重新获取 sheet/view，不使用打开装配之前缓存的 view
    sheet = doc.GetCurrentSheet
    sheet_name = sheet.GetName
    doc.ActivateSheet(sheet_name)

    views = sheet.GetViews
    view = next(v for v in views if getattr(v, "Type", None) != 1)
    doc.ActivateView(view.Name)
    doc.ClearSelection2(True)

    # 4) 插入前硬校验：活动文档必须是图纸
    active = sw.ActiveDoc
    print("active before insert:", active.GetTitle if active else None)
    print("drawing doc:", doc.GetTitle)
    print("sheet/view:", sheet_name, view.Name)
    assert active is not None
    assert active.GetTitle == doc.GetTitle, "活动文档不是目标图纸，停止插入"

    table = view.InsertBomTable4(
        False,
        0.24, 0.19,
        1,          # TopLeft
        2,          # TopLevelOnly
        "",         # TopLevelOnly 不指定 Configuration
        template,
        False,
        0,
        False,
    )
    return doc, view, table
```

### 3.3 如果项目 `_open_drawing` 不保证激活

则使用项目现有的文档激活函数，或在 `sw.ActivateDoc3` 成功后继续。
无论采用哪种方式，**都必须用 `sw.ActiveDoc.GetTitle == doc.GetTitle` 做插入前断言**，不要凭函数名假设它已激活。

### 3.4 视图缓存也要处理

即使文档对象仍有效，工具此前获取的 `view` 也可能对应旧的文档激活/图纸状态。
所以不是只重新激活 `doc`，还要重新执行：

```python
views = doc.GetCurrentSheet.GetViews
view = ...
```

## 4. 脚本与工具的上下文指纹对照

如果重新激活后仍失败，不要继续猜缓存。让两条路径在插入前各输出一份 JSON，再逐项比较。

```python
import os
import threading


def bom_context_fingerprint(sw, doc, view, args):
    active = sw.ActiveDoc
    sheet = doc.GetCurrentSheet
    return {
        "pid": os.getpid(),
        "thread": threading.get_ident(),
        "sw_active_title": active.GetTitle if active else None,
        "sw_active_path": active.GetPathName if active else None,
        "doc_title": doc.GetTitle,
        "doc_path": doc.GetPathName,
        "sheet": sheet.GetName,
        "view_name": view.Name,
        "view_type": getattr(view, "Type", None),
        "view_configuration": getattr(view, "ReferencedConfiguration", None),
        "selection_count": doc.SelectionManager.GetSelectedObjectCount,
        "args": list(args),
        "table_count": len(list(doc.GetFirstView.GetTableAnnotations or ())),
    }
```

比较顺序：

1. `sw_active_path` 是否都是目标图纸；
2. `doc_path` 是否一致；
3. `sheet` / `view_name` / `view_configuration` 是否一致；
4. `args` 是否逐项、逐类型一致；
5. `thread` 是否一致；
6. 最后才看进程内缓存。

**第一个不同项就是优先修复点。**

## 5. 问题二：空表先查 BomFeature 的配置可见性

### 5.1 为什么不是继续试 SetConfigurations(['Default'])

官方签名不是单参数：

```text
IBomFeature.SetConfigurations(
  OnlyVisible As Boolean,
  Visible As Object,
  Names As Object
) As Boolean
```

所以以下调用必然不对：

```python
bf.SetConfigurations(["Default"])
```

而只传 `VARIANT` 数组但不同时提供另一个数组，也不满足接口语义。

### 5.2 先采集四项信息

```python
bf = table.BomFeature

print("table type:", bf.TableType)
print("configuration count:", bf.GetConfigurationCount)
print("view configuration:", view.ReferencedConfiguration)
print("bf configuration:", getattr(bf, "Configuration", None))
```

然后获取配置数组。VBA 形式为：

```vba
Names = BomFeature.GetConfigurations(False, Visible)
```

pywin32 对 ByRef 数组的返回形态需要在本机打印一次：

```python
result = bf.GetConfigurations(False, None)
print(type(result), result)
```

预期要得到两组等长数据：

```text
Names   = ['Default', 'UP', ...]
Visible = [False, True, ...] 或类似布尔数组
```

如果返回是 `(Names, Visible)`，直接解包；如果是其他结构，先按实际结构归一化，不要再盲目套 VARIANT。

### 5.3 判读

| 现象 | 含义 | 下一步 |
|---|---|---|
| `Names` 为空 | BOM 没拿到模型配置，不是 SetConfigurations 问题 | 查视图模型引用、装配解析状态 |
| `Names` 非空，目标配置 `Visible=False` | 很可能就是空表原因 | 将目标配置设 True 后 SetConfigurations |
| 目标配置已 `Visible=True`，仍空表 | 配置可见性不是根因 | 查组件抑制、轻化、缺失引用 |
| `GetConfigurationCount=0` | 模型侧没有可用配置/模型未解析 | 先修模型上下文 |

## 6. TopLevelOnly 的正确配置流程

### 6.1 官方语义

- TopLevelOnly 可以显示多个配置的数量列。
- 用 `GetConfigurations` + `SetConfigurations` 管理。
- `OnlyVisible=False` 表示数组包含**所有可用配置**及各自可见性。
- 若只要当前视图配置，应把 `view.ReferencedConfiguration` 对应项设为 True，而不是盲选 `Default`。

### 6.2 参考实现【待测】

```python
def show_view_configuration_in_bom(table, view):
    bf = table.BomFeature

    result = bf.GetConfigurations(False, None)
    # 本机若返回 (Names, Visible)，按下面解包；否则先按打印结果调整
    names, visible = result

    names = [str(n) for n in names]
    visible = [bool(v) for v in visible]
    assert len(names) == len(visible)

    target = view.ReferencedConfiguration
    print("BOM configurations:", list(zip(names, visible)))
    print("target view configuration:", target)

    if target not in names:
        raise RuntimeError(f"视图配置 {target!r} 不在 BOM 可用配置 {names!r} 中")

    # OnlyVisible=False：传入的是所有可用配置及可见性
    for i, name in enumerate(names):
        visible[i] = (name == target)

    ok = bf.SetConfigurations(False, visible, names)
    print("SetConfigurations:", ok)
    return ok
```

调用后使用项目现有重建封装：

```python
call_method(doc, "ForceRebuild3", False)
print("rows:", table.RowCount)
```

### 6.3 若要显示所有配置

```python
visible = [True] * len(names)
bf.SetConfigurations(False, visible, names)
```

这会生成多个数量列；列数变化是预期行为，不要误判为模板错误。

## 7. PartsOnly / Indented 的配置流程

官方说明：非 TopLevelOnly 通常只显示一个配置，直接使用 `IBomFeature.Configuration` 更简单。

```python
bf = table.BomFeature
bf.Configuration = view.ReferencedConfiguration
call_method(doc, "ForceRebuild3", False)
print("rows:", table.RowCount)
```

注意：

- 配置名必须来自 `view.ReferencedConfiguration` 或装配 `GetConfigurationNames`，不要猜。
- `BomType=1` 是 PartsOnly，`BomType=2` 是 TopLevelOnly，`BomType=3` 是 Indented。
- 若 Configuration 赋值成功但 rows 不变，转 §8 查模型组件状态。

## 8. 如果配置正确仍只有表头

按顺序检查：

### 8.1 视图与 BOM 是否指向同一个装配和配置

打印：

```text
view 的模型路径
view.ReferencedConfiguration
装配当前配置
BOM Names/Visible
```

不要让视图引用 `UP`，BOM 却强行使用 `Default` 作为第一轮验证。

### 8.2 组件是否被抑制或排除在 BOM 外

空表最常见模型侧原因包括：

- 当前配置下组件被抑制；
- 组件设置为不包含在材料明细表中；
- 子装配/零件引用缺失；
- 轻化状态导致 BOM 数据未解析。

用项目已有的装配树/BOM 数据能力交叉检查：
**如果 `export_bom` 能返回 9 行，而图纸原生 BOM 为 0 行，优先查配置可见性与组件 BOM 选项；如果 `export_bom` 也为空，则不是图纸 API 问题。**

### 8.3 解析轻化并重建

在模型侧完成解析后，**重新激活图纸**，再重建：

```python
call_method(doc, "ForceRebuild3", False)
```

解析装配后同样需要执行 §3 的“重新激活图纸”。

### 8.4 检查缺失项显示策略

诊断阶段记录：

```text
BomFeature.KeepMissingItems
BomFeature.StrikeoutMissingItems
```

不要为了让行数好看而直接长期开启缺失项；先确认是否存在文件引用缺失。

### 8.5 与原宏图纸做同配置对照

在原 `BOM_TEST.SLDDRW` 上读取成功 BOM 的：

```text
TableType
Configuration / Names / Visible
ReferencedConfiguration
KeepMissingItems
```

与新图纸的空表逐项对比。这个对比比继续猜宏的 8 参入口更直接。

## 9. EditRebuild3 的本机写法更正

前一份方案写“Python 必须加括号”，这个说法对当前本机绑定不准确，应撤回。

本机实测：

```python
doc.EditRebuild3       # 返回 bool，是属性式映射
doc.EditRebuild3()     # TypeError: 'bool' object is not callable
```

因此本项目统一使用：

```python
call_method(doc, "EditRebuild3")
call_method(doc, "ForceRebuild3", False)
```

规则应写成：

> 不要凭 VBA 语法推断 pywin32 属性/方法映射；以本机 `call_method` 封装和实际返回类型为准。

## 10. 建议的 30 分钟验证顺序

| 时间 | 动作 | 判定 |
|---|---|---|
| 0–10 min | 工具内补开装配后重新激活图纸、重取 view、断言 ActiveDoc | 工具是否也能创建表格 |
| 10–15 min | 打印空表的 `TableType / ConfigurationCount / Names / Visible / view.ReferencedConfiguration` | 空表是否由配置不可见造成 |
| 15–20 min | TopLevelOnly 用三参 `SetConfigurations(False, visible, names)` 设置目标配置 | rows 是否增加 |
| 20–25 min | 检查组件抑制、BOM 排除、轻化与缺失引用 | 是否为模型侧空数据 |
| 25–30 min | 对比原宏成功 BOM 与新空表的配置和 BomFeature 属性 | 定位剩余差异 |

**只有以上都有日志仍失败，才投入宏入口、vtable 或 RunCommand。**

## 11. 交付判定与能力声明

当前不能把 `rows=1` 的原生 BOM 当成可交付成果。

建议状态：

```text
bom_table_native_python = partial
  - 已验证：独立脚本可创建原生 BomTableAnnotation + BomFeature
  - 未验证：工具路径稳定创建
  - 未通过：数据行填充与 export_bom 对账
```

交付门禁：

- `RowCount <= 1` → `pending` / `bom_table_empty`，不得称“明细栏已完成”。
- 工具路径未重新激活图纸的修复验证前，不启用自动装配图交付。
- 成功后必须对账：数据行数、零件号、数量、配置与 `export_bom` 一致。
- 原生 BOM 创建成功不代表内容正确，仍需 `delivery_check`。

## 12. 附录：枚举值与官方签名

### 12.1 枚举值确认

官方 VBA 示例：

```text
swBomType_PartsOnly    = 1
swBomType_TopLevelOnly = 2
swBomType_Indented     = 3
```

锚点：

```text
swBOMConfigurationAnchor_TopLeft     = 1
swBOMConfigurationAnchor_TopRight    = 2
swBOMConfigurationAnchor_BottomLeft  = 3
swBOMConfigurationAnchor_BottomRight = 4
```

所以 `capabilities.py` 中若曾写 `TopLevelOnly=1`，应修正；`AnchorType=0` 不应使用。

### 12.2 BomFeature 配置接口【官方】

```text
GetConfigurations(OnlyVisible: bool, Visible: byref object) → Names

SetConfigurations(
  OnlyVisible: bool,
  Visible: object,
  Names: object
) → bool
```

- TopLevelOnly：优先 Get/SetConfigurations。
- PartsOnly / Indented：优先 `BomFeature.Configuration`。
- `SetConfigurations` 必须是三个参数，不是 `SetConfigurations(['Default'])`。

### 12.3 参考来源

- SOLIDWORKS API Help：`IBomFeature.GetConfigurations` / `SetConfigurations` / `ISetConfigurations`。
- SOLIDWORKS API Help：`IView.InsertBomTable4`、TopLevelOnly 配置说明。
- SOLIDWORKS API 官方 BOM VBA 示例：`GetConfigurations(False, Visible)` 后调用 `SetConfigurations(..., Visible, Names)`。
