# P0 剖视无剖面线：真实性复核与解决方案

> 针对 `P0-剖视无剖面线-交接.zip`。
> 日期：2026-11-02。复核环境：SOLIDWORKS 2024 SP4（32.4.0）· Python + pywin32。
> 本文只给复核结论与解决方案，不修改项目代码。

---

## 1. 问题真实，但原报告不能把根因写成“拿不到 DrSection”

### 1.1 现象成立

交接包中的 `axis/drawing_p1.png` 与 `door/drawing_p1.png` 都显示：

- 剖视图已创建；
- 有外轮廓和 A-A 标记；
- 剖切区域没有任何 45° 剖面线。

所以“工具返回成功，但导出的图纸没有剖面线”是实际存在的问题，而且会影响交付正确性。

### 1.2 补充实测：DrSection 可以拿到

原报告的探测使用属性式访问：

```python
getattr(view, "GetSection")
```

这会在本机派发环境下报 `DISP_E_MEMBERNOTFOUND`。改为项目的显式方法派发后可以成功：

```python
sec_raw = call_method(view, "GetSection")
sec = win.Dispatch(sec_raw)
```

实测返回：

```text
DrSection <COMObject <unknown>>
GetAutoHatch             False
GetDisplayOnlySurfaceCut False
ScaleHatchPattern        False
SectionDepth             0.00635
GetLabel                 A
```

**因此，“IView.GetSection 在这个 binding 下不存在”这个判断应修正为：需要用 `call_method` 显式按 DISPATCH_METHOD 调用，并对返回的 PyIDispatch 再做 `win.Dispatch`。**

## 2. 目前不能下的结论

### 2.1 `ScaleHatchPattern=True` 不是“开启剖面线”

官方定义是“是否按剖视图比例缩放已有剖面图案”，不是控制有无剖面线。
不能把它当成修复开关。

### 2.2 `SetAutoHatch(True)` 对当前两个零件不适用

官方 `IDrSection.SetAutoHatch` 的 Remarks 明确：

> Automatic hatching applies only to assembly section views. **For section views of parts, this method has no effect.**

当前证据是 `axis` 和 `door` 两个**零件**，不是装配体。
所以 `SetAutoHatch(True)` 不是这两个用例的修复路径；它只应保留给装配剖视。

### 2.3 `options=32` 也不是剖面线开关

`swCreateSectionView_DisplaySurfaceCut = 32` 只表示“只显示被剖切线切到的表面”。
`options=0/4` 与剖面线是否生成没有直接关系，继续尝试这个位没有意义。

### 2.4 全局样式、材质和图案文件实测正常

补充读取结果：

```text
系统 swDrawingAreaHatchFillStyle = 2（Pattern）
系统 Pattern = ANSI31
零件文档 AreaHatchFillStyle = 2（Pattern）
零件 Pattern = ANSI32（钢）
剖面图案文件 sldwks.ptn 存在
```

所以不能再简单写成“没材质导致没图案”或“系统剖面样式为 None”。

### 2.5 剖切深度非零，且中间位置新建剖视仍无线

实测原剖视 `SectionDepth = 0.00635 m`，不是 0。
在主体中部另建 B-B 对照剖视并导出 PDF，仍然没有剖面线。
因此“只是剖切深度为 0”不成立，“剖切线稍微偏一点”也不是已证实根因。

---

## 3. 最可能的两类根因

按当前剩余证据，优先查下面两类，而不是继续调 hatch scale。

### A. 视图级“材质剖面线/区域剖面线”被关闭或显示属性异常

这类设置不一定体现在 `DrSection.SetAutoHatch` 上，零件剖视尤其如此。
可能包括：

- 视图级 Material crosshatch 未启用；
- 区域剖面线被设为 None；
- 剖面线颜色/图层与背景一致；
- 模板中的剖面线显示属性异常。

### B. 没有形成有效的实体剖切面

即使视图有轮廓、`edge_count` 正常，也不能证明剖切到了有效实体。
可能包括：

- 剖切平面只经过空腔或零厚度区域；
- 模型存在无效几何；
- 零件不是可正常剖切的实体（曲面、网格或导入几何异常）；
- 剖切范围被排除或实体状态异常。

**必须用 UI 对照和几何检查区分 A/B，不能只靠 `ok:true` 与边数。**

---

## 4. 推荐的解决顺序

### 第一步：先修正 API 访问方式

在 `add_section_view` 的诊断代码里统一改成：

```python
import win32com.client as win

sec = win.Dispatch(call_method(section_view, "GetSection"))
print("GetAutoHatch:", call_method(sec, "GetAutoHatch"))
print("DisplayOnlySurfaceCut:", call_method(sec, "GetDisplayOnlySurfaceCut"))
print("ScaleHatchPattern:", sec.ScaleHatchPattern)
print("SectionDepth:", sec.SectionDepth)
```

仅在**装配体**剖视时允许：

```python
call_method(sec, "SetAutoHatch", True)
```

零件剖视不要调用它。

### 第二步：做一次 UI 对照，并录制宏

在同一张图纸副本上，用界面手工创建与 API 相同的剖视：

| 结果 | 含义 | 下一步 |
|---|---|---|
| UI 有剖面线 | 文档/模型可以正常生成，工具创建或视图属性有差异 | 对比宏与 `DrSection` 属性，修复工具参数 |
| UI 也没剖面线 | 不是 API 独有问题 | 查模型几何、模板、视图级剖面线设置 |

**如果 UI 有线，务必开宏录制。** 这是拿到真实调用序列最短的方法，比继续猜枚举有效。

### 第三步：检查有效剖切几何

1. 让剖切线完整贯穿目标实体，避免只切到边缘、空腔或零厚度区域。
2. 对模型执行 SolidWorks 的“检查几何体”（Check Geometry）。
3. 确认模型是可剖切实体，而不是仅曲面/网格或无效导入体。
4. 若是多实体或装配，检查是否有实体/组件被排除在剖切范围外。
5. 将剖切线移到主体另一位置做对照，但不要只改 `SectionDepth` 数值就认为已验证。

### 第四步：在 UI 中检查视图级剖面线属性

在剖视图上检查区域剖面线属性：

- 选择 **Hatch**，不要选 None；
- 需要材料驱动时启用 **Material crosshatch**；
- 需要手动统一图案时，关闭 Material crosshatch 并选 ANSI31/ANSI32；
- 检查剖面线颜色与图层，确保不是白底白线；
- 重建后再次导出 PDF。

若手动选择 Hatch 后出线，说明根因是视图级剖面线属性，而非模型或创建 API。
随后用宏录制取得对应的可编程设置。

## 5. 建议的工具修复结构

### 5.1 创建阶段

```text
创建剖视
→ call_method(view, "GetSection") 获取 DrSection
→ 记录 AutoHatch / Scale / Depth / DisplayOnlySurfaceCut
→ 装配体才 SetAutoHatch(True)
→ 重建
```

### 5.2 交付前必须加剖面线验证

原报告提出的 `verify_hatch=True` 应保留，但它只是**验收门禁**，不是根因修复。

建议流程：

```text
建剖视 → 导出 PDF → 定位剖视窗口 → 统计内部非白像素/斜线密度
→ 低于阈值返回 hatch_missing
→ 不进入可制造交付
```

返回示例：

```json
{
  "ok": false,
  "error": "hatch_missing",
  "view": "剖面视图 A-A",
  "hint": "剖视已创建，但剖切面没有剖面线；检查有效剖切几何与视图级剖面线属性"
}
```

不要再用 `edge_count > 0` 或 `sanity.verdict == "ok"` 证明剖视合格。

---

## 6. 最小验证脚本骨架

```python
# section_view 是刚创建的剖视 IView
import win32com.client as win

sec = win.Dispatch(call_method(section_view, "GetSection"))

# 装配体专用；零件不要调用
if is_assembly:
    call_method(sec, "SetAutoHatch", True)

call_method(doc, "ForceRebuild3", False)
doc.GraphicsRedraw2()

# 导出 PDF 后做像素验证；不能仅凭 API 返回成功
result = verify_hatch_in_pdf(pdf_path, section_view)
if not result["has_hatch"]:
    return {
        "ok": False,
        "error": "hatch_missing",
        "detail": result,
    }
```

---

## 7. 最终判断

- **问题真实**，且应列为交付阻断项。
- `GetSection` 的入口问题可用 `call_method + win.Dispatch` 解决。
- 但“有剖视、无剖面线”的根因**尚未被当前证据唯一确定**。
- 不要直接采用 `ScaleHatchPattern=True` 或对零件调用 `SetAutoHatch(True)` 作为结论。
- 最短闭环是：**UI 对照 + 宏录制 → 区分视图属性与几何问题 → 按结果修复 → PDF 剖面线验证通过后再交付**。
