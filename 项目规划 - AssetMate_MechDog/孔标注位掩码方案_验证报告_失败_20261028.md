# 孔标注位掩码方案验证报告（失败）

> 针对《SolidWorks工程图_竞品借鉴与v0.5实施方案.md》§7.1「借鉴资产 D：haunchen 的 COM 调用写法」
> 中提出的 `SW_INSERT_HOLE_CALLOUT = 0x100000` 方案。
> 验证日期：2026-10-28。验证人：本项目维护者。
> 环境：Windows 10 x64 · SOLIDWORKS 2026 SP0（中文版，RevisionNumber 34.0.0）· Python 3.11 + pywin32 · 晚绑定。

---

## 一、结论先说

**`InsertModelAnnotations3` 的 `types` 参数传 `0x100000` 没有产生任何孔标注。**

在两组零件（一组普通拉伸切除孔、一组 Hole Wizard 螺纹孔）上做了对照实验，
加与不加该位，图纸上产出的标注**类型与数量完全相同**。

因此 §7.1 提出的「零扫边方案」目前**没有可用的实现路径**，孔标注仍然不可自动化。
但失败原因可能不在方案本身，而在常量取值或调用上下文——见第五节，有 4 个待验证假设。

---

## 二、实验设计

要证明「位掩码无效」，必须先排除「零件不匹配」：

| 组 | 零件 | 孔的类型 | 目的 |
|---|---|---|---|
| A | `panel box.SLDPRT` | 拉伸切除出的圆孔 | 对照组：没有 Hole Wizard 特征 |
| B | `SAB1_0101_002.SLDPRT` | **M6 螺纹孔（Hole Wizard）** | 实验组：标准孔特征 |

> SolidWorks 的原生孔标注只识别 Hole Wizard 创建的孔。如果只用 A 组，失败可以解释为
> "零件没有异型孔"，所以必须用 B 组才能真正排除零件因素。

每组内做两轮插入，唯一变量是 `types` 掩码：

```python
HOLE = 1048576                      # 0x100000，取自方案 §7.1
VARIANT_1 = 32768                   # swInsertDimensionsMarkedForDrawing
VARIANT_2 = 32768 | HOLE            # 1081344

doc.ClearSelection2(True)
doc.InsertModelAnnotations3(0, mask, True, False, False, True)
doc.EditRebuild3
doc.GraphicsRedraw2
# 然后遍历所有视图的 GetAnnotations，按 GetType 统计
```

统计方式：遍历每个 view 的 `GetAnnotations`，读 `IAnnotation.GetType`，按类型计数。

```python
for view in views:
    for item in view.GetAnnotations:
        annotation = win32com.client.Dispatch(item)
        type_counts[int(annotation.GetType)] += 1
```

`swAnnotationType_e` 对照：`4` = 尺寸（Dimension）、`6` = 注释（Note）、`13` = 中心标记（CenterMark）。

## 三、实测数据

### A 组：`panel box.SLDPRT`（拉伸切除孔）

| 掩码 | 标注类型统计 | 总数 |
|---|---|---|
| `32768` | `{4: 44, 6: 82, 13: 4}` | 130 |
| `32768 \| 0x100000` | `{4: 44, 6: 82, 13: 4}` | 130 |

**逐类型完全相同。**

### B 组：`SAB1_0101_002.SLDPRT`（M6 螺纹孔，Hole Wizard）

| 掩码 | 标注类型统计 | 总数 |
|---|---|---|
| `32768` | `{4: 12, 6: 82}` | 94 |
| `32768 \| 0x100000` | `{4: 12, 6: 82}` | 94 |

**逐类型完全相同。**

### 关键点

- 两组的差异（44 个尺寸 vs 12 个尺寸）来自零件本身，与掩码无关
- 没有任何一轮出现 `swAnnotationType_HoleCallout`
- 也没有出现"新增了几条标注但类型未知"的情况——总数和构成都不变

## 四、排除的两个干扰因素

### 4.1 「零件没有 Hole Wizard 特征」

已排除。B 组零件经 `build_feature_ledger` 确认含 `M6 螺纹孔1` 特征，是标准 Hole Wizard 孔，
两轮结果仍无变化。

### 4.2 「标注被重复抑制」

第一轮实验曾观察到"第二次插入时标注数从 24 变成 27"，一度误以为掩码生效。
后续用完整类型统计发现：那 3 个增量来自**前一轮已插入标注被重新识别**，不是新增孔标注。
改用"同一文档内清空重插"的对照方式后，差异消失。

> 教训：只看标注总数会误判，必须按类型分解。建议后续任何"插入类"验证都按 GetType 统计。

## 五、四个待验证假设（按优先级）

### 假设 1：`0x100000` 不是孔标注的位（最可能）

方案 §7.1 标注该值来自 haunchen 源码常量。但 `swInsertAnnotation_e` 是**按位或**的枚举，
不同版本的成员值可能变化，且我们拿到的是二手转述。

**验证方法**（建议由规划者确认）：

1. 查 `SolidWorks.Interop.swconst` 类型库中 `swInsertAnnotation_e` 的权威定义
   - 本地路径参考：`C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\api\redist\SolidWorks.Interop.swconst.dll`
   - 或用 `oleview` / .NET 反射读枚举成员
2. 或查官方文档正文（`help.solidworks.com/2024/english/api/swconst/...swInsertAnnotation_e.html`
   的表格部分；本次用 WebFetch 只拿到目录，未取到正文）

**判断标准**：若权威值不是 `0x100000`，用正确值重跑第 2 节的实验即可定论。

### 假设 2：`InsertModelAnnotations3` 不处理孔标注

`types` 参数可能只接受「尺寸类」位（Marked / NotMarked），孔标注属于另一种注释类型，
需要单独的 API（例如先选中视图再调用，或 `IView.InsertHoleCallout` 之类的入口）。

**验证方法**：在同一零件上分别传 `types = 0x100000`（只传孔标注位，不带尺寸位），
观察是否产生任何标注。若一条都没有，说明该位被忽略。

### 假设 3：调用上下文缺失（选中的视图 / 激活状态）

`InsertModelAnnotations3(Source, Types, AllViews, ...)` 的第二参数 `allViews=True`
可能让 SolidWorks 走"全视图批量"路径，而该路径不支持孔标注（孔标注依赖具体视图的投影边）。

**验证方法**：`AllViews=False` + 先 `SelectByID2` 选中某个视图，再调用，观察是否有孔标注。

### 假设 4：SolidWorks 2026 的行为变化

方案调研对象的版本与我们不同（haunchen 面向 2021，SolidPilot 面向 2026）。
若 2026 移除了该路径，Python 侧无法解决。

## 六、建议的下一步：先用宏录制取证

上述四个假设都可以用**一个动作**同时缩小范围——在 SolidWorks 界面里手工做一次：

1. 打开有 Hole Wizard 孔的零件所建的工程图
2. 菜单：**插入 → 模型项目 → 注释类型勾选「孔标注」**
3. **宏录制**（工具 → 宏 → 录制）→ 执行第 2 步 → 停止录制
4. 查看生成的 VBA 代码

录出来的调用**就是这条路径的真实 API 与真实参数**，比任何二手常量都可靠。
我这边固件的坑清单里已经记过同类教训：

> 「形位公差 14 个参数」是查官方文档才对上的，而「4 个参数的版本试了 4 次都失败」，
> 靠猜参数的成本远高于录一次宏。

**建议把「录一次宏」列为该方案的前置动作**，而不是继续在二手常量上试。
