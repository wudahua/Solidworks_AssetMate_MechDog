## 四、宏是怎么解出来的（可复用技术）

`.swp` 不是文本，是 **OLE 复合文档 + VBA 压缩流**。`strings` 看不到代码。

### 4.1 定位流

```python
import olefile
ole = olefile.OleFileIO('Macro1.swp')
for entry in ole.listdir():
    print('/'.join(entry))

# 输出（节选）：
# apc/The VBA Project/_VBA_Project/VBA/Macro11     ← 代码在这里
# apc/The VBA Project/_VBA_Project/VBA/dir
# apc/The VBA Project/_VBA_Project/VBA/_VBA_PROJECT
```

**注意**：流名是 `Macro11`（不是 `Module1`），且带 `apc/The VBA Project/_VBA_Project/` 前缀。按 `VBA/Module1` 找会漏。

### 4.2 解压（MS-OVBA 2.4.1）

```python
import struct

def decompress(data):
    """MS-OVBA decompression. `data` starts right after the 0x01 signature byte."""
    out = bytearray()
    pos = 0
    while pos + 2 <= len(data):
        header = struct.unpack_from('<H', data, pos)[0]; pos += 2
        size = (header & 0x0FFF) + 3
        compressed = bool(header & 0x8000)
        end = min(pos + size, len(data))
        if not compressed:
            out += data[pos:end]; pos = end; continue
        chunk = data[pos:end]; pos = end
        base = len(out); i = 0
        while i < len(chunk):
            flag = chunk[i]; i += 1
            for bit in range(8):
                if i >= len(chunk): break
                if not (flag >> bit) & 1:
                    out.append(chunk[i]); i += 1
                else:
                    if i + 2 > len(chunk): break
                    token = struct.unpack_from('<H', chunk, i)[0]; i += 2
                    diff = len(out) - base
                    bits = max(4, (diff - 1).bit_length())
                    lmask = 0xFFFF >> bits
                    length = (token & lmask) + 3
                    offset = ((token & (~lmask & 0xFFFF)) >> (16 - bits)) + 1
                    src = len(out) - offset
                    for _ in range(length):
                        if 0 <= src < len(out):
                            out.append(out[src]); src += 1
    return bytes(out)
```

要点：

- 跳过首字节 `0x01`（压缩容器签名）
- 每个 chunk 头 2 字节：`0x0FFF` 是 chunk 长度、`0x8000` 是压缩标志
- token 的位宽随「已解出字节数」增长（4→8→12→16 bit），**`bits = max(4, (diff-1).bit_length())` 这一行是关键**

### 4.3 读出来

```python
raw = ole.openstream('apc/The VBA Project/_VBA_Project/VBA/Macro11').read()
code = decompress(raw[1:])          # 跳过 0x01
text = code.decode('latin1')        # 中文会是乱码，但英文标识符清晰可读
```

## 六、关键差异：`SelectByRay`

宏在插入前做了一次**射线选择**——用屏幕坐标 + 方向向量在视图里选中某个实体。

### 6.1 为什么这条能解释一切

SolidWorks 的 BOM 需要知道「挂在哪个装配视图上」。**选中视图对象**（`DRAWINGVIEW`）与**选中视图内的几何**，在 SolidWorks 内部是两条不同的路径：

- 选 `DRAWINGVIEW` → 选择集 count=1，但 BOM 命令认为「没有选中视图内容」
- `SelectByRay` 打到实体上 → 内部上下文里「当前视图」被正确设置

这解释了为什么：
- 我 `SelectByID2(..., "DRAWINGVIEW", ...)` 返回 `True`、`count=1`，插 BOM 仍 `None`
- 宏里同样一句 `InsertBomTable4` 却成功

### 6.2 为什么我复现不了 `SelectByRay`

pywin32 下所有参数封送都被拒：

```python
doc.Extension.SelectByRay(cx, cy, 0.0, 0.0, 0.0, 0.0, 0.002, 2,
                          False, 0, byref_dispatch_null(), 0)
# → DISP_E_TYPEMISMATCH（报在第 11 个参数位置）
```

11 个参数，最后一个 `Callout` 需要 byref 变体、第 8 个是枚举、第 9 个是 bool…… 逐个试的代价很高，而且宏已经能跑通，**没有必要继续**。

### 6.3 另一个被忽略的线索

**`InsertTableAnnotation2`（通用表格）也全部返回 None。**

通用表格不需要装配上下文，它失败说明问题不只是「BOM 找不到装配」，而是更底层的「插入表格这个动作在当前上下文里被拒」。这条线索当时被我当作「又一个失败」，其实它指向的正是 §6.1 那个结论：**缺的是「射线选中」这个前置，而不是参数**。

## 九、两条通用化路径

### 路径 A：生成宏而不是录制宏（推荐）

思路：宏从**外部读参数**，Python 侧只负责写参数 + 触发生成。

```vba
' 参数化后的宏骨架
Dim xy As String
xy = Environ("ASSETMATE_BOM_XY")          ' 形如 "0.24,0.19"
Dim viewName As String
viewName = Environ("ASSETMATE_BOM_VIEW")  ' 形如 "工程图视图2"

If viewName <> "" Then swModel.ActivateView viewName
' ... SelectByRay 用视图中心坐标
swModel.InsertBomTable4 x, y, ... 
```

Python 侧：

```python
os.environ["ASSETMATE_BOM_XY"] = "%.3f,%.3f" % (x, y)
os.environ["ASSETMATE_BOM_VIEW"] = view_name
call_method(sw, "RunMacro", macro, "Macro1", "main")
```

要点：

- **`SelectByRay` 仍在宏里**（这是关键，不能移到 Python）
- 视图名和坐标由环境变量传入，覆盖「测试图纸」以外的场景
- `SelectByRay` 的坐标要用**视图 outline 的中心**，而不是固定值

**成本**：需要写一个参数化宏（VBA，约 20 行），并重新录一次确保 `SelectByRay` 的向量正确。

### 路径 B：继续攻 `SelectByRay` 的参数封送

11 个参数：

```
x, y, z           : double（屏幕/图纸坐标）
dirX, dirY, dirZ  : double（射线方向）
radius            : double（容差）
type              : int（swSelectType_e）
append            : bool
mark              : int
callout           : byref IDispatch（必须 byref null）
option            : int
```

已经试过 `byref_dispatch_null()` + 裸值组合，报第 11 位类型不匹配。剩余可能需要：
- 所有 double 用 `VARIANT(VT_R8)`
- `append` 用 `VARIANT(VT_BOOL)`
- 或者整组用 `VARIANT(VT_ARRAY|VT_R8)` 传坐标

**成本**：不确定，可能在 30 分钟也可能又是几小时。**且即使成功，仍要面对「选哪个实体」的判定问题**（宏里的射线方向是特定角度打过去的）。

### 路径 C：`RunCommand` 命令通道

用 `ISldWorks.RunCommand` 触发「插入材料明细表」菜单命令。**异步**，需要同步等待与超时保护，且依赖界面在场。

## 十、方法论价值（三条）

### 10.1 宏录制是「最后一公里」的最短路径

从 `InsertGtol`（形位公差）到 `InsertBomTable`（BOM），两次都是：
**纯 API 试到穷尽 → 一段宏录制直接给出答案。**

宏里有**完整的调用序列**（包括那些文档没写的「前置调用」）。这比读文档、比试参数都直接。

**规则**：当某个操作在界面上能做、API 反复返回空时，**先录一次宏**，不要继续试参数。

### 10.2 「返回 None」必须被当作「前置条件未满足」，不是「API 不可用」

本次 20+ 组合全 `None`，我一度写成「环境拒绝」。实际上是**缺一次射线选择**。

`None` 的含义是「我收到了请求，但你没准备好我要的东西」——**该找的是「它要什么」，不是「换个参数再试」**。

### 10.3 通用表格也失败 = 最强的诊断信号

当时我把「`InsertTableAnnotation2` 也 None」当成「又一个失败」，其实它说明：

> 问题不在 BOM 专属参数，而在它们共享的前置条件。

**同一类操作全部失败时，先找共同前置，而不是逐个调参。**
