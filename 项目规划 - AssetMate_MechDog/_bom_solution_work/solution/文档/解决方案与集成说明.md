# BOM 原生明细栏解决方案与集成说明

## 1. 已验证结果

本包已在 **SOLIDWORKS 2024 SP4（32.4.0）+ Python + pywin32 晚绑定** 上完成端到端实测：

```text
RowCount = 10（1 行表头 + 9 行数据）
ColumnCount = 4（项目号 / 零件号 / 说明 / 数量）
BomFeature.TableType = 2（TopLevelOnly）
```

首三行数据：

```text
1  SAB1_0100_000  框架模块        1
2  SAB1_0200_000  扫描笔固定模块  1
3  SAB1_0300_000  运动单元模块    1
```

保存、关闭并重新打开 `BOM_SOLVED.SLDDRW` 后，以上状态保持不变。成功图纸在 `成功案例/`。

## 2. 根因

直接调用：

```python
view.InsertBomTable4(..., BomType=2, ...)  # TopLevelOnly
```

在当前环境只生成表头，且没有数量列。`SetConfigurations` 的各种数组形式均不能修复。

但同一视图、同一装配、同一模板下：

- `BomType=3`（Indented）能生成 120 行、4 列；
- `BomType=1`（PartsOnly）能生成 101 行、4 列。

因此装配、模板、图纸和模型引用都正常，问题仅在于 **TopLevelOnly 的配置关联未建立**。

## 3. 最终解法

```text
1. 用 Indented（BomType=3）创建原生 BOM，Configuration 传有效配置（本例 Default）
2. 确认表中有数据行和 Quantity 列
3. 设置 table.BomFeature.TableType = 2（TopLevelOnly）
4. 重建：得到 10 行、5 列（9 个目标模块 + 重复数量列）
5. 对最后一个可见列执行 ColumnHidden(index, True)
6. 再重建：得到 10 行、4 列，完成
```

关键代码：

```python
table = view.InsertBomTable4(
    False, 0.24, 0.19,
    1,              # AnchorType=TopLeft
    3,              # 先 Indented
    "Default",      # 有效配置
    template,
    False, 0, False,
)

table.BomFeature.TableType = 2
call_method(doc, "ForceRebuild3", False)

# 当前环境此时为 10 行、5 列，隐藏最后一个重复 Quantity 列
ole = table._oleobj_
dispid = ole.GetIDsOfNames("ColumnHidden")
ole.Invoke(dispid, 0, pythoncom.DISPATCH_PROPERTYPUT,
           True, table.ColumnCount - 1, True)
call_method(doc, "ForceRebuild3", False)
```

完整实现见 `代码/bom_native.py`。

## 4. 不要做的事

### 4.1 不要再调用 SetConfigurations

在本流程中，它会把 TopLevelOnly 表重新清空为表头。最终修复不依赖该方法。

### 4.2 不要用 InsertColumn2 + SetColumnType 补 Quantity 列

官方限制：不能把普通列改成 Quantity 列。实测 `SetColumnType2(..., 203, ...)` 返回 False。

### 4.3 不要依赖 DeleteColumn 删除重复 Quantity 列

实测返回 True，但可见重复列仍存在。使用 `ColumnHidden` 才是本环境有效路径。

### 4.4 不要再用 ColumnHidden=False 猜测“取消隐藏”

本流程只隐藏最后一个重复列：`ColumnHidden(last_index, True)`。写操作前记录原始列状态，并在副本上测试。

## 5. 集成到现有 layout.add_bom_table

1. 将 `代码/bom_native.py` 复制到项目 `tools/` 包目录。
2. 用 `代码/layout_add_bom_table.py` 中的函数替换旧 `add_bom_table`。
3. 确认同一文件内没有第二个 `def add_bom_table`。
4. 重启 MCP server，避免旧模块仍在运行。
5. 用真实 MCP 调用一次，并检查返回：`native_bom=True`、`populated=True`、`rows=10`、`columns=4`。

`layout_add_bom_table.py` 是替换函数示例，不是完整 `layout.py`，避免覆盖你其他工具函数。
