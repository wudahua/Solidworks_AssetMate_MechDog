## 三、空表：已排除的六类原因

### 3.1 判据修正（关键）

**看 `ColumnCount`，不是只看 `RowCount`。**

| 表 | rows | cols | 表头 |
|---|---:|---:|---|
| 宏成功那次 | 10 | **4** | 项目号 / 零件号 / 说明 / **数量** |
| 我现在 | 1 | **3** | 项目号 / 零件号 / 说明 |

TopLevelOnly 应为每个所选配置生成数量列。**3 列 = 一个配置都没关联上**——这比「没有数据行」更靠前。

### 3.2 已排除清单

| # | 假设 | 怎么排除的 | 结果 |
|---|---|---|---|
| 1 | 配置名空串不对 | 传 `'Default'` / `'UP'` / `''` 九种组合 | 全 rows=1 |
| 2 | 配置未设为可见 | `SetConfigurations(False, vis, names)` 三种封送 | 返回 True/False，**列数始终 3** |
| 3 | 组件缺失被隐藏 | `KeepMissingItems=True` / `StrikeoutMissingItems=True` | 列数不变 |
| 4 | 未重建 | `EditRebuild3` / `ForceRebuild3` / `GraphicsRedraw2` | 都执行成功，行数不变 |
| 5 | BOM 挂错模型 | `GetReferencedModelName` | **正确指向装配** |
| 6 | `BomType` 错 | 1(PartsOnly) / 2(TopLevelOnly) / 3(Indented) | 全部 3 列 |

`SetConfigurations` 三种封送的细节：

| 形式 | 返回 | 列数 |
|---|---|---|
| plain `list` | `True` | 3 |
| `VARIANT(VT_ARRAY\|VT_VARIANT)` | `True` | 3 |
| `VARIANT(VT_ARRAY\|VT_BSTR)` | **`False`** | 3 |

**`SetConfigurations` 返回 True 不等于配置进入表格。**

另：`GetConfigurations(False, None)` 在本机始终 `DISP_E_TYPEMISMATCH`，读不出来，所以只能手工构造数组。

## 四、只剩一个方向：模板

`TableTemplate` 用的是：

```
D:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\lang\chinese-simplified\bom-standard.sldbomtbt
```

**可能的解释**：这个模板文件本身**没有定义数量列**。

SolidWorks 的 BOM 模板（`.sldbomtbt`）定义列结构，如果模板里只有「项目号/零件号/说明」三列，那无论配置怎么设都不会出现数量列。

**同目录下还有别的模板**（已确认存在）：

```
bom-standard.sldbomtbt
bom-material.sldbomtbt
bom-all.sldbomtbt
bom-costing.sldbomtbt
bom-circuit-summary.sldbomtbt
```

### 4.1 我想做的验证（成本 5 分钟）

```python
for name in ('bom-standard', 'bom-all', 'bom-material'):
    tpl = os.path.join(base, 'lang', 'chinese-simplified', name + '.sldbomtbt')
    table = view.InsertBomTable4(False, 0.24, 0.19, 1, 2, '', tpl, False, 0, False)
    print(name, table.RowCount, table.ColumnCount)
```

- 若某个模板出 4 列且有数据 → **根因是模板**
- 若全部 3 列 → 模板不是根因，问题在「配置如何进入列」

### 4.2 如果模板也不是

那剩下的可能性只有：**`swModel.InsertBomTable4`（宏的 8 参入口）与 `view.InsertBomTable4`（10 参）行为确实不同**，需要解开「该成员在 Python 侧不存在」这个矛盾。
