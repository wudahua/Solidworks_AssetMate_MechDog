## 1. 结论速查

### 1.1 核心判断

**"剩下的是环境状态，本工具能查的都查了"这个判断不准确。** 有三个**官方文档写明**的拒绝条件尚未满足，且本次实验的变量组合并未真正覆盖它们：

| # | 高概率原因 | 依据 | 本次是否真正验证过 |
|---|---|---|---|
| 1 | **`Configuration` 传了空串** | 【官方】空串不会默认 Default；parts-only / indented 下配置无效 → **不创建** | 未验证（报告自己列为未排除 #5） |
| 2 | **`UseAnchorPoint=True` 但图纸格式没有 BOM 锚点** | 【官方】"if true **and the appropriate sheet format anchor point exists**" | 未验证锚点是否存在 |
| 3 | **视图对象拿错 / 图纸不是活动文档** | 【实战】`doc.GetFirstView` 第一个是图纸背景，必须用 `sheet.GetViews`；视图/文档未激活时插入类调用常静默失败 | 未打印视图与配置信息佐证 |

### 1.2 一条被忽略的重要线索

**`InsertTableAnnotation2`（通用表格）也全部返回 None。**

BOM 专用 API 与通用表格 API 同时失败，说明问题**大概率不在 BOM 参数**，而在它们共享的前置条件：文档激活状态、视图对象有效性、图纸格式状态、模型解析状态。

因此下一步不应再围绕 BOM 参数做排列组合，而应**先把"插入任意表格"这一最小动作跑通**。

### 1.3 建议动作顺序

```
① 跑 §5 诊断脚本（5 分钟，打印每个前置条件真实值）
② 用 §4 黄金参数组合调一次（改 3 个参数：配置名 / 锚点策略 / 视图来源）
③ 仍失败 → 换极简两件装配复测，区分"模型问题"与"环境问题"
④ 仍失败 → 界面手工插 + 宏录制（保留原报告建议）
⑤ 仍失败 → 走 §8 替代交付路径，不再投入
```

## 2. 官方硬证据：三个会直接导致"返回 None"的条件

### 2.1 条件一：`Configuration` 空串 ≠ 使用 Default 配置【官方】

`IModelDocExtension.InsertBomTable4` 的 Remarks 原文（同一 BOM 语义的官方说明）：

> **The system does not default to the Default configuration when you specify an empty string for Configuration. You must specify the configuration.**
>
> **If the BOM table is a parts-only or indented-style BOM and ConfigurationName is invalid, then the BOM is not created.**

对照本次调用：

```python
view.InsertBomTable5(False, 0.02, 0.02, 0, 1, '', tpl, False, 0, False, False)
#                                            ↑ BomType      ↑ Configuration = ''
```

- 传了空串，而官方明确要求**必须指定配置**。
- `BomType = 2 (PartsOnly)` / `3 (Indented)` 时，配置无效 → **BOM 不被创建**，正好表现为"无异常、返回 None"。

**这是与实测现象吻合度最高的一条官方解释，且修正成本只是一行代码。**

> 注意区分：CodeStack 的公开宏里 `Configuration` 也传了 `""` 且能成功【实战】。两者不矛盾——它走的是 `UseAnchorPoint=True` + `IView` 的路径，说明**不同入口/锚点模式下配置校验严格程度不同**。因此正确做法是：**显式传真实配置名，把这个变量彻底消掉**，而不是纠结空串到底行不行。

### 2.2 条件二：`UseAnchorPoint=True` 依赖图纸格式里存在对应锚点【官方】

`IView.InsertBomTable4` 参数说明原文：

> UseAnchorPoint — If true **and the appropriate sheet format anchor point exists**, then insert table at this point; if false, then use the values specified for the X and Y arguments as the insertion point.

含义：

- 锚点不存在时，`True` 分支没有可用落点，可能直接返回 None。
- 本次使用的是自定义模板（`gb_a3.drwdot` 一类），**模板里是否定义了 BOM 锚点从未检查过**。
- `X/Y` 与 `AnchorType` 的取值在两种模式下含义不同：`True` 时 X/Y 被忽略，锚点类型决定表格角点；`False` 时才真正使用 X/Y。

**结论**：排障阶段应固定 `UseAnchorPoint=False` + 明确的图纸内坐标，把"锚点是否存在"这个变量关掉。

### 2.3 条件三：`TableTemplate` 必须与表类型匹配【官方】

> BOM table templates are in the `\lang` folder and have a filename extension of `.sldbomtbt`. **The template and table must be of the same type.**

本次虽然确认了文件存在，但**没有确认模板类型与 `BomType` 是否匹配**（例如用了材料明细表模板却请求了其他表类型，或语言/版本不符）。

排障阶段建议：**`TableTemplate = ''`（用默认模板）**，先证明能创建，再换回自定义模板定位模板问题。CodeStack 宏同样是用空模板跑通的【实战】。

## 3. 本次实验设计中的三处盲区

### 3.1 盲区一：变量是"组合"试的，失败时无法归因

报告记录了 7 条 API × 20+ 组合全失败，但**没有一行是"其他条件全部理想、只改一个变量"的对照**。例如：

- `Configuration=''` 与 `BomType=2/3` 同时出现 → 命中官方拒绝条件。
- `UseAnchorPoint` 切换时，没有同步确认锚点存在性。
- 模板在"空串/真实路径"之间切换时，`BomType` 与配置也在变。

**结果**：20+ 组合全部踩在同一组未满足的前置条件上，看起来像"彻底无解"。

### 3.2 盲区二：没有打印任何"上下文真实值"

整份记录没有以下信息，而它们恰恰是判断前置条件的关键：

```text
view.Name / view.Type                      ← 拿到的到底是什么视图
view 对应的模型文件是否是 .SLDASM            ← BOM 只能挂在装配视图上
装配的配置名清单                            ← Configuration 该传什么
当前活动文档标题                            ← doc 是否真的激活
组件是否轻化                                ← 模型是否已解析
```

**没有这些日志，"视图已激活""上下文无差别"这类结论缺乏佐证。**

### 3.3 盲区三：`IModelDocExtension.InsertBomTable*` 用错了场景【官方】

官方对该入口的定义是：

> Inserts a bill of materials (BOM) table **in a part or assembly document**.

即它是**模型侧**（零件/装配文档）入口，不是图纸视图的明细栏入口。**图纸里插明细栏应该用 `IView.InsertBomTable4/5`。**

因此 `ext.InsertBomTable2/3` 那一组实验（含各种参数个数报错）与目标无关，可以从排查清单里删掉，避免继续消耗轮次。

## 4. 最小可行调用（黄金参数组合）

设计原则：**把所有非必要变量全部固定到"最不容易被拒绝"的取值**，只保留一个待验证动作。

```python
# 目标：先证明"能创建出一张 BOM 表"，再谈样式与位置
table = view.InsertBomTable5(
    False,          # UseAnchorPoint=False → 不依赖图纸格式锚点（关掉条件二）
    0.20, 0.15,     # X, Y：图纸内明确坐标，单位米（A3 为 0.42 × 0.297）
    ANCHOR_TOPLEFT, # AnchorType：用本地常量，不猜数字
    1,              # BomType = swBomType_TopLevelOnly
                    #   → 避开官方"parts-only/indented 配置无效则不创建"的严格校验
    config_name,    # Configuration：装配真实配置名，绝不传 ''（关掉条件一）
    '',             # TableTemplate = '' → 用默认模板（关掉条件三）
    False,          # Hidden = False
    0,              # IndentedNumberingType = swNumberingType_None（官方枚举值 0）
    False,          # DetailedCutList = False
    False,          # DissolvePartLevelRows（v5 专有；v4 调用时去掉此参数）
)
```

要点：

| 参数 | 取值理由 |
|---|---|
| `UseAnchorPoint=False` | 排除锚点缺失导致的静默失败 |
| `X=0.20, Y=0.15` | 确保落在图纸可视区内，便于肉眼确认 |
| `BomType=1` | 顶层-only 是校验最松的类型；跑通后再换 2/3 |
| `Configuration=真实配置名` | 官方明确要求，不可空 |
| `TableTemplate=''` | 默认模板，排除模板类型不匹配 |
| `IndentedNumberingType=0` | 官方 `swNumberingType_None = 0`，且仅在 Indented 时有意义 |
| 优先 `InsertBomTable5` | 2024 FCS 起可用，`InsertBomTable4` 已 Obsolete；失败再退化 4 |

## 5. 一次性诊断脚本（按顺序跑，失败点自现）

> 【待测】结构参考。每一步都打印真实值，**任何一步不符合预期就先修那一步，不要继续往下调 API**。

```python
import os
import win32com.client
from win32com.client import gencache

app = gencache.EnsureDispatch("SldWorks.Application")   # 同时生成本地枚举常量
from win32com.client import constants as C              # 枚举从这里取，不再猜数值

def step(title, value):
    print(f"[{title}] {value}")

# ---------- 1. 文档必须激活、可见 ----------
app.Visible = True
doc = app.ActiveDoc
step("active doc", doc.GetTitle if doc else None)
# 若图纸不是活动文档：先激活再往下走
# errs = None
# app.ActivateDoc3(drawing_title, False, 0, errs)   # 签名以本机为准

# ---------- 2. 用 sheet.GetViews 取视图，不要用 doc.GetFirstView ----------
draw = win32com.client.CastTo(doc, "IDrawingDoc")       # 接口明确化
sheet_name = draw.GetCurrentSheet.GetName
step("sheet", sheet_name)
draw.ActivateSheet(sheet_name)

views = draw.GetCurrentSheet.GetViews                   # 【实战】正确的视图来源
step("view count", len(views))
view = views[0]
step("view name", view.Name)
step("view type", getattr(view, "Type", None))

# ---------- 3. 确认视图挂的是装配 ----------
# BOM 只能挂在装配体视图上；挂零件视图必然失败
try:
    ref = view.ReferencedDocument                       # 属性名以本机为准，可能需 GetModelDoc2
    step("view model", ref.GetPathName if ref else None)
    step("is assembly", ref.GetType if ref else None)   # 2 = swDocASSEMBLY
except Exception as exc:
    step("view model probe error", repr(exc))

# ---------- 4. 取真实配置名 ----------
assy = app.ActiveDoc                                    # 或打开装配后取
config_name = None
try:
    names = view.ReferencedDocument.GetConfigurationNames
    step("configurations", names)
    config_name = names[0]
except Exception as exc:
    step("config probe error", repr(exc))
step("use configuration", config_name)
assert config_name, "拿不到配置名，先解决这一步"

# ---------- 5. 解析轻化组件（装配常见坑） ----------
try:
    draw.ResolveOutOfDateLightWeightComponents()
    step("resolve lightweight", "done")
except Exception as exc:
    step("resolve lightweight", repr(exc))
draw.EditRebuild3()

# ---------- 6. 枚举值用本地常量 ----------
step("swBomType_TopLevelOnly", C.swBomType_TopLevelOnly)
step("anchor TopLeft", C.swBOMConfigurationAnchor_TopLeft)
step("numbering None", C.swNumberingType_None)

# ---------- 7. 黄金参数插入 ----------
draw.ActivateView(view.Name)
draw.ClearSelection2(True)

args5 = (False, 0.20, 0.15,
         C.swBOMConfigurationAnchor_TopLeft,
         C.swBomType_TopLevelOnly,
         config_name, '', False,
         C.swNumberingType_None, False, False)

table = view.InsertBomTable5(*args5)
step("InsertBomTable5", "None" if table is None else type(table))

if table is None:                                       # 退化 v4（去掉最后 1 个参数）
    table = view.InsertBomTable4(*args5[:-1])
    step("InsertBomTable4", "None" if table is None else type(table))

if table is not None:
    table.BomFeature.FollowAssemblyOrder2 = True        # 【实战】保持装配顺序
    step("rows/cols", (table.RowCount, table.ColumnCount))
    draw.EditRebuild3()
```

### 5.1 结果判读

| 卡点 | 含义 | 处置 |
|---|---|---|
| 第 1 步图纸非活动文档 | 插入类调用在不活动文档上静默失败 | 激活后重跑 |
| 第 2 步 `view.Type` 异常 / 名称为图纸背景 | 视图拿错 | 改用 `sheet.GetViews`，过滤出模型视图 |
| 第 3 步不是装配 | BOM 无源 | 换装配视图 |
| 第 4 步配置名取不到 | 模型未正确打开/解析 | 先打开装配再建图 |
| 第 5 步轻化解析报错 | 组件状态问题 | 手动解析后重跑 |
| 第 6 步常量不存在 | 类型库未生成或枚举名拼写不同 | 用 `dir(C)` 搜 `Bom`/`Anchor` 关键字 |
| 第 7 步返回 None | 前置已全部打印确认，才轮到怀疑 API/环境 | 走 §7 决策树 |

## 6. 六个高概率前置条件逐项说明

| # | 前置条件 | 为什么会导致 None | 确认方法 |
|---|---|---|---|
| 1 | **配置名必须显式指定** | 【官方】空串不默认 Default；parts-only/indented 配置无效则不创建 | 打印 `GetConfigurationNames`，传真实名 |
| 2 | **锚点模式与锚点存在性匹配** | 【官方】`True` 需要图纸格式存在对应锚点 | 排障期固定 `False` + 坐标 |
| 3 | **视图来自 `sheet.GetViews`** | 【实战】`doc.GetFirstView` 第一个是图纸背景，拿它插表必然失败 | 打印视图名/类型/所属模型 |
| 4 | **视图必须挂装配体** | BOM 的数据源是装配结构 | 打印视图模型路径与文档类型 |
| 5 | **文档激活、模型已解析** | 不活动文档、轻化未解析时插入类调用常静默失败 | `ActivateDoc3` / `ResolveOutOfDateLightWeightComponents` / `EditRebuild3` |
| 6 | **模板与表类型匹配** | 【官方】模板和表必须同类型 | 排障期用 `''` 默认模板 |

补充两个低概率但廉价的检查：

- **图纸不是只读/Detached 状态**，且当前不处于"编辑图纸格式"模式（该模式下插入的是格式对象而非明细栏）。
- **换一个极简两件装配**复测：若简单装配能成功，说明是原装配（9 行含 5 子装配、可能轻化/多配置）的特定状态问题，而非 API 或环境。

## 8. 若仍失败：三条交付替代路径（含优于画线的方案）

### 8.1 替代 A（推荐）：原生通用表格 + 本项目 BOM 数据

现方案是 `add_sheet_line` 画网格 + `add_note` 逐格写字，产物是**一堆线和文字**，不可读、不可维护。
更好的替代：**用通用表格 API 创建真正的 `ITableAnnotation`，再把 `export_bom` 的数据填进去。**

| 对比 | 画线 + Note | 原生通用表格 |
|---|---|---|
| 图面对象 | 散线 + 散文字 | 单个表格对象 |
| 行列结构 | 无 | 有，可设行高列宽 |
| 回读校验 | 几乎做不了 | 可逐格读回文本做对账 |
| 位置控制 | 米坐标 | 米坐标 + 锚点 |
| 随装配更新 | 否 | 否（同样需披露） |
| 气球联动 | 无 | 无（同样需披露） |

要点：

- 数据来源复用现有 `export_bom`（零件名/数量/材料/单重/总重），**序号列由工具按行号生成，并与气球编号规则显式对齐**，保证图面一致。
- 必须在交付说明中写明：**这是静态表格，不是 SolidWorks 原生 BOM，不随装配更新，气球编号由本工具生成**。
- 官方存在 `IModelDocExtension.InsertGeneralTableAnnotation` 入口【官方】，其签名与调用上下文需按本机文档确认【待测】。
- 若通用表格也创建不了（与本次现象一致），此路同样不可用 → 退到替代 B。

### 8.2 替代 B：CSV/表格文件 + 图面简化明细

- 图纸上只保留必要的序号气球与关键技术要求，**完整明细栏以 `.csv` / `.xlsx` 随图交付**。
- 优点：零 COM 风险、数据可复核、可直接用于采购。
- 缺点：图面无明细栏，需在交付说明里明确"明细栏以附件形式提供"。
- 适合内部评审与打样阶段，不适合正式归档图纸。

### 8.3 替代 C：RunCommand / UI 自动化（需界面在场）

- 用 `ISldWorks.RunCommand` 触发"插入材料明细表"命令，再读取生成的 `BomTableAnnotation`。
- 注意 `RunCommand` **异步**，需要同步等待与超时保护；依赖界面与选中上下文。
- 标 `pilot`，仅限有人值守的本机批处理。

### 8.4 禁止事项

- 不得把画线 + Note 的产物在工具返回里称为"原生 BOM"。
- 不得仅凭"调用了 InsertBomTable5 且无异常"就记为成功——**必须回读到表格对象与行数**。
- 装配变更后未重生成表格时，`delivery_check` 应提示"明细栏可能过期"。

### 11.2 枚举速查

| 枚举 | 成员与值 | 来源 |

```python
from win32com.client import gencache, constants
gencache.EnsureDispatch("SldWorks.Application")
print(constants.swBomType_TopLevelOnly)
print(constants.swBOMConfigurationAnchor_TopLeft)
print([n for n in dir(constants) if "Anchor" in n or "BomType" in n])
```
