## 1. 结论：还不用回到宏 8 参入口

“只剩模板”这个判断可以保留为假设，但还有三条**不依赖宏入口**的直接路径：

1. **数量列可能已存在但被隐藏**：应比较 `ColumnCount` 与 `TotalColumnCount`，而不是只看 `ColumnCount`。
2. **可以读取宏成功表的第 4 列定义**：用 `GetColumnType3` 取 Quantity 列的类型和 `PropData`，得到事实，不再猜。
3. **可以手工补 Quantity 列**：`InsertColumn2` + `SetColumnType3`，类型常量官方为 `swBomTableColumnType_Quantity = 203`。

建议顺序：

```text
隐藏列检查（1 分钟）
→ 模板对照（5 分钟）
→ 读取宏成功列定义（5 分钟）
→ 手工补 Quantity 列（10 分钟）
→ 仍无数据行再查组件状态
```

这套验证完成前，不建议定 `partial` 收尾，也不建议投入宏接口考古。

## 2. 第一步：检查数量列是否只是被隐藏

### 2.1 为什么要查

`ITableAnnotation` 同时有：

- `ColumnCount`
- `TotalColumnCount`
- `ColumnHidden`

当前只证明了“可见列为 3”，没有证明“表中总共只有 3 列”。

### 2.2 检查代码【待测】

```python
print("ColumnCount:", table.ColumnCount)
print("TotalColumnCount:", table.TotalColumnCount)
```

判读：

| ColumnCount | TotalColumnCount | 含义 |
|---:|---:|---|
| 3 | 3 | 确实没有第 4 列，继续模板/补列 |
| 3 | 4 或更多 | **数量列可能已存在但被隐藏**，先处理隐藏状态 |

若总数大于可见数，逐列读取标题、类型和隐藏状态：

```python
for i in range(table.TotalColumnCount):
    title = table.GetColumnTitle2(i, True)
    print("column:", i, "title:", title)
    # ColumnHidden 的索引访问形式以本机属性映射为准
    try:
        print("  hidden:", table.ColumnHidden(i))
    except Exception as exc:
        print("  hidden probe:", repr(exc))
```

若找到数量列且隐藏，取消隐藏后重建：

```python
# 形式以本机映射为准：属性、索引属性或 Set 方法
# table.ColumnHidden(i) = False
call_method(doc, "ForceRebuild3", False)
```

**如果 TotalColumnCount=4，这一分钟就可能比后面所有实验都快。**

## 3. 第二步：做完整的模板对照，而不是只试三个中文模板

### 3.1 必须加入两个对照

除了 `bom-standard / bom-all / bom-material`，还要加：

| 对照 | 目的 |
|---|---|
| `TableTemplate=''` | 使用默认模板，排除指定文件本身的问题 |
| 英文目录下的 `bom-standard.sldbomtbt` | 排除中文语言模板内容/兼容性问题 |

### 3.2 实验纪律

每个模板都应：

- 在**新图纸**上测试，或先删除前一张测试表；
- 使用完全相同的视图与参数：`AnchorType=1`、`BomType=2`；
- 插入后执行项目的重建封装；
- 同时记录 `RowCount / ColumnCount / TotalColumnCount / 表头`。

### 3.3 参考结构【待测】

```python
import os

cases = [
    ("default-empty", ""),
    ("cn-standard", os.path.join(base, "lang", "chinese-simplified", "bom-standard.sldbomtbt")),
    ("cn-all", os.path.join(base, "lang", "chinese-simplified", "bom-all.sldbomtbt")),
    ("cn-material", os.path.join(base, "lang", "chinese-simplified", "bom-material.sldbomtbt")),
    ("en-standard", os.path.join(base, "lang", "english", "bom-standard.sldbomtbt")),
]

for name, tpl in cases:
    if tpl and not os.path.exists(tpl):
        print(name, "template missing")
        continue

    # 每个 case 使用新图纸/新视图，避免前一张表影响计数
    doc2, view2 = new_test_drawing_with_same_assembly()

    table = view2.InsertBomTable4(
        False, 0.24, 0.19,
        1, 2, "", tpl, False, 0, False,
    )
    call_method(doc2, "ForceRebuild3", False)

    if table is None:
        print(name, "returned None")
        continue

    headers = [table.GetColumnTitle2(i, True) for i in range(table.ColumnCount)]
    print(name, {
        "rows": table.RowCount,
        "cols": table.ColumnCount,
        "total_cols": table.TotalColumnCount,
        "headers": headers,
    })
```

### 3.4 判读

- 某模板直接出现数量列与数据行 → 模板是根因，固定该模板并补回归。
- 默认/英文模板出 4 列，中文模板不出 → 中文模板内容或兼容性问。
- 全部 3 列 → 模板不是充分解释，继续读取宏成功列定义与手工补列。

## 4. 第三步：读取宏成功表的数量列定义

### 4.1 目的

宏成功表已经有第 4 列。直接读取它的：

- 列类型（应为 Quantity=203）；
- 列标题；
- `PropData`；
- 是否隐藏。

这比继续推测“8 参入口行为不同”更有价值。

### 4.2 官方接口

官方示例使用：

```vba
ColType = theTableAnnotation.GetColumnType3(i, True, PropData, status)
ColTitle = theTableAnnotation.GetColumnTitle2(i, True)
```

pywin32 的 ByRef 返回形态需要先打印：

```python
result = macro_table.GetColumnType3(3, True, None, None)
print(type(result), result)
print("title:", macro_table.GetColumnTitle2(3, True))
```

预期要拿到：

```text
ColType = 203（swBomTableColumnType_Quantity）
PropData = 与配置绑定有关的数据（以实际返回为准）
```

### 4.3 同时读取当前空表三列

```python
for i in range(table.ColumnCount):
    print("current column", i,
          table.GetColumnTitle2(i, True),
          table.GetColumnType3(i, True, None, None))
```

对比宏成功表与当前表，回答两个问题：

1. 当前缺的是否正是 `Quantity(203)`？
2. 宏的 Quantity 列 `PropData` 到底是什么？

拿到 `PropData` 后，下一步可以直接复用，不必解宏的 8 参入口。

## 5. 第四步：用 InsertColumn2 + Quantity(203) 直接补列

### 5.1 官方依据

```text
ITableAnnotation.InsertColumn2(Where, Index, Name, WidthStyle) → bool
swBomTableColumnType_Quantity = 203
```

### 5.2 操作顺序

```text
在空表末尾 InsertColumn2
→ 取新列索引 ColumnCount - 1
→ SetColumnType3(新索引, 203, True, PropData)
→ 设置目标配置（如需）
→ 重建并检查行数与表头
```

### 5.3 参考实现【待测】

```python
# 常量优先从 win32com.client.constants 获取；203 为官方 Quantity 值
QUANTITY = 203

# Where/WidthStyle 建议用本地常量：
# swTableItemInsertPosition_Last
# swInsertColumn_DefaultWidth
ok = table.InsertColumn2(
    2,              # 示例：若本机 Last=2；正式代码必须用常量，不照抄数字
    0,
    "数量",
    0,              # 示例：若本机 DefaultWidth=0；正式代码用常量
)
print("InsertColumn2:", ok)

new_index = table.ColumnCount - 1

# PropData 优先使用从宏成功 Quantity 列读到的真实值
prop_data = get_macro_quantity_prop_data()

ok2 = table.SetColumnType3(
    new_index,
    QUANTITY,
    True,
    prop_data,
)
print("SetColumnType3 Quantity:", ok2)

call_method(doc, "ForceRebuild3", False)
print("rows/cols:", table.RowCount, table.ColumnCount)
```

> 注意：上面 `Where=2`、`WidthStyle=0` 只是占位示例，不能作为已确认枚举值。
> 正确做法是从本地常量读取 `swTableItemInsertPosition_Last` 和 `swInsertColumn_DefaultWidth`。

### 5.4 如果 PropData 暂时拿不到

先试 `None`，但要把它当作诊断而不是最终方案：

```python
table.SetColumnType3(new_index, 203, True, None)
```

判读：

- 成功出数量列且有数据 → 问题解决；
- 出列但无数据 → 列已建立，继续绑定配置/查组件；
- 返回 False 或类型错误 → 必须先拿到宏成功列的 PropData，不要继续盲试。

## 6. 如果补出 4 列仍无数据行

此时“数量列缺失”已解决，才把问题降级为“组件数据未填充”。

按顺序检查：

1. `BomFeature.GetReferencedModelName` 是否仍正确；
2. `view.ReferencedConfiguration` 与 Quantity 列绑定配置是否一致；
3. `export_bom` 是否有 9 行数据；
4. 当前配置下组件是否被抑制或设置为不包含在 BOM 中；
5. 组件是否 missing/轻化未解析；
6. 对比宏成功表的 `KeepMissingItems / StrikeoutMissingItems / Configuration / TableType`。

判读：

| export_bom | 原生表补列后 | 结论 |
|---|---|---|
| 0 行 | 0 行 | 模型侧无数据，不是图纸列问题 |
| 9 行 | 0 行 | 查配置绑定、组件状态与原生 BomFeature 属性 |
| 9 行 | 9 行 | 完成，进入对账与交付 |

## 7. 重复函数：加入 AST 静态检查

### 7.1 建议加入，而且应检查“同一作用域重复定义”

这次工具失败与 COM 无关，是后定义覆盖先定义。
静态检查成本很低，应该加入 `static_check.py`。

### 7.2 参考实现

```python
import ast
from pathlib import Path


def _duplicate_defs_in_body(body, scope, path):
    seen = {}
    errors = []

    for node in body:
        if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
            if node.name in seen:
                errors.append(
                    f"{path}: duplicate def {scope}{node.name} "
                    f"(line {seen[node.name]} and {node.lineno})"
                )
            else:
                seen[node.name] = node.lineno

        elif isinstance(node, ast.ClassDef):
            # 类方法允许与其他类/模块函数同名，但同类内不允许重复
            errors.extend(
                _duplicate_defs_in_body(
                    node.body,
                    scope=f"{scope}{node.name}.",
                    path=path,
                )
            )

    return errors


def check_duplicate_defs(path):
    path = Path(path)
    tree = ast.parse(path.read_text(encoding="utf-8"), filename=str(path))
    return _duplicate_defs_in_body(tree.body, scope="", path=path)
```

### 7.3 再加一道运行时抽检

静态检查之外，在 `tests/smoke.py` 或开发调试脚本中对关键工具函数打印：

```python
import inspect
from solidworks_assetmate_mechdog.tools import layout

print(inspect.getsourcefile(layout.add_bom_table))
print(inspect.getsource(layout.add_bom_table))
```

要求：

- 函数定义只有一份；
- 文件路径来自预期源码目录；
- 修改函数后重启 MCP 再测；
- 可将函数源码 hash 写入 MCP 调试返回，防止旧进程问题。

## 8. 最终验证矩阵与交付标准

| 顺序 | 验证 | 通过标准 |
|---|---|---|
| 1 | 隐藏列 | 明确 `ColumnCount == TotalColumnCount`，或找到并恢复隐藏 Quantity 列 |
| 2 | 模板矩阵 | 默认/中文/英文模板结果有记录，无重复表干扰 |
| 3 | 宏成功列定义 | 得到 Quantity 列类型与 PropData |
| 4 | 手工补列 | `ColumnCount` 变为 4，表头出现数量 |
| 5 | 数据行 | `RowCount > 1` |
| 6 | 数据对账 | 行数、零件号、数量与 `export_bom` 一致 |
| 7 | 工具路径 | MCP 与独立脚本结果一致 |
| 8 | 静态防线 | 重复 def 检查通过，MCP 加载的是最新函数 |

只有 1–6 全部通过，才把 `bom_table` 从 `partial` 升级。
`RowCount<=1` 继续记 `bom_table_empty`，不得进入正式交付。
