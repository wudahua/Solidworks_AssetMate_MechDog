# AssetMate 工程图性能优化：审校结论与实施规格

> 基线：《AssetMate_工程图出图性能优化方案_v0.8.89.md》
> 日期：2026-11-03
> 目标读者：负责具体实现的 AI / 工程师
> 性质：实施规格，不是“已提速”的验收报告。所有性能收益必须重新测量。

---

## 0. 结论先行

### 大方向正确

原方案的核心判断是对的：

- 主要成本在 SolidWorks 内部重建、视图更新和重复布局，不在 Python 语法本身；
- 应减少重复保存、重复 `GraphicsRedraw2`、重复 `ForceRebuild3`；
- 布局计算应尽量在内存中完成，再统一写回；
- 注释应批量处理，最终统一保存和审计；
- C# Shim 只应在测量证明有额外收益后引入。

### 但不能原样实施

原方案有六处需要纠正：

1. **本机类型库没有 `swAutomaticRebuild`**，不能照抄该开关。可测的是 `swDrawingAutomaticViewUpdate=90` 等真实接口。
2. `AddDimension2` 只有 `X,Y,Z` 三个参数，尺寸内容由**当前选择**决定；原示例额外传几何与尺寸类型是错误的。
3. `SetPosition` 只移动图纸位置，**不会把尺寸改派到另一个视图**。
4. 当前源码的 `InsertModelAnnotations3` 已有真实分布证据（20/10/9），不能继续断言“尺寸全部挤首视图”。
5. C# Shim 示例里 `new SldWorks()` 会连接/创建错误的应用实例；应使用 `Marshal.GetActiveObject` 或传入已确认的对象。更重要的是，Shim 不会自动减少 SolidWorks 内部重建。
6. 性能门禁不能靠“源码里有没有某字符串”的静态断言；必须做运行时计数、设置恢复测试和 A/B 基准。

### 推荐实施顺序

```text
先加测量，不改行为
→ 合并保存/刷新/审计
→ 对可关闭的真实开关做小范围 A/B
→ 缓存布局输入、减少重复轮廓读取
→ 只为缺失覆盖补手工尺寸
→ 最后才评估 C# Shim
```

## 1. 审校明细：保留、修改、停止

| 原方向 | 判定 | 修正 |
|---|---|---|
| 减少重建与刷新 | 保留 | 通过批处理作用域和显式同步点实现，不虚构 `swAutomaticRebuild` |
| 比例预计算 | 保留但不大重写 | 当前已有模型包围盒、标准比例和真实轮廓校正，只减少校正轮次 |
| 尺寸一次到位 | 修改 | 保留 `InsertModelAnnotations3` 的覆盖能力，手工 `AddDimension2` 只补缺口 |
| 尺寸批量外推 | 保留 | 先计算全部目标位置，再每条只写一次，最后统一同步 |
| 注释批量插入 | 保留 | 各工具使用 `save=False`，统一保存；技术要求优先合并成一条多行 Note |
| C# Shim | 延后 | 只有 A/B 测量显示 Python/COM 遍历成为主瓶颈时才做 |
| save-reload-verify | 保留最终验证 | 不在每个工具内部各做一次，整图完成后统一做 |
| 静态字符串性能断言 | 停止 | 改为运行时调用计数、首选项恢复和正确性测试 |

## 2. 现有代码可以复用什么

基于当前源码，不应重新写一套平行出图系统。

### 2.1 布局与比例

已有：

- `_model_box`
- `_standard_scale`
- `_fit_scale`
- `_place_views`
- `precise_outline`
- 创建后真实轮廓测量和有限次比例校正

优化重点应是：

- 缓存模板安全区；
- 缓存模型包围盒；
- 避免同一视图反复读取轮廓；
- 减少布局后再次全量重排；
- 保留最终越界检查。

**不要删除真实轮廓校正。** 模型包围盒不是投影轮廓，尤其装配体和等轴测视图仍需实测。

### 2.2 尺寸

已有：

- `InsertModelAnnotations3`
- `dimension_filter`
- `_dedupe_inserted_dimensions`
- `_push_dimensions_outside`
- `layout_dimensions`
- `add_drawing_dimension`
- `survey_dimensions_by_view`

优化重点：

- 保留 all-views 的模型尺寸覆盖；
- 不让“等轴测 0 尺寸”成为错误；
- 对必须存在但没有被导入的尺寸，才走手工尺寸补建；
- 位置规划与 COM 写入分离；
- 每条尺寸最多写一次位置；
- 不在去重、过滤、外推每个子阶段分别保存。

### 2.3 注解与验证

已有：

- `add_note`
- `add_geometric_tolerance`
- `add_datum_feature`
- `add_surface_finish`
- BOM 原生路径
- `drawing_audit`
- `delivery_check`
- PDF 导出与渲染检查

性能优化不能回退这些已经修复的功能，特别是：

- GTol 的旧格式写入 → ConvertFormat → XML 顺序；
- GTol 引线参数与 PDF 验证；
- BOM 数量列与数据行验证；
- 剖面线和焊接符号不能因“只检查对象存在”而误判完成。

## 3. 目标架构：一条带显式同步点的流水线

建议主流程收敛为一个编排函数，而不是让每个工具各自保存、刷新、审计。

```text
prepare
  ├─ 打开/复用模型
  ├─ 装配轻化处理
  ├─ 读取模型 box、模板 safe area（一次）
  └─ 打开性能记录

drawing_batch.enter
  ├─ 保存原始首选项
  ├─ 按需关闭可关闭的真实开关
  └─ 开始计时

create_views
  ├─ 使用预测比例
  ├─ 创建全部视图
  └─ sync("view_geometry")：必须同步，才能读真实轮廓

layout
  ├─ 读取/缓存真实轮廓
  ├─ 计算比例和位置
  ├─ 统一写回
  └─ 只在需要实际几何反馈时同步

annotations
  ├─ 尺寸导入与筛选
  ├─ 尺寸位置统一写回
  ├─ 注释/GD&T/BOM
  └─ 各子工具 save=False，不各自刷新

finalize
  ├─ sync("final")
  ├─ 保存一次
  ├─ 最终审计 / PDF 验证
  └─ 输出性能与正确性报告

finally
  └─ 恢复首选项、图形设置、只关闭本次创建的文档
```

### 同步点原则

只有以下情况允许同步：

1. 创建视图后，需要真实轮廓；
2. 几何或模型引用发生变化，而后续查询依赖新几何；
3. 最终保存、导出和审计前；
4. 已证明某个 API 不同步就返回过期数据。

禁止在以下循环中默认同步：

- 每条注释；
- 每次位置写入；
- 每个尺寸去重判断；
- 每次轮廓读取；
- 每次 GTol 属性读取。

## 4. 批处理作用域规格

### 4.1 目的

`DrawingBatch` 负责：

- 保存并恢复首选项；
- 按需抑制尺寸输入对话框；
- 小范围控制自动视图更新；
- 提供显式 `sync()`；
- 统一保存；
- 异常时也恢复环境。

### 4.2 真实可用的开关

本机类型库已确认：

| 名称 | 数值（SW2024 SP4） | 层级 | 用途 |
|---|---:|---|---|
| `swInputDimValOnCreate` | 10 | 应用 | 禁止创建尺寸时弹输入框 |
| `swDrawingAutomaticViewUpdate` | 90 | 文档 | 自动视图更新开关 |

注意：

- 第二个参数是 `swUserPreferenceOption_e`，一般传 `swDetailingNoOptionSpecified=0`，不是文档类型。
- 当前某些图纸的自动视图更新已经是 False；此时无需再改，也不能把提速归因于它。
- `SetUserPreferenceToggle` 返回“现在是否开启”，不是传统意义上的成功/失败。必须读回确认。
- 不要把应用级开关与文档级开关混用。

### 4.3 默认不做的激进设置

以下设置只能在专项测试后启用：

- `EnableGraphicsUpdate=False`：可能影响选择、可见几何和最终预览；
- `SetDisplayWhenAdded(False)`：主要适用于草图实体批量创建，不应全局套在注解流程；
- `SetAddToDB(True)`：只适用于允许直接写数据库的草图路径；
- 隐藏 SolidWorks 窗口或锁 UI：可能破坏需要可见文档/选择的 API；
- 关闭重建后读取旧几何：必须由显式同步点保护。

### 4.4 不提供“事务回滚”的假象

SolidWorks COM 写入不是数据库事务。
发生异常时可以恢复首选项，但不能自动撤销几十个建模/注解操作。

因此：

- 新图任务写到临时输出路径；
- 已有图任务先复制文件或使用明确的临时输出；
- 最终验证通过后再替换正式交付文件；
- 不在原文件上声称“可一键回滚”。

## 5. 布局与比例优化规格

### 5.1 缓存键

轮廓缓存不得只按视图名长期保存。至少包含：

```text
drawing 规范化路径
view.Name
view 对象身份
ScaleDecimal
Position
当前模型配置
本轮 batch_id
```

任一变化都应失效。不要跨文档复用 COM 对象或轮廓缓存。

### 5.2 比例策略

保留现有标准比例和真实轮廓校正，但把预测输入补齐：

```text
视图几何需求
+ 视图间距
+ 标题栏/明细栏/模板安全区
+ 尺寸文字预计包络
+ 剖视/局部视图的投影约束
```

建议输出：

```json
{
  "predicted_scale": 0.2,
  "scale_reason": "annotation_envelope",
  "needs_measured_correction": true,
  "max_correction_rounds": 1
}
```

`max_correction_rounds=1` 只是性能目标，不是硬性删除保护。
若仍然越界，必须允许继续校正或返回明确错误。

### 5.3 禁止事项

- 不用纯模型 bbox 直接宣称布局完成；
- 不为省一次重建而读取创建前的默认轮廓；
- 不用放大视图来掩盖尺寸重叠；
- 不自动把 A3 改 A2 而不记录原因；
- 不把剖视图的投影对齐当作普通自由布局处理。

## 6. 尺寸优化规格

### 6.1 不再把“首视图集中”当成既定事实

当前代码和实测已经表明 `all_views=True` 可以在多个视图分配尺寸。
因此第一优先级不是替换它，而是测量：

- 插入总数；
- 各视图尺寸数；
- 必须删除的重复数；
- 去重/过滤/外推各阶段耗时；
- 必须覆盖但缺失的尺寸清单。

### 6.2 保留的主路径

```text
InsertModelAnnotations3(all_views=True)
→ 一次同步，使 view.GetAnnotations 可见
→ 基于模型 FullName 去重
→ 按计划过滤
→ 内存计算布局
→ 每条尺寸写一次位置
→ 最后统一同步
```

### 6.3 手工尺寸只作为补缺口路径

适用：

- 深度尺寸只在侧视/剖视能表达；
- 某关键尺寸未被模型项导入；
- 局部视图需要新的参考尺寸。

正确 `AddDimension2` 使用方式：

```python
# 1. 激活目标视图
# 2. 在目标视图中选择真实边/面/顶点
# 3. 必要时使用 SelectData.View = target_view
# 4. AddDimension2 只传文字位置
raw = doc.AddDimension2(x_m, y_m, 0.0)
```

不存在原方案示例中的：

```python
AddDimension2(x, y, z, sketchSegment, dimension_type)  # 错误，不可采用
```

### 6.4 位置写入纪律

- `SetPosition` 只改图纸位置，不改视图归属；
- 不用“把尺寸移到另一个视图坐标”伪装成改派视图；
- 不用相同数值去重；
- 模型 FullName、尺寸类型、语义和几何证据必须保留；
- 等轴测视图无尺寸是正常，不应触发补标。

## 7. 注释、GD&T、BOM 的批处理

### 7.1 保存策略

所有子工具支持并遵守：

```python
save=False
```

由编排层最后保存一次。

如果现有工具仍默认 `save=True`，实现时应保持公开默认兼容，但流水线内部显式传 False。

### 7.2 技术要求

优先把多条技术要求合并为**一条多行 Note**：

- 减少独立对象；
- 减少布局碰撞；
- 避免每条 Note 都执行保存/刷新。

若必须保留独立对象，再批量插入，但不重复审计。

### 7.3 GD&T

批量只表示“在同一 DrawingBatch 中执行”，不能改变已经验证的创建顺序：

```text
选择/附着目标
→ 旧格式写符号与数值
→ ConvertFormat
→ 必要时 AddFrame
→ SetSymbolXml
→ 正确 SetLeader3
```

不得为提速改成“先 ConvertFormat 再写数值”。

### 7.4 BOM

BOM 只在最终布局稳定后创建一次。
必须保留数量列、数据行、与装配数据对账的验证，不因耗时较长而改成普通文本表。

## 8. 保存、审计与 PDF 验证

### 8.1 当前可合并的成本

每个子工具各自执行保存/审计会放大成本。
改为：

```text
过程中：不保存、不审计
最终同步后：保存一次
最终交付前：审计一次
需要 PDF 时：导出一次并验证
```

### 8.2 不删除最终验证

不能为达到时间目标而删除：

- 保存后文件实际更新检查；
- 视图和尺寸覆盖检查；
- 尺寸附着与孤儿检查；
- GTol 符号/数值/基准/引线检查；
- BOM 数据检查；
- 剖面线/焊接图形的 PDF 检查。

性能与正确性是两条门禁，任何一条失败都不能交付。

## 9. 性能测量规格

### 9.1 必须先加仪器，再改算法

每次运行输出 JSONL 一条记录，至少包含：

```json
{
  "run_id": "uuid",
  "variant": "baseline|save_batch|view_update_off|layout_cache|phase1",
  "sw_revision": "32.4.0",
  "model_path": "规范化路径或脱敏标识",
  "model_class": "part|assembly",
  "view_count": 4,
  "dimension_count": 30,
  "success": true,
  "correctness_pass": true,
  "timings_ms": {
    "model_open": 0,
    "drawing_create": 0,
    "view_create": 0,
    "geometry_sync": 0,
    "dimension_insert": 0,
    "dimension_dedupe": 0,
    "dimension_layout": 0,
    "annotations": 0,
    "bom": 0,
    "save": 0,
    "audit": 0,
    "export": 0,
    "total": 0
  },
  "counts": {
    "force_rebuild": 0,
    "graphics_redraw": 0,
    "save": 0,
    "layout_pass": 0
  }
}
```

### 9.2 测量方法

- 同一模型、同一模板、同一视图集合；
- 使用同一 SolidWorks 实例做 A/B；
- 冷启动与热缓存分开记录；
- 每组至少 5 次，正式结论建议 10 次；
- 记录中位数和 P95，**P95 不排除慢样本**；
- 首轮 JIT/文件缓存影响单独标记，不删除异常值；
- 同一测试记录打开文档数，避免文档泄漏拖慢后续样本。

### 9.3 性能结论格式

禁止写“预计提升 5 倍”作为验收结果。
只允许：

```text
variant A 中位数 xx s，P95 xx s；
variant B 中位数 yy s，P95 yy s；
样本 n=…；正确性门禁全部通过/失败；
性能差异及置信区间/样本限制。
```

## 10. 分阶段实施计划

### PR0：只加测量，不改行为

内容：

- 引入 `PerfRecorder`；
- 包装现有 ForceRebuild3、GraphicsRedraw2、保存和审计调用；
- 输出基线 JSONL；
- 建立 10~20 个代表模型的小型基准，再扩展到 100 张真实图纸。

验收：

- 结果可重复；
- 无功能变化；
- 能定位最耗时阶段。

### PR1：合并保存与最终审计

内容：

- 编排层统一传 `save=False`；
- 删除子阶段重复审计；
- 最终保存一次、审计一次；
- 异常路径恢复首选项。

验收：

- 保存次数下降；
- 最终文件仍更新；
- 正确性测试不变差；
- 统计实际耗时变化。

### PR2：显式同步点与真实开关 A/B

内容：

- 引入 `DrawingBatch`；
- 只在真实同步点重建/刷新；
- 对 `swDrawingAutomaticViewUpdate` 做 A/B；
- 对尺寸输入对话框开关做异常恢复测试。

验收：

- 读取轮廓前一定同步；
- 无过期几何；
- 设置恢复；
- 如果开关原来就是 False，不虚报收益。

### PR3：布局缓存与位置一次性写入

内容：

- 缓存模板安全区、模型 box、真实轮廓；
- 位置计算与 COM 写入分离；
- 同一尺寸/视图每轮最多写一次；
- 保留越界与重叠校验。

验收：

- 轮廓读取次数下降；
- 无重复位置写入；
- 尺寸重叠率和越界率不升高。

### PR4：尺寸覆盖补偿

内容：

- 先输出缺失覆盖清单；
- 只对必要缺口使用 `AddDimension2`；
- 使用目标视图选择上下文；
- 保留模型项主路径。

验收：

- 无 empty-view 误报；
- 无同值误删；
- 无“移动位置冒充改派视图”；
- 补偿尺寸与几何证据一致。

### PR5：可选 C# Shim

进入条件必须同时满足：

- 测量显示 Python 遍历/COM 调用是主要剩余瓶颈；
- 纯 Python 批处理已完成；
- 有明确的高频循环可迁移；
- 能维护部署和回归测试。

若不满足，停止，不引入新组件。

## 11. C# Shim 的强制修正

若最终需要 Shim：

- 使用 `Marshal.GetActiveObject("SldWorks.Application")`，不要 `new SldWorks()` 创建新实例；
- 不在 Shim 内盲目 `OpenDoc6` 打开另一个文档副本；
- 明确 OpenDoc6 的 ByRef errors/warnings；
- 明确 STA、进程和位数；
- 不关闭用户已有文档；
- 返回结构化错误；
- 与 Python 走完全相同的正确性验证；
- 纯 Python 路径永久保留。

Shim 的价值主要是强类型和减少宿主遍历开销，**不是让 SolidWorks 内部重建消失**。

## 12. 正确性与回归测试矩阵

| 类别 | 必须覆盖 |
|---|---|
| 基本出图 | 零件、装配、钣金、含剖视/局部视图 |
| 布局 | 1/2/3/4 视图，A3/A2，不同投影比 |
| 尺寸 | 标记/非标记、同值异义、剖视深度、局部视图 |
| 注解 | 多行技术要求、GTol、基准、粗糙度、BOM |
| 引线 | 返回 0、LeaderSide 正确、PDF 实际可见 |
| 保存 | 目标已打开、只读、同名冲突、路径未更新 |
| 异常恢复 | 中途异常后首选项/图形设置恢复 |
| 文档管理 | 文档数不增长，不关闭用户已有文档 |
| 幂等 | 重复运行不重复插入、不重复移动已有内容 |
| 性能 | 中位数、P95、冷/热运行、打开文档数 |

## 13. 失败语义

以下情况不得返回 `ok:true`：

- 最终文件没有实际更新；
- 使用了过期轮廓导致越界；
- 必须尺寸缺失但未报告；
- GTol 数值或引线只在 XML/状态中、图面不可见；
- BOM 无数量列或数据行；
- 性能提升来自删除最终审计；
- 测试结束后首选项未恢复；
- 文档数持续增长。

## 14. 最终目标表达

原“15~30 秒”可保留为简单/中等图纸的优化目标，但不能写成所有图纸的承诺。

建议验收目标：

```text
第一阶段：中位耗时显著下降，P95 不恶化，正确性全通过；
第二阶段：按模型复杂度分桶设目标；
最终：用真实基准数据决定是否继续 Shim，而不是预设倍数。
```

核心原则不变：

> 先测量，再减少重复工作；先保证图面正确，再追求速度。
