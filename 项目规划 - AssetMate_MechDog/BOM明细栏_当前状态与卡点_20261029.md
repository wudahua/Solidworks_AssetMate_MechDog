## 零、12:30 更新：工具路径已通，根因是重复函数

「脚本成、工具败」的原因找到了，与 COM 无关：

```
$ grep -n "def add_bom_table" tools/layout.py
361: def add_bom_table(..., bom_type=2, anchor_type=1, ...)    ← 新版
569: def add_bom_table(drawing_path, view_name=None, save=True) ← 旧版（宏驱动）
```

**同一文件里两个同名函数，后定义的覆盖前面**，所以工具一直跑的是旧版（宏驱动那段）。

这是我这轮真正的失误：我用字符串替换重写函数时，插入到了文件中段，而没有删除末尾的旧版，**却没有验证 `inspect.getsource()` 的实际内容**。

修掉重复 + 两处调用错误（`GetExecutablePath` 是属性不能加括号、`ReferencedDocument` 返回的 `PyIDispatch` 需 `Dispatch` 包装）后：

```
ok: True | created: True | rows: 1 | bom_feature: True | populated: False
```

**工具路径现在能创建表格了。** 剩下只有「数据行」这一件事。

> 方案 §2 的「B 层直接调用 layout 函数」是这次的关键动作——我此前一直在脚本里**重写**调用序列，从没直接调用工具函数本身，所以完全没发现它跑的是旧代码。

## 二、已经解决的部分（两个枚举值）

此前报告说「20+ 组合全失败」，根因是我传错了两个枚举值：

| 参数 | 我此前传 | 正确值 | 后果 |
|---|---:|---:|---|
| `AnchorType` | `0` | **`1`**（TopLeft） | 0 不是有效成员，**每次调用直接返回 `None`** |
| `BomType` | `1` | **`2`**（TopLevelOnly） | 1 是 `PartsOnly`，不是宏里的类型 |

改完立刻从「返回 None」变成「返回表格对象」。

> 附带影响：我在 `capabilities.py` 里曾写 `swBomType_TopLevelOnly = 1`，这个值是错的，可能已污染其他文档。

**可复现的最小调用**（已实测）：

```python
doc.ActivateView(view.Name)
doc.ClearSelection2(True)

table = view.InsertBomTable4(
    False, 0.24, 0.19,
    1,      # AnchorType = TopLeft
    2,      # BomType = TopLevelOnly
    '',     # Configuration（TopLevelOnly 传空串）
    tpl,    # D:\...\lang\chinese-simplified\bom-standard.sldbomtbt
    False, 0, False,
)
# → CDispatch，图纸表格数 0→1
```

回读：

```
rows=1  cols=3
r0: ['项目号', '零件号', '说明']
BomFeature: 可取到
```

`BomType` 1/2/3 × `Configuration`（`''`/`Default`/`UP`）九种组合，全部创建成功、全部 rows=1。

## 三、问题一：封进工具后失败

### 3.1 现象

| 执行路径 | 结果 |
|---|---|
| 独立脚本（先 `open_document(装配)` → `create_drawing` → `_open_drawing` → 插入） | ✅ 表格 0→1 |
| `layout.add_bom_table(drawing_path)` | ❌ 表格 0→0，`bom_table_not_created` |

### 3.2 已排除：活动文档被切走

上一份方案判断「工具里打开装配会把活动文档切走，之后用缓存的 view 插入必失败」。**这个判断是对的——我的补丁确实制造了这个顺序。**

已按方案修：打开装配后重新 `_open_drawing` → `ActivateSheet` → 从 `sheet.GetViews` 重取 view（不用旧对象）→ `ActivateView` → 硬断言 `sw.ActiveDoc.GetTitle == doc.GetTitle`。

结果：

```
断言未触发  →  活动文档确实已切回图纸
但仍失败    →  表格 0→0
```

**所以活动文档不是唯一原因。**

### 3.3 已排除的其他项

| 项 | 处理 | 结果 |
|---|---|---|
| 装配未打开 | 工具内用 `ReferencedDocument` 取路径并打开 | 无效 |
| 模板路径 | 显式传默认路径，`os.path.exists` 为真 | 无效 |
| 视图选取 | 都取 `Type != 1` 的第一个视图 | 一致 |
| 表格计数 | 都用 `len(GetFirstView.GetTableAnnotations)` | 一致 |
| 参数值 | 完全相同的 10 个参数 | 一致 |
| 重建调用 | 都用 `call_method(doc,'ForceRebuild3',False)` | 一致 |

### 3.4 为什么我自己查不下去了

方案 §4 建议做「上下文指纹对照」——两条路径在插入前各打印一份 JSON（`sw_active_path` / `doc_path` / `sheet` / `view_configuration` / `selection_count` / `args` / `thread` / `pid`），第一个不同项就是修复点。

**这个方法对，但我拿不到工具侧的运行时快照**：

- 独立脚本：我自己写的，随时可打印
- 工具：通过 MCP 协议在子进程里跑，我只能拿到它的返回 JSON

**这是我这轮真正卡住的地方，不是技术问题，是观测手段问题。**

## 四、问题二：表格只有表头

### 4.1 现象

```
rows=1  cols=3
r0: ['项目号', '零件号', '说明']
```

而宏录制那次是 **10 行 × 4 列**（9 行数据，与装配的 9 行一一对应）。

### 4.2 已排除：配置可见性（含列数证据）

**新增判据：`ColumnCount` 才是关键。** 宏成功时为 4 列（多一列"数量"），我的一直是 3 列：

```
before: rows=1 cols=3
header: ['项目号', '零件号', '说明']
```

TopLevelOnly 应为每个所选配置生成数量列。**3 列 = 没有关联出任何配置数量列**，这比「没有数据行」更靠前。

用装配配置名手工构造（绕开调不通的 `GetConfigurations`）：

```python
names = ['Default', 'UP']          # assembly.GetConfigurationNames
vis   = [True, False]              # 目标 = view.ReferencedConfiguration = 'Default'
bf.SetConfigurations(False, vis, names)
```

三种封送形式的结果：

| 形式 | 返回 | 列数 |
|---|---|---|
| plain list | `True` | 3（不变） |
| `VT_ARRAY\|VT_VARIANT` | `True` | 3（不变） |
| `VT_ARRAY\|VT_BSTR` | **`False`** | 3（不变） |

**`SetConfigurations` 返回 True 不等于配置进入表格**——列数始终 3。

### 4.2b 已排除：缺失项策略

按方案 §8 做诊断：

```
KeepMissingItems = True        → rows=1 cols=3（不变）
StrikeoutMissingItems = True   → rows=1 cols=3（不变）
```

组件缺失不是根因。

### 4.3 已排除：配置可见性（旧记录，保留）

方案指出 `SetConfigurations` 是三参数：

```python
bf.SetConfigurations(OnlyVisible: bool, Visible: object, Names: object)
```

实测：

```
3arg list              -> True
3arg VT_ARRAY|VARIANT  -> True
rows now: 1（不变）
```

**调用成功，行数不变。配置可见性不是根因。**

同时采集的状态：

```
TableType                      2  (TopLevelOnly，与传入一致)
view.ReferencedConfiguration   'Default'
KeepMissingItems               False
StrikeoutMissingItems          False
GetConfigurations(False, None) → DISP_E_TYPEMISMATCH（读不出来）
```

### 4.3 已排除：重建方式

| 尝试 | 结果 |
|---|---|
| `call_method(doc,'EditRebuild3')` | 返回 True，rows 不变 |
| `call_method(doc,'ForceRebuild3',False)` | 返回 True，rows 不变 |
| `doc.EditRebuild3`（属性取值） | 不报错，rows 不变 |
| `doc.EditRebuild3()`（加括号） | **`TypeError: 'bool' object is not callable`** |

> **`EditRebuild3` 在这套绑定下是属性，不是方法。** 上一份方案说「必须加括号」，在本机是反的。
