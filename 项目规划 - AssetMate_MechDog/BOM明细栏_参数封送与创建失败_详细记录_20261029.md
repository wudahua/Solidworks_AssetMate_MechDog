## 二、三条有价值的技术发现

这三条是本次唯一可复用的产出——下次不必再从错误的方向重来。

### 2.1 `IView.InsertBomTable4` 是 10 个参数，第一个是 `bool` 不是模板

官方 2024 文档（`InsertBomTable4`，2013 FCS 起）：

```text
InsertBomTable4(
  UseAnchorPoint        : bool      ← 第 1 参数
  X                     : double
  Y                     : double
  AnchorType            : int       (swBomConfigurationAnchorType_e)
  BomType               : int       (swBomType_e)
  Configuration         : string
  TableTemplate         : string    ← 模板在第 7 位
  Hidden                : bool
  IndentedNumberingType : int       (swNumberingType_e)
  DetailedCutList       : bool
) → BomTableAnnotation
```

**我此前整晚按 6 参数调用、把模板路径放在第 1 位**——等于让 `bool` 接字符串，必然 `DISP_E_TYPEMISMATCH`。

这解释了为什么「4/5/6/7 个参数全试过」都没用：**参数个数不是一个连续可试探的量，而是一个必须先查文档的确切值**。

### 2.2 `IView.InsertBomTable5` 是 11 个参数，2024 FCS 起可用

```text
InsertBomTable5(...同上..., DissolvePartLevelRows : bool)
```

比 4 多一个参数，**可用性 SOLIDWORKS 2024 FCS**——本机正是 2024 SP4，理应可用。文档同时标注 `InsertBomTable4` 已 **Obsolete**。

**所以正确顺序是：2024+ 优先试 5，而不是 4。**

### 2.3 `swBomType_e` 的真实值是 1/2/3/4

```text
swBomType_TopLevelOnly   = 1
swBomType_PartsOnly      = 2
swBomType_Indented       = 3
swBomType_Flattened      = 4
```

我最初按 0/1/2 猜。**0 不是有效成员**——传无效枚举可能不报错、直接「不创建」，与观察到的 `None` 一致。

> 说明：该枚举的官方页面在 WebFetch 时只返回目录（正文被截断），上述数值来自枚举命名惯例与检索结果，**未从官方页面逐字确认**。若规划者要用于定论，建议先核对 `swconst` 类型库。

### 2.4 附带一条环境知识

`ISldWorks.GetExecutablePath` 返回的是**安装目录**（`D:\Program Files\SOLIDWORKS Corp\SOLIDWORKS`），不是可执行文件路径。

所以模板路径是：

```
<GetExecutablePath>\lang\<language>\bom-standard.sldbomtbt
```

我第一次按「文件路径」取 `dirname` 两次，算错两层，导致模板传空——这也是早期 `None` 的原因之一。

## 四、逐轮记录（思路演进）

### 第一轮：以为参数个数是试出来的

按 4/5/6/7 参数轮试，全部类型不匹配。

**错误假设**：以为 API 会「忽略多余参数」或「按最少参数匹配」。
**实际**：COM 调用参数个数必须完全精确，多一个少一个都是 `TYPEMISMATCH` 或「非选择性的参数」。

### 第二轮：以为显式 VARIANT 能解决封送

用 `VARIANT(VT_BSTR, ...)` / `VARIANT(VT_R8, ...)` / 手动 `ole.Invoke(DISPATCH_METHOD)` 三种方式重试。

**结果**：一样失败。

**说明**：封送本身没问题（同一套封装在 `InsertGtol`、`AddHoleCallout2` 上都是通的）。问题在参数表本身。

### 第三轮：查官方文档，拿到真实签名（突破）

WebFetch 官方 2024 页面，得到 **10 参数**签名，第一个是 `UseAnchorPoint: bool`。

改成正确签名后：**不再报类型不匹配，变成返回 `None`**。

**这是质变**——从「调用方式错误」进入「调用成功但业务拒绝」。

### 第四轮：以为是 `BomType` 值错

按 0/1/2 试过无效，改试 1/2/3/4（真实枚举）。

**结果**：仍全 `None`。

### 第五轮：以为是模板路径错

发现 `GetExecutablePath` 返回目录而非文件，之前路径算错两层。修正后确认：

```python
tpl = os.path.join(base, 'lang', 'chinese-simplified', 'bom-standard.sldbomtbt')
os.path.exists(tpl)  # True
```

**结果**：仍 `None`。

### 第六轮：以为是上下文状态

试 `EditSheet` / `ActivateSheet` / 先 `SaveAs3` 存盘 / 视图激活与否。

**结果**：无差别，全 `None`。

### 第七轮：换 API —— `InsertTableAnnotation2`（通用表格）

反馈报告说这个「能创建，只是 X/Y 相对锚点」，说明在**他们那次**是成功的。

本机重试（7 参数，anchor True/False，模板空/真实，sheet/view 两种激活）：

**结果**：全 `None`。

### 第八轮：换 `InsertBomTable5`

11 参数，BomType 1–4。

**结果**：全 `None`。

## 五、`返回 None` 到底意味着什么

这一点值得单独说，因为它容易被误读。

```
抛异常（如 TYPEMISMATCH）  = 调用没进去，参数或方式错
返回 None（无异常）        = 调用进去了，业务层拒绝创建
```

**两者是完全不同的失败。** 前者是自己的问题，后者是环境或前置条件的问题。

本次走到「返回 None」这一步，说明：

- COM 调用链是通的
- SolidWorks 收到了请求
- 但它决定不创建，且**不告诉你为什么**

这种「静默拒绝」在 SolidWorks API 里并不罕见（`OpenDoc6` 失败也常返回 None 而非异常）。所以下一步不能再靠试参数，**必须去找它拒绝的理由**。

## 九、方法论反思（三条）

### 9.1 「参数个数是试出来的」这个假设本身就是错的

COM 方法签名是**确切的**，不是区间。试 4/5/6/7 参数是在浪费轮次——**应该一开始就查文档**。

这和形位公差那次的教训一样：查官方文档正文 5 分钟，胜过试 20 种组合。

### 9.2 `WebFetch` 拿枚举细节不可靠

`swBomType_e` 的页面只返回了目录，正文被截断。这导致我只能靠惯例推断 1/2/3/4——**没从官方逐字确认**。

更可靠的做法：读本机 `SolidWorks.Interop.swconst.dll` 的类型库（`oleview` 或 .NET 反射）。

### 9.3 「同一 API 在别人环境成功、我这儿返回 None」时，先怀疑环境

反馈报告明确说 `InsertTableAnnotation2` 能创建（只是位置不对）。我这台全 `None`。

**这不代表报告有误，也不代表我调错了**——很可能两边环境不同（模板、文档属性、SW 配置）。此时继续在本机试参数是无用功，**应该先做一次界面验证**。
