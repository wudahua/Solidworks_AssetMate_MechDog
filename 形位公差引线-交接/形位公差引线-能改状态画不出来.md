# 形位公差引线：能改状态，画不出来（交接给规划者）

> 目标：让 `add_geometric_tolerance` 画出的形位公差框格**带引线**（指向被测要素），
> 进而支持国标习惯的**转折引线**（先出一小段水平线再折下打箭头）。
>
> 实测环境：SOLIDWORKS 2024 SP4（32.4.0）· pywin32 晚绑定 · Python 3.13 · 2026-11-03
> 证据：`证据/框格无引线_改计数后仍空白.png`（反馈方图纸，加引线后渲染）

---

## 一、需求（来自用户评审）

> "形位公差的位置好像不对？圆柱度缺少基准面和引线？"
> "引线好像不对，是不是要加个垂直转折？"

拆开是两条：

| 子需求 | 判定 |
|---|---|
| 圆柱度缺**基准面** | **评审误解**——圆柱度是形状公差，GB/T 1182 不允许引用基准 |
| 圆柱度缺**引线** | **确实缺**，本文的主题 |
| 引线要**垂直转折** | 国标习惯"框格先出一小段水平线再折下打箭头" |

**为什么要紧**：框格悬空时，读图者无法判断它管 Ø10、轴环还是整根轴。
反馈原话："框格放在 Ø10 上方、箭头指向下表面，读者会以为公差管下半段，**比不画更容易误读**。"

---

## 二、现象

`add_geometric_tolerance` 只给 `x/y` 时：

```json
{"ok": true, "attached_to": null, "frame_has_leader": false}
```

框格落在指定点，**没有引线、没有箭头**。

给 `edge_index` 时**也会失败**（在旋转轴上实测，两条路 `attached_to` 都是 null）。

---

## 三、三层追查（含两次自我更正）

### 第一层：我一开始查错了对象（已更正）

第一版结论写的是「没有入口」——**错的**。

原因：我只查了 `GetSpecificAnnotation` 返回的对象。

```python
spec = win.Dispatch(annotation.GetSpecificAnnotation)
spec.SetLeader2   # ❌ 不存在
spec.AttachTo     # ❌ 不存在
spec.GetLeaderCount  # ✅ 有，但只能读
```

**而真正的接口在 `IAnnotation` 上**：

```python
annotation.SetLeader2       # ✅ 存在
annotation.SetLeader3       # ✅ 存在
annotation.SetLeader          # ✅ 存在
annotation.GetLeaderCount   # ✅ 存在
```

### 第二层：对象类型也查错了（已更正）

我拿 `GetType == 6` 的对象试——**那是 note**。

真正的形位公差是 **`GetType == 7`**。

在反馈方那张图上：

```
type=4  D1 / D2                  ← 尺寸
type=13 细节项目254 / 257         ← 表面粗糙度？
type=7  细节项目260               ← 形位公差（本文对象）
type=5  细节项目261
type=6  细节项目256 / 262         ← 技术要求（note）
type=1  装饰螺纹线1
```

### 第三层：参数对了，状态变了，但图面不画

在 `type=7` 的对象上：

```python
SetLeader3(1, True, 2, 0, True, True)
# 位置参数: LeaderType, UseDocLeaderStyle, LeaderStyle, ArrowSize, UseDocArrowSize, LeaderBent
# LeaderStyle=2 (bent), LeaderBent=True —— 正是"转折"要的
```

**实测 arity = 6**（`SetLeader2` 和 `SetLeader3` 都是）。

| 调用 | 返回 | `GetLeaderCount` |
|---|---|---|
| 调用前 | — | **0** |
| `SetLeader3(1, True, 1, 0, True, True)` | `-2` | — |
| **`SetLeader3(1, True, 2, 0, True, True)`** | **`-2`** | **1** ✅ |
| `SetLeader3(True, True, 2, 0, True, True)` | `-1` | 1 |
| `SetLeader3(True, False, 2, 0, True, True)` | `-1` | 1 |

**`-2` 是"有问题"不是"失败"**——引线计数从 0 变成 1，对象状态确实改了。

**但导出 PDF 渲染**：

> `⌓ 0.008` 框格在，**没有任何引线**。

见 `证据/框格无引线_改计数后仍空白.png`。

## 四、根因假设：缺少可附着的几何

**同源问题第三次出现**：

| 对象 | 症状 | 版本 |
|---|---|---|
| GTol 符号格 | 存字符串、`GetText` 读回一致、**不渲染** | 0.8.58 已解（`IGtolFrame` XML） |
| 焊接符号 | 存字符串、`GetText` 读回一致、**不渲染** | 0.8.67 改用草图线绕过 |
| **形位公差引线** | 改计数、`GetLeaderCount` 读回 1、**不渲染** | **本文** |

**共同点**：SW 接受了状态变更，但没有生成可见几何。

**为什么**：这批零件的**轮廓边没有顶点**（`GetStartVertex` 恒返回 None，v0.8.24 记录），
所以：

- `AttachTo` 返回 null
- `attached_to` 为 null
- **没有附着点，引线退化成零长度 → 看不见**

**这不是参数问题，是"先有边、才有引线"的顺序问题。**

## 五、复现脚本

```python
import sys, os, shutil, tempfile
sys.path.insert(0, "src")
import win32com.client as win
from solidworks_assetmate_mechdog.tools import drawing
from solidworks_assetmate_mechdog.sw_session import call_method

SRC = "测试用例/旋转轴-工程图/out/旋转轴-工程图.SLDDRW"   # 反馈方的图纸
work = tempfile.mkdtemp(prefix="leader_")
drw = os.path.join(work, "his.SLDDRW")
shutil.copy2(SRC, drw)

try:
    d = drawing._open_drawing(drw)

    # 1) 找到形位公差：GetType == 7（不是 6！）
    gt = None
    for v in drawing._iter_views(d):
        for raw in (v.GetAnnotations or ()):
            a = win.Dispatch(raw)
            try:
                if int(a.GetType) == 7:
                    gt = a
                    break
            except Exception:
                pass
        if gt:
            break
    print("gtol:", str(gt.GetName))              # 细节项目260

    # 2) 设引线：LeaderStyle=2 (bent) + LeaderBent=True
    print("before:", int(gt.GetLeaderCount))    # 0
    r = drawing._invoke_as_method(gt, "SetLeader3", 1, True, 2, 0, True, True)
    print("SetLeader3 ->", r)                   # -2
    print("after :", int(gt.GetLeaderCount))    # 1  ← 状态变了

    # 3) 重建 + 导出，图面仍然空白
    try:
        call_method(d, "EditRebuild3")          # 注意：是方法，属性访问会 TypeError
    except Exception:
        pass
    try:
        d.GraphicsRedraw2()
    except Exception:
        pass
    drawing._save_drawing(d)
    pdf = os.path.join(work, "out.pdf")
    if drawing.export_drawing(drw, pdf).get("ok"):
        drawing.render_drawing(pdf, output_dir=work, scale=5.0)
    print("WORKDIR:", work)
finally:
    drawing.close_document(drw)
```

**预期**：`leaders 0 -> 1`，PDF 里框格**没有引线**。

## 六、待查方向（按成本从低到高）

### ① `LeaderType` 的枚举值可能不对

我传的是 `1`（`SetLeader3` 的第一个参数）。`swLeaderType_e` 的真实取值没查到：

- 是否 `1` 表示"直线引线"？
- 是否需要先有 `LeaderStyle` 才能设 `LeaderType`？

**最省事的验证**：在 UI 里手工给一个框格加引线，**录宏**，看它调的什么值。GTol 符号那次
（0.8.58）就是靠官方文档说清"圆柱度不允许基准"才停手的。

### ② `AttachTo` 才是前置条件，`SetLeader3` 只是摆设

如果 `AttachTo(edge)` 能成功，引线可能有落点。但这批零件的边没有顶点：

```python
annotation.AttachTo   # 在 spec 上不存在，在 IAnnotation 上有？
```

**需要确认 `IAnnotation.AttachTo` 的签名与实际返回**。

### ③ 换一个"轮廓边有顶点"的零件对照

v0.8.24 记录 `GetStartVertex` 对全圆边实体返回 None。
**但如果换一个钣金/方块零件**（边是直线、有顶点），`AttachTo` + `SetLeader3` 是否就通了？

**这条最有价值**：能区分"引线功能本身坏了"和"这些零件的边特殊"。

### ④ 是否需要 `Save3` 之前 `EditRebuild3`

我调了 `EditRebuild3`（用 `call_method`，属性访问会 `TypeError`），但可能顺序不对。
**UI 手工加引线后保存再到导出**，这条链路是通的——说明不是"渲染器不支持"。

## 八、这一条与 P0-1 的关系

**P2-1 挡在 P0-1 的另一半后面。**

| P0-1 的两半 | 状态 |
|---|---|
| 轴映射（`axes_ambiguous`） | ✅ v0.8.70 修好 |
| 圆边投影（`CircleParams`） | ✅ v0.8.70 补上 |
| **直线边取几何（`GetStartVertex`）** | ❌ **仍无解**（v0.8.24 确认） |

**引线要落在边上 → 边要能被选中/取到几何 → 直线边取不到 → 引线退化。**

所以 P2-1 有两条路：

- **A. 先解决直线边取几何**（影响面更大：尺寸定位、孔标注、引线都依赖它）
- **B. 先确认"直线边有顶点的零件能出引线"**，把问题范围缩小到"特定边的类型"

**建议先做 B**——一次实验就能知道该修哪一层。
