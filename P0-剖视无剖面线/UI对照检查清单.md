# UI 对照检查清单：剖视图无剖面线

> 目的：用 30 分钟界面对照，把根因从「A 视图级属性」和「B 几何无效」里二选一。
> 结论出来后，修复路径就唯一了，不用再猜 API。
>
> 前置：本机已复现（`P0-剖视无剖面线/证据/axis/drawing_p1.png`，A-A 内部全白）。
> 建议全程**开着宏录制**（见文末），每一步的操作都能变成代码。

---

## 准备

1. 打开 `P0-剖视无剖面线/证据/axis/drawing.SLDDRW`
2. **先确认现状**：找到标 A-A 的那个细长视图，放大看——应该没有 45° 斜线
3. **另存一个副本**（`drawing_ui_test.SLDDRW`），后面所有操作都在副本上做

---

## 步骤 A：UI 手工建一个同位置的剖视

目的：区分「工具创建有问题」还是「环境本身画不出」。

1. 切到 `工程图视图1`（那个阶梯轴的主视图）
2. **插入 → 工程图视图 → 剖面视图**
3. 剖切线画在**和 API 相同的位置**（视图水平中线，横向贯穿）
4. 方向保持默认，标签用 `C`（避免和 A/B 混淆）
5. 放到图纸空白处

**立刻看**：新剖视 `C-C` 的剖切面有没有斜线？

| 结果 | 含义 | 下一步 |
|---|---|---|
| **有线** | 环境能画，**工具创建方式有差异** | 跳到「步骤 D：对比宏」 |
| **无线** | 环境和工具都画不出 | 继续步骤 B |

---

## 步骤 B：检查视图级剖面线属性

目的：确认是不是「区域剖面线被设成 None / 材质剖面线没勾」。

1. **右键** 剖视图 `C-C` → **属性**（或双击视图边框）
2. 切到 **显示** 标签页（Display）
3. 找到 **区域剖面线 / Area hatch** 区域，逐项看：

| 项目 | 期望值 | 实际值（请填写） |
|---|---|---|
| **Hatch**（剖面线图案） | 不是 `None` | |
| **Material crosshatch**（材质剖面线） | 勾选状态 | |
| **Hatch pattern**（图案名） | `ANSI31` 或类似 | |
| **Scale**（比例） | 非 0 | |
| **Angle**（角度） | 45° | |
| **颜色 / 图层** | 不是白色 | |

**关键动作**：

- 若 `Hatch = None` → **改成 `ANSI31`** → 确定 → **重建**（Ctrl+B）→ 看有没有线
- 若勾了 `Material crosshatch` → **取消勾选** → 手动选 `ANSI31` → 确定 → 重建 → 看有没有线
- 若颜色是白色 → 改成黑色 → 重建 → 看有没有线

| 结果 | 含义 |
|---|---|
| **改完有线** | 根因 = **视图级剖面线属性**（A 类）。去步骤 D 录宏，拿到对应 API |
| 改完仍无线 | 继续步骤 C |

---

## 步骤 C：检查几何是否有有效剖切面

目的：确认「剖切面是否真的切到了实体」。

### C1. 看剖切轮廓

放大 `C-C` 的边界线。反馈里提到过「小端出现**波浪线**」——波浪线是 SW 表示「剖切面在此处没有穿过实体」的标志。

| 观察 | 含义 |
|---|---|
| 轮廓全是直线 | 剖切正常，问题不在几何 |
| 出现**波浪线 / 断裂线** | **剖切面部分没切到实体** → 大概率 B 类 |

### C2. 检查模型几何

1. 打开 `P0-剖视无剖面线/证据/axis/model.SLDPRT`
2. **工具 → 评估 → 检查**（Check）
3. 勾选「无效的面/边线」「最小曲率半径」等，运行

| 结果 | 含义 |
|---|---|
| 报无效几何 | **B 类根因确认**：模型本身剖不干净 |
| 全部通过 | 几何正常，问题在视图属性（回到步骤 B 深挖） |

### C3. 换位置对照

1. 再建一个剖视 `D-D`，剖切线**沿轴向**（纵向），位置偏到轴的另一侧
2. 看有没有线

| 结果 | 含义 |
|---|---|
| 换位置有线 | 原位置**恰好切在空腔/槽**上 → B 类 |
| 换位置也无线 | 不是位置问题，回步骤 B |

---

## 步骤 D：宏录制（拿到真实调用序列）

**这是把 UI 结论变成代码的唯一办法。**

1. **工具 → 宏 → 录制**
2. 保存为 `hatch_fix.swp`（任意路径）
3. **重复一遍能出线的操作**（比如步骤 B 里那次改成 ANSI31）
4. **工具 → 宏 → 停止**
5. 打开生成的 `.swp` 同目录下的 `.swb`（VBA 源码），或直接在 SW 里 **工具 → 宏 → 编辑**

**要抓的关键行**：任何包含 `Hatch` / `AreaHatch` / `SetHatch` / `HatchPattern` / `MaterialCrosshatch` 的调用。

把这几行贴回来，就能直接映射成 pywin32 调用。

## 判定表（把结论填在这里）

| 检查 | 结果 |
|---|---|
| A. UI 建剖视有没有线 | ☐ 有 ☐ 无 |
| B. 改 Hatch / 取消 Material crosshatch 后有没有线 | ☐ 有 ☐ 无 |
| C1. 剖切轮廓有没有波浪线 | ☐ 有 ☐ 无 |
| C2. 检查几何体是否报错 | ☐ 报错 ☐ 通过 |
| C3. 换位置有没有线 | ☐ 有 ☐ 无 |

**结论**：
- B 项「有」→ **A 类（视图属性）**，等宏录制的 API 名
- C1/C2/C3 任一项异常 → **B 类（几何）**，需要先修模型或调整剖切位置
- 全「无」且几何正常 → 需要联系 SW 支持，或接受「本环境不支持零件剖视剖面线」并依赖 `hatch_missing` 拦截

## 现有兜底（已发布）

不管上面结论如何，工具现在**不会再把空白剖视报成成功**：

```python
add_section_view(...)  →  {"ok": false, "error": "hatch_missing",
                           "hatch_count": 0, "edge_count": 13}
```

判据是 `IView.GetFaceHatchCount`，直接读、不需要渲染。
所以在你排查期间，任何用本工具出的剖视都会被拦下，不会流到交付。
