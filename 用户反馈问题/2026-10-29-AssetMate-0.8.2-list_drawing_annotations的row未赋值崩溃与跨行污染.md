## 二、核心新问题（建议优先修复）

### 2.1 list_drawing_annotations 的 row 未赋值：崩溃 + 跨行污染（P1）

**现象 A（崩溃）**：对含孔标注的 `实验_005.SLDDRW` 调用即报

```
{"error": "annotations_failed", "message": "cannot access local variable 'row' where it is not associated with a value"}
```

**现象 B（静默跨行污染）**：对 `produce_铰链1.SLDDRW`（不崩溃）的返回中，callout 前一条注解被塞进了多余的 text 字段：

```json
{"kind": "dimension", "name": "D4", "value_mm": 10.0, "text": null},   ← 被污染（D4 本无 text 字段）
{"kind": "radius_callout", "name": "RD1", "text": null},               ← RD1~RD3 也全是 null
{"kind": "radius_callout", "name": "RD4"}                              ← 最后一个 callout 无 text 字段
```

**根因**（`tools/drawing.py` `list_drawing_annotations`，约 2431–2444 行）：

```python
if kind == "hole_callout" and name:
    ...  # 分类出 radius_callout / hole_callout_unverified 等
    row["text"] = callout_text or None      # ① 先写 row —— 此时 row 还是上一轮的 dict（或未绑定）
    ...
if name and key in seen:
    continue
row = {"kind": kind, "name": name, "scope": scope}   # ② 后创建 row
```

- **崩溃路径**：遍历到的第一个 callout 类注解若发生在任何完整迭代之前（如 实验_005 中视图 1 的 RD1 是最先被扫描的注解），`row` 尚未绑定 → UnboundLocalError；
- **污染路径**：非首位的 callout 处理时，`row["text"]` 写进的是**上一轮已 append 到结果列表的 dict**（所以 D4 被塞了 text:null），随后 `row = {...}` 新建 dict，callout 自己的 text 反而丢失（下一个 callout 再来时才被补上）。RD4 作为最后一个 callout 没有 text 字段，与该顺序完全吻合。

这是 0.8.2 重构孔标注分类（IDisplayDimension.GetText 那段很好的改进）时引入的回归。**修复**：把 `row["text"] = ...` 移到 `row = {...}` 之后（或先存局部变量，row 创建后统一赋值），崩溃与污染一并消除。建议补一张「首注解即 callout」的测试图纳入回归。

### 2.2 material_library 列出的材料 set_part_material 应用失败，且顶层状态自相矛盾（P2）

**现象**：同一库 `自定义材料.sldmat`、同一零件 KSHE-016.017：

- `material_library` 列出材料 **"45"**（XML 中是标准叶片节点 `<material name="45" description="GB/T 699 优质碳素结构钢">`，非文件夹）；
- `set_part_material(material_name="45")` → `applied: true, changed: []`，嵌套结果 `ok: false, material_after: "Steel"`，hint 称材料不存在；
- 换 **"自定义塑料"** 同零件 apply → `ok: true`，材质写入并读回一致。

即：清单工具说有、写入工具说无，且顶层 `applied: true` 与 `changed: []` 互相矛盾（apply 失败应体现在顶层）。dry-run 阶段 `would_change: true` 也未能预警。

**建议**：排查 "45" 的应用路径（疑与分类节点 "钢" 下同名解析或与其他已加载库的重名有关）；apply 结果汇总时把嵌套失败上抛到顶层状态；可在 apply 前先做一次与 material_library 的一致性校验。

### 2.3 sheet_metal_qc 读不到板厚，与 build_feature_ledger 结果矛盾（P3）

`sheet_metal_qc` 报 `thickness_mm: null, "no Thickness parameter found in the feature tree"`，但同一模型的 `build_feature_ledger` 明确读到了驱动尺寸 `厚度@钣金1 = 3.0mm`（图纸里它也被 auto_dimension 标成了"厚度"尺寸）。建议 sheet_metal_qc 的板厚读取复用 ledger 的厚度尺寸路径。
