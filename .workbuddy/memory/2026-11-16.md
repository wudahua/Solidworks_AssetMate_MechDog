## v0.8.347 — `dimension_coverage` 零校验（伪造数字 + 抛异常）

- 反馈 P0：`dict | None` 只关掉顶层；`{"foo":1}` 印出「计划 None 条…覆盖 0%（ok:true）」，
  `{"missing":["总长"]}` / `{"coverage_ratio":"75%"}` 直接抛异常（无回执、无 `call_status`）。
- 修法：纯函数 `normalise_dimension_coverage` → `absent/ rejected_invalid / accepted`；
  `render_manifest` 只有 accepted 才印数字；`export_delivery_report` **COM 之前**校验，
  非法返 `error("invalid_dimension_coverage")` + `call_status:failed` + 逐条原因 + session 字段空值。
  回执新增 `dimension_coverage_status`。`coverage_ratio` 限 0–1（传 75 会拒并说明）。
- `server.py` 用 pydantic `DimensionCoverage` 让 schema 带 properties，但签名写
  `DimensionCoverage | dict | None`：只用模型时类型错会在工具执行前被 pydantic 拒 → ToolError 无回执。
  **模型是提示，校验器是权威。**
- P1：清单暴露 `close_opened` 并转发；「有一个已打开就一个都不关」写进两个 MCP description；
  `_paths_to_close` 改 4 元组，回执加 `documents_not_closed_newly_opened`。
- P2：`documents_closed` / `documents_left_open` 统一为完整路径（标题另放 `documents_closed_titles`）；
  错误路径 session 字段由 `null` 改 `[]`/`not_started`；stdio 新增 `dimension_coverage schema is typed` +
  `close_opened is reachable on both tools`（9/9）。
- 断言 334（+1 行为：合法/非法/崩溃形状/COM 前拒绝）。真机清单 PASS 40.7s（7497 B）。
