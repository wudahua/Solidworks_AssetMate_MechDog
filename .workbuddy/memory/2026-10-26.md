## v0.1.3 rename auto 模式（commit 8fab0c2）

- 装配打开时会锁住组件文件，`os.rename` 报 WinError 32；关装配再改名会导致断链，两者都不可行。
- 可用路径：`part.SaveAsSilent(new_path, False)`（静默另存，返回 0 但文件已生成）→ `comp.ReplaceReference(new_path)`（返回 1，逐个实例）→ `doc.SaveSilent`。
- `SaveAsSilent` 会顺带更新已打开装配的引用；多实例仍需逐个 ReplaceReference。
- 副作用：实例名跟随新文件名（`P02_new-1` → `AUT_P02_new-1`），这是目前唯一能"改实例名"的间接手段。
- 实测：P02 两个实例改为 AUT_ 前缀，保存后关闭重开，路径与实例名均正确；原文件保留可回退。
- 顺带修复 `sw_session.open_document`：重新打开文档后清空组件缓存，避免返回陈旧组件指针。
- 未采用 `Extension.RenameDocument`（返回 2、文件不变，非 PDM 环境无效）。

## v0.5 / v0.6：孔标注与形位公差双双突破（2026-10-28 16:20，tag v0.6.0）

- **孔标注可用**（0.5.0）：`AddHoleCallout2` 在 SW2026 **不弹窗**（官方 2001 Remarks 过时），
  走「视图可见边 `GetVisibleComponents`+`GetVisibleEntities2(comp,1)` → `Select2` → 调用」，
  单视图 13 条边 12 秒（此前全模型扫边 >400 s）。成功判定必须用 **`IsHoleCallout`**
  （孔标注是 DisplayDimension，GetType=4，没有独立注解类型）。仅朝向观察者的孔边可标，
  背面（z≠0）返回 null。
- **形位公差可创建**（0.6.0，最重要的发现）：根因是 **pywin32 把 `InsertGtol` 当属性派发**
  （`DISPATCH_PROPERTYGET`）→ 必然 `DISP_E_MEMBERNOTFOUND`。
  解法：`ole.Invoke(dispid, 0, pythoncom.DISPATCH_METHOD, True)` 拿到 Gtol 对象，
  再 `SetFrameValues2` + `GetAnnotation.SetPosition`。实测两个框格回读正确。
  **遗留**：框格内的符号（平面度/位置度）用 `<MOD-*-PAR>` 格式码无效，仍为空。
- **新增工具**：`check_capabilities`（38 工具中）、`plan_drawing`、`add_geometric_tolerance`。
- **能力边界**：blocked 从 4 项降到 2 项（dxf_import / geometry_creation），
  pilot = 孔标注 / 批量孔标注 / 形位公差。
- **方法论（血的教训）**：`DISP_E_MEMBERNOTFOUND` 有三种来源——①属性/方法派发方式错
  ②接口指针不对 ③真的没实现。只测 ① 的一种写法就断言 ③，把自己堵了两天。
  断言「API 不存在」前必须排除三种来源（GetIDsOfNames / _FlagAsMethod 或手动 DISPATCH_METHOD /
  QueryInterface / 选中前置）。
- **纪律**：装配测试必须原路径或整目录复制（单拷 .SLDASM 导致引用断、视图空白，曾误判为 bug）。
