- 测试约定（2026-10-31）：`python tests/check_all.py` 离线回归（136 条断言）+ `python tests/smoke.py` 真机（32 项，裸跑约 18 分钟，须后台跑避免 10 分钟被杀）；smoke 里每个 `模块.函数(...)` 调用由 `regressions.py` 断言绑定到 tools 层真实签名，改签名必须同步改 smoke；改完必须跑一次真实调用再发布。
- 出图几何口径（2026-10-31，P2-13）：`IView.GetOutline` 宽高各恒定虚胖 `OUTLINE_MARGIN_M = 0.0119`（11.9 mm，与视图/比例无关，实测 4 视图 1:1 与 2:1）。所有 overlap / 出界 / 打包判断一律用 `drawing.precise_outline`（常数内缩，O(1) 零 COM）；`ink_outline()` 逐可见边顶点重算在 25 特征零件上约 200 s，只做一次性交叉校验，**绝不**放进 audit 或 `_place_views` 循环。`ink_outline` 必须用 `paper = view.Position + (model - centre) * scale` 投影成图纸米，不能返回模型坐标。
- 出图标注口径（2026-10-31，0.8.19）：尺寸身份是 `IDimension.FullName`，不是 `IAnnotation.GetName` 的 `细节项目N`（同一驱动尺寸跨视图插入会得到不同标签）；`eliminate_duplicates` 靠 SW 自带标志无效，必须按 full name 分组删除副本且只动本次插入的标注（插入前 `before_names` 快照），绝不碰用户已有尺寸。`IDisplayDimension.GetAnnotation` 必须 `call_method` 按方法调用才能读 `GetPosition`（属性派发拿不到）；`IAnnotation.GetType == 4` 才是尺寸，note/GTOL/粗糙度是别的类型（单尺寸移动先查类型）；`EditRebuild3` 是方法不是属性，插入后必须真调用才能让 `view.GetAnnotations` 刷新。
- 局部视图 / 形位公差 / 粗糙度口径（2026-10-31，0.8.20）：`add_detail_view` 的 `scale` 是**请求比例**，不能被 `target.ScaleDecimal`（父视图比例）覆盖——父比例只用于边界圈草图坐标换算；判空用 `GetVisibleComponents` + `GetVisibleEntities2(comp, 1)` 数可见边，`edge_count == 0` 才是真空视图；比例被锁必须返回 `detail_scale_locked` 错误而不是静默 `ok:true`。`<MOD-*-PAR>` 在 `SetFrameSymbols2` 里**不会**解析成 GD&T 几何符号，只当字面文本，所以符号格改写中文文字（如「位置度」），并用 `GetFrameSymbols2(1)` 回读校验，不等就删框返回 `gtol_symbol_not_applied`（`SetFrameSymbols2` 返回 None，只能靠回读判成败）。`InsertSurfaceFinishSymbol3` 会**忽略传入 x/y**，符号实际落在图纸原点，必须 `IAnnotation.SetPosition` 修正并回读 `position_actual_m`；PDF 像素自检要把图纸左下原点映射到 PNG 左上：`px = x/sheet_w*W`、`py = (1-y/sheet_h)*H`，±50 px 窗口 `ImageChops.difference` 变化像素 ≥20 判可见；DWG 是矢量无像素通道，只做文件非空检查。
- 剖切面口径（2026-10-31，0.8.21，P1-4）：模型坐标→视图坐标**没有可用 API**——`IView.GetViewPlaneNormal` 不存在（属性 `AttributeError` / 方法 `DISP_E_UNKNOWNNAME`）、`IView.ModelToViewTransform` 的 16 个 double 不是行主序 4x4、`IMathPoint.MultiplyTransform` 报 `MEMBERNOTFOUND`。改用「视图 deflated outline（减 11.9mm）宽高 vs 零件包围盒三轴 extent 两两组合」尺寸匹配，唯一且误差 ≤5% 才算成功；误差相同（正立方体）返回 `axes_ambiguous` **拒绝而不是猜**。`IView.GetVisibleEntities2(comp,1)` 返回的是**轮廓边**（`GetStartVertex` 为 None、只有 `GetCurve`），所以 `ink_outline()` 永远拿不到顶点，不可依赖它出数。`GetReferencedModelName` 可取模型路径，但 `open_document` 读 `GetPartBox` 会切 ActiveDoc，之后必须重新 `_open_drawing` + `ActivateView` 才能碰草图。`offset_m = (origin[dominant] - centre[dominant]) * scale`，`orientation != vertical` 时内部仍取反。sanity 是几何事实而非启发式：垂直于图纸水平轴的剖切**不可能**改变宽度，故剖视宽必须等于源视图宽（竖切比高），容差 `SECTION_KEEP_TOLERANCE = 0.10`；实测正确 58.98/58.98 = 1.000、切错 14.40/58.98 = 0.244；`depth>0` 部分剖尺寸本就缩小，记 `checked=false` 不判定。
- 桥接自愈与 outline 口径（2026-10-31，0.8.22，P0-1 / P2-13）：`get_sw()` 缓存 dispatcher 后必须用 `RevisionNumber` 探活（实测 17.97 ms/call），节流 `LIVENESS_PROBE_INTERVAL_S = 2.0` 秒，失败立即 `_SW = None` 重连；`pythoncom.CoRegisterMessageFilter` **本机不存在**，所以忙时重试只能手工分类——`RPC_E_CALL_REJECTED`(-2147418111) 等退避重试 ≤2 次，`CO_E_OBJNOTCONNECTED`(-2147220995) 等**不重试**而是丢缓存抛 `BridgeLost`，`DISP_E_MEMBERNOTFOUND`(-2147342077) 两者都不属；**不做线程级硬超时**（pywin32 在 STA 线程派发，跨线程放弃会破坏公寓）。`_LAST_CALL` 必须有模块级默认值，否则首失败时 `log_failure` 自己抛 `NameError`。outline 只有 `precise_outline()`（常数内缩 11.9 mm）一条真源：`ink_outline` 已删，因为四条取点路全断（`GetVisibleEntities2` 返回轮廓边、`IBody2.GetVertices` 对全圆边实体返 None、`IEdge.GetStartVertex` 返 None、`ICurve` 无 `GetEndPoint`/`GetTessPoints`）；`ISheet`/`GetFirstView.GetOutline` 是精确的（420×297 实测），像素映射不用改。`_projection_axes` 与 `_view_at_point` 必须用 precise（否则 11.9 mm 偏移扭曲宽高比与命中判定）。
- 裸名字与静默失败口径（2026-10-31，0.8.25）：`drawing.py` 曾有 5 处 `_call_method(...)` 但模块级从未定义（只有别名 `_call_method_sf`）→ 每次删除抛 `NameError` 被 `except` 吞掉，`duplicates_removed` 从 0.8.19 到 0.8.24 恒为 0，看起来像「本来就没有重复」。两道防线都漏：`static_check` 只校验 `module.attribute`、不查裸名字；回归断言只写 `isinstance(removed, int)` 而 `isinstance(0, int)` 也 True。现在 `regressions.py` 有通用断言 `assert_no_undefined_bare_calls`（遍历 21 模块检查每个 `ast.Call` 的裸名可解析），smoke 的判据改成「removed==0 且 failed>0 即失败」。**通用规则：任何被 `except` 吞掉的分支，都要有「结果不可能为 0」的断言——失败与空操作必须可区分。** 另：`auto_dimension` 补 `dedupe_failed_count`（原 `dedupe_failed` 截断到 10 条，无法区分「删 0 失败 23」与干净空操作）。
- 圆边与版面口径（2026-10-31，0.8.24）：视图可见实体是**轮廓边**，`GetStartVertex` 恒 None，所以一切靠顶点的枚举（`list_circular_edges` 的弦长预筛、`ink_outline`）在该类几何上必空——圆边只能用 `ICurve.CircleParams`（圆心/轴/半径一次给全），坐标再用 `_view_axis_map` 投影，映射不可用时给 `x: null` 不编坐标（实测 0 → 23 条）。`AddHoleCallout2` 的 null 与选择方式无关：`SelectByID2 EDGE`、`edge.Select2`、相邻面 `face.Select2` 三种都选中了仍为 null，而钣金拉伸孔可标 → 判据是几何类型，故返回 `verdict: no_native_callout` 而不是让调用方反复调 offset。`IAnnotation.GetType` 是**属性**，`int(GetType())` 必抛 TypeError，被 `except: pass` 吞掉会让类型过滤**从未生效**（`layout_dimensions` 因此把 note 当尺寸搬动）；判断标注类型必须属性优先/方法回退，尺寸是 4、note 是 6。`layout_dimensions` 把 note 当 fixed 障碍塞进 placed，撞上时尺寸向下让。`add_note(avoid_collisions=True)` 用「行数×字高×1.6」估高、「最长行×字高×0.75」估宽，障碍用 `precise_outline`。orphan 尺寸只能用 `prune_orphan_dimensions`（name+position）清，`delete_dimensions` 按值删分不清三个 23 mm。
- 标注删除与尺寸文本口径（2026-10-31，0.8.23，P0/P1-1/P3-3）：`delete_annotation` 的成功判定**必须跨全部视图求和**（`doc.GetFirstView` 是图纸，删尺寸时其 `GetAnnotations` 计数不变：实测图纸恒 83、工程图视图1 8→7、总数 122→121），只看图纸会把成功报成 `delete_failed`；`IAnnotation.Select(False)` 对尺寸有效、`EditDelete` 确实生效。四类（note/GTOL/SFSYMBOL/DIMENSION）实测均可删；v0.8.14 的"四类全失效"根因是 `_find_annotation_by_name` 里写了未导入的 `call_method` → NameError 被 except 吞成"没有候选"。SolidWorks 按草图复用 `D1/D2/D3`（一图实测 19 个 `D1`），故 `delete_annotation`/`move_annotation` 接受 `position_m` 精确指定。**尺寸的显示文本在 `GetText(1)`**：`GetText()` 无槽号对尺寸返回空串，`GetText(1)` 才是 `<MOD-DIAM>`；`IDisplayDimension.GetType` 属性 5 = 直径、2 = 线性。`delivery_check` 判直径必须用 `dimension_type`，用文本会恒为 0。`reconcile_ledger` 的 0.0 是草图约束值不是长度，从覆盖率分母剔除。

- 回执文本与投影口径（2026-11-10，0.8.293）：孔标注 `text` **只能是一条原生文字**，多槽内容放 `text_lines` 数组，绝不拼 `" | "` 合成串（`list_drawing_annotations` 的 `text_is_format_code`/`text_decoded` 按单串解析）；`native_text_complete` 恒 `null`（固定枚举 6 槽无法证明读全），完备性用 `text_completeness:"unknown"`。`<hw-*>` 是 Hole Wizard 无值占位符、图面不显示，只剥这一类、原始留 `text_slots_raw`；`<MOD-DIAM>` 是**会渲染成 Ø 的格式码必须保留**，全删尖括号会重现 `Ø1515`。**改字段语义必须枚举所有以它为判据的消费者**：单数 `add_hole_callout` 的深度门必须判 `" ".join(text_lines)`，因为实测 `<HOLE-DEPTH>68` 在第二槽，只看 `text` 会让 0.8.291 的 `Ø16 ↧68` P0 重新 `ok:true`。`sheet_projected` 的新语义是「存在两个不同端点的投影边、可按 `edge_index` 选边」，不是「圆心被投影过」；全圆侧视图必须 `false` + `circular_model_edges_only`，圆心坐标保留并用 `sheet_coordinates_present` 说明；无顶点轮廓边 `edge_kind` 诚实给 `unknown`，不编 `arc`。`bump_version.py --check` 无 `.git` 必须 fail-closed 返 1 + `UNVERIFIABLE`，且**否定文案也不能含 "safe to tag" 字面量**（审计按短语 grep 会误判）。
- 同轴合并与判据复用口径（2026-11-10，0.8.294）：**一个阈值不能兼做两件事**——chamfer 过滤器用 `CHAMFER_RADIUS_GAP_M=0.0015` 判「可能是倒角」并显式发布 `_chamfer_pair_keys`；coaxial 合并由纯函数 `_coaxial_merge_plan(axis_keys, chamfer_pair_keys)` 只按成员身份排除、**代码里零半径比较**（Ø11 沉孔配 Ø9.8 通孔径向差 0.6 mm 也必须合并，旧 `>0.0015` gate 会产生两条相同 callout）。等半径是不同孔位永不 drop；回执 `coaxial_chamfer_protected` 让「保护生效 / 没触发」可区分。3D 中心差 ≤1.5 mm 的极浅沉孔与 45° 倒角几何不可分，保守走 `ambiguous_chamfer_pairs`+`ok:false` 人工路径，不冒险把真实孔 Ø16 折进 Ø18 倒角口删掉。**通用规则：改判据时必须同步枚举所有以旧判据为守卫的回归断言**，否则旧断言会反向锁死修复（本轮 `0.8.278` 断言曾要求旧字面量必须存在，0.8.293 的 `text` 语义漂移同类）；新回归断言用 AST 剥掉 docstring 再检查代码，避免把「解释旧实现为何废弃」的注释误判为回归。
- 全量 smoke 与 partial 判据（2026-11-11，0.8.295）：`python tests/smoke.py` 全量 53m19s / 56 项。`produce_drawing` 的 partial 结果是 `ok:false` + `error/message=null` + `partial_steps`，**任何调它的 check 都必须 `require(..., allow_partial=True)` 且不留裸 `assert payload.get("ok")`**，否则报出误导性的 `call failed: None None`（全量唯一 FAIL 即此，非产品回归）。partial 图纸仍须过 `views` / `drawing_audit` 断言，不能跳过。另：Windows 会话里后台任务会走沙箱并拦截 shell shim（exit 125），长任务用「前台 Bash + 豁免 + timeout=600000 → 自动转后台」，前台超时不会发 SIGTERM。
- 默认值与剖切口径（2026-11-11，0.8.296）：**同名参数的默认值分散在两层时，必须断言两层一致**——`auto_nudge_zero_offset` 内层 `drawing.add_section_view` 早已 `False`，MCP 外壳 `server.add_section_view` 仍 `True`，导致每次 `offset_m=0` 被改写成 `0.001 m`（1:2 = 0.5 mm 模型偏心），而回执 hint 已写「默认已改为 False」。偏心剖直径错但视图仍 `ok:true`+`hatch:2`，只有直径错 → 极难发现。现两层均 `False`，显式 `True` 给 `offset_nudged:true` + 顶层 `warning`；`zero offset is not nudged by default` 用 `inspect.signature` 同时断言两层，回归断言用 AST 读两处默认值。
- 回执字段与快照时刻口径（2026-11-11，0.8.297）：**一份回执里的字段必须来自同一时刻的快照**——`add_section_view` 曾在打断对齐**前**算 `alignment_kept`/`position_axis_ignored`、在**后**重读 `position_actual_m`，于是「忽略 x」会配两个完全相同的坐标。现抽纯函数 `_position_deviation(requested, actual, tol=1e-3)`，打断前只留 `alignment_rewrote_request` 快照，所有位置字段在打断后重算，并用 `position_fulfilled` 与 `alignment_kept` 互为否定做自检。公差读回会给 **-0.0**，`%+g` 打 `-0` 而图面是 `0`（GB `Ø30 +0.033/0`）→ 统一走 `_signed_mm`（`|v|<5e-7`→`"0"`）。`add_center_marks` 新增 `dedupe_existing`（默认 False，会删标注），纯函数 `_coincident_mark_groups(rows, tol=1e-4)` **三轴**都判（只比 X/Y 会把纯 Z 差异误判），且**先清理再统计** `already_marked`。`delivery_check` 的 0 驱动尺寸 = `status:"not_applicable"` 而不是覆盖率失败（导入件永远修不了它）。另：**按字符窗口（`src[i:i+1200]`）定位源码的断言会被无关新增文本打破**，一律改 AST 取函数体。
- 交付判定字段分工（2026-11-11，0.8.298）：`produce_drawing` 的 `ok` 是完整性门（某步 partial 即 false），`completeness`（`complete`/`incomplete`）+ `execution_ok` + `incomplete_reasons`（`kind: blocker|partial_step`）与 `add_hole_callouts` 同名同义；**`verdict` 是给人看的中文交付标签，不是机器信号，绝不为编码 partial 而加档**（一个事实两个判据是项目已修 5 次的错误）；**`blockers` 只放「调用方能在本工具集内修的硬缺陷」**，能力缺口塞进去会制造永久红灯（与 0/0 永久 pending 同型）。推导用纯函数 `_delivery_status(blockers, partial_steps, failed_steps=())`；列表类数据在 return 前只算一次，避免两份漂移。
- 顶层 `ok` 与 completeness 同源口径（2026-11-11，0.8.299，P0）：**0.8.298 自己造了「一个事实两个判官」**——`ok=(not _partial_steps)` 只看 partial，而 `completeness` 还看 blockers → 有 blocker 无 partial 时 `ok:true + completeness:"incomplete"`，把交付判定丢失的图纸报成功。三条真机路径：A `delivery_check` 返回 error dict、B `do_hole_callouts=False` + 真实 blocker、C 任何非 `_CRITICAL` 步骤 `status="failed"`（C 更糟：`"complete"`）。现顶层 `ok` 由纯函数 `_receipt_ok(status)` = `completeness == "complete"` 派生，**不许有第二个公式**；`_delivery_status` 增加 `kind:"failed_step"` 与 `failed_steps` 回执字段。**通用规则：新增一个判据维度时，必须回头检查所有基于旧判据的字段；守护断言必须把两个相关字段放进同一条断言**——分开断言时两边各自「正确」，组合却是错的（本轮 287 断言 + 61 check 全绿仍漏检）。
- 完整性判据的白名单口径（2026-11-11，0.8.300）：**「这一步失败了」与「图纸能不能交付」是两个问题**——`close_documents` 的 ok 只表示「至少关掉一个文档」，把它喂给 `completeness` 会让已保存、审计通过、`delivery_check ok` 的完整图纸变成 `ok:false`（0.8.299 的 over-correction）。现由 `_COMPLETENESS_RELEVANT` **白名单**（`create_drawing`/`dimensions`/`center_marks`/`surface_finish`/`hole_callouts`/`save`）决定，纯函数 `_step_partition(steps, verdict_ok)` 分流；清理/只读/版面步骤进 `cleanup_incomplete` + `warnings`，可观测但不污染 `completeness`。`delivery_check` 在 verdict 已丢失时**只算 blocker**，不许 blocker + failed_step 双计。`critical_step_failed` 带 `execution_ok:true`（跑完了但图纸不可用），字段缺失才表示没跑到出回执。**过滤条件一律用白名单**——黑名单永远落后于下一次新增的步骤。
