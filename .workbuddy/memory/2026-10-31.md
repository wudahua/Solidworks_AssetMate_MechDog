## v0.8.21：P1-4 剖切算法收尾（版本只 +0.0.1）

用户「好，做 P1-4」。起点 v0.8.20 已发布，v0.8.6 反馈 15 项只剩 P0-1 / P1-4 / P2-13
三项部分解决，其中 P1-4 是唯一还影响「图对不对」的实质缺口。

### 探测：模型坐标 → 视图坐标，三条 API 路全堵死

- `IView.GetViewPlaneNormal`：属性 `AttributeError`，按方法调用 `DISP_E_UNKNOWNNAME`
  （未知名称）——该版本根本没有这个 API。
- `IView.ModelToViewTransform`：**存在**，返回 16 个 double，但**不是行主序 4×4**：
  平移量与一个孤立 `-1` 对不上，按任何常见分组都凑不出正交矩阵。
- `IMathPoint.MultiplyTransform`：`DISP_E_MEMBERNOTFOUND`，没法让 SW 自己算。
- **额外发现**：`IView.GetVisibleEntities2(comp, 1)` 返回的是**轮廓边（silhouette edge）**，
  `GetStartVertex` 返回 `None`、只有 `GetCurve` 有值（3 个视图各 10/14/11 个实体，取顶点
  全军覆没）。这意味着 `ink_outline()` 里的 `edge.GetStartVertex.GetPoint` **永远拿不到顶点**，
  它只会返回 `None`——此前一直把它当"慢速但有效的交叉校验"，实际从未生效。

### 修改

- **`_view_axis_map(view)`**（新）：`GetReferencedModelName` 取模型路径 →
  `open_document` + `GetPartBox(True)` 取包围盒 → 用视图 **deflated outline**（减 11.9 mm）
  的宽高与三轴 extent 的**两两组合**做尺寸匹配，唯一且误差 ≤ `max(w,h)×5%` 才算成功；
  误差相同（正立方体）返回 `axes_ambiguous` **拒绝而不是猜**。读 part box 会切换 ActiveDoc，
  所以调用方之后必须重新 `_open_drawing` + `ActivateView` 才能碰草图。
- **`_section_sanity(...)`**（新）：几何事实判据，不是启发式——剖切平面垂直于图纸
  **水平轴**时不可能改变宽度，所以剖视宽必须等于源视图宽（竖切比高）。
  `SECTION_KEEP_TOLERANCE = 0.10`；`depth > 0` 部分剖尺寸本就缩小，记 `checked=false` 并写明原因。
- **`add_section_view`** 新增 `cut_plane_normal` / `cut_plane_origin`（模型米，必须成对，
  覆盖 orientation + offset_m）与 `verify_cut=True`。拒绝 token：`cut_plane_incomplete`、
  `cut_plane_oblique`（主分量 < 0.9）、`cut_plane_not_in_view_plane`（法向平行视线）、
  `cut_plane_unmapped`（带 `mapping_reason`）。成功返回 `cut_plane`
  （`dominant_axis` / `derived_orientation` / `derived_offset_m` / `mapping.axes`）+
  `edge_count` + `sanity` + `precise_outline_m`。`edge_count == 0` → `section_empty`；
  sanity suspicious → `section_suspicious`；**两者都保留视图供检查**，不删。
  `offset_m = (origin[dominant] - centre[dominant]) * scale`，`orientation != vertical` 时
  内部仍取反（保留 0.8.10 的符号修正）。
- `server.add_section_view` wrapper 同步三参数并转发（含 docstring 说明）。

### 补丁之外，我自己又发现两处

1. **`dedupe_failed` 只截断到 10 条、没有计数** —— "删 0 失败 23"与"干净的空操作"
   在返回值上无法区分，正是这个 P0 能藏五个版本的第二个原因。补 `dedupe_failed_count`。
2. **我的 smoke 断言写成了 `isinstance(duplicates_removed, int)`** —— `isinstance(0, int)`
   也 True，所以五年没抓到。改成「`removed == 0` 且 `failed_count > 0` 即失败」。

### 新增通用防线：`assert_no_undefined_bare_calls`

`static_check` 只校验 `module.attribute`、不管裸函数名，所以 `_call_method(...)` 这类
"引用但从未定义"的名字完全在防线之外。新断言遍历 `src/` **21 个模块**，收集每个
`ast.Call` 的裸名，要求能解析到内置 / import / 定义 / 参数 / 赋值 / `global`。
这是整类 bug 的通用防线，不再依赖"记得给某个函数加断言"。

**通用规则（写进 com-quirks 第二十一节）**：任何被 `except` 吞掉的分支，都要有一个
「结果不可能为 0」的断言——失败的删除和没有可删对象必须可区分。
