处理三份 2026-11-10 验收反馈，三项都是「看起来修了其实没修」：

1. **`list_tool_profiles` 硬编码计数**：`profiles.full` 从写死 `all 70` 的说明文字改成运行时

   已改局部导入 + 源码级断言。**通用教训：有个 check ≠ check 跑过；计数式横幅要能区分。**

2. **偏心剖切静默通过**：`section_off_axis` 原只比 `kept_dimension`，而回转体偏心弦剖缩短的
   恰是被丢弃那一维（horizontal 剖偏心改高度）。`ratio 1.000` 与 `127.98→127.73` 同框仍
   `ok:true`。现在两轴都进回执，非 kept 维用**绝对 0.1 mm**（0.25/127.98=0.195%，比例门必放行）；
   判定抽成纯函数 `_section_off_axis_from_sanity(sanity)`，smoke 用实测数字回放。
   附 `eccentricity_mm`（仅诊断，不作判据）、nudge 顶层 warning、弦长 63.5→63.875 更正。

3. **主孔 `Ø16 ↧68` 与 `ok:true` 双重放行**（核心）：
   **根因是读法** —— 单数 `add_hole_callout` 用 `callout.GetDimension2(0).GetText(slot)` 全空，
   复数 `add_hole_callouts` 用 `win.Dispatch(display).GetText(slot)` 能读到
   `<MOD-DIAM> | <HOLE-DEPTH>68`。文字一直可读，旧结论「SolidWorks 不返回文字」是错的。
   现在 `_hole_callout_verification()` 纯函数门控 `ok`；未验证时用
   `GetAnnotation`/`Select(False)`/`EditDelete`/`EditRebuild3` **撤销刚创建的标注**，
   回执 `ok:false/created:false/verified:false/drawing_safe:false/callout_revert`。
   `model_match` 增 `through_state:"unknown"`（ledger 只有圆柱面清单，判不出贯通）、
   `depth_text_consistent:null`、`ok_means`；带 `model_path` 时 `ok:true` 直径匹配也不再放行。
   复数工具补 `execution_ok` / `completeness`。

顺带：`capabilities` 的 `section_view.why` 旧结论标为历史存档、`advice` 不再对 partial 说
「全部可做」；`hole_callout_text_slots.workaround` 撤回已证伪的 `add_drawing_dimension` 推荐；
`line_style` schema 补数字码（轴线 `"4"`、实线 `"7"`）+ 回执 `line_style_warning`，
撤回过时「图纸草图不渲染」hint。

## 关键 COM / 口径（有长期价值）

- `AddHoleCallout2` 的返回值必须 `win32com.client.Dispatch(display)` 再 `GetText(slot)`；
  `GetDimension2(0)` 读不到任何槽。复数工具早就是对的，单数工具抄错了对象。
- 删除刚创建的标注：`Dispatch(dim)` → `_call_method(dim, "GetAnnotation")` →
  `ann.Select(False)` → `_call_method(doc, "EditDelete")` → `EditRebuild3`（否则计数不刷新）。
  与复数工具 `_discard` 同一条已验证路径。
- `build_feature_ledger` 的 `holes` 只有 `diameter_mm/axis/centre_mm/feature`，
  **没有贯通/盲孔标志**，所以 `through_state` 只能 `unknown`，不许猜。
- `SECTION_OFF_AXIS_TOLERANCE_MM = 0.1` 必须是绝对值：偏心误差按比例算只有 0.195%。
- 顶层 `ok:false` 的两种含义要在不同字段表达：`execution_ok`（调用跑了）与 `completeness`（图纸完整吗）。

## 关键结论（长期）

- **契约声明 ≠ 运行时守卫**。mcp 1.30.0 下，只 seal 不装 `_install_argument_guard` 时
  `ping({"bogus_param":123})` 仍 `ok:true`（pydantic `extra="ignore"` 丢键）；反过来客户端
  也可能在发送前按 schema 本地过滤，服务端守卫看不到原始 arguments。两者都不能互相替代。
- `FastMCP.list_tools()` 用 `inputSchema=info.parameters`，所以改 `Tool.parameters` 是最小注入点。
- 只改顶层：Pydantic 对 dict 参数生成嵌套 `additionalProperties:true`（当前 2 处
  `palette`；数量随 SDK/工具集变，**不要写死数字**）。
- 注释里最初写了「four nested」，实测只有 2 处，已改成不写数字——刚因硬编码 70 被点名，
  同类错不能立刻再犯。
