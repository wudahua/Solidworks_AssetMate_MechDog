# 2026-11-12

## v0.8.301 发布：`502` 是「假失败」，重试前先 `git fetch`

`git push` 报 `CONNECT tunnel failed, response 502`，`gh release create` 报
`Post "https://api.github.com/graphql": Bad Gateway`。下一轮重试得到：

```text
! [remote rejected] main -> main (cannot lock ref 'refs/heads/main':
  is at 19df76b8ed5fa40e20e4095b88f9a46ed903343f but expected 22bc7df0f2e051...)
```

**服务端其实已经收到上一轮的 push**，只是客户端没拿到响应。本地 remote-tracking
还停在旧值，所以 `git push` 认为要 fast-forward，服务端看到「已在目标位置」就拒绝。
`git fetch origin` 之后 `origin/main` 就是 `19df76b`，与本地 HEAD 一致；
tag `v0.8.301` 与 Release 也都成功。

结论：代理 502 之后**先 `git fetch` + `gh api .../commits/main` 核对**，再决定是否重推。
不要把 `remote rejected / cannot lock ref` 当成需要 `--force` 的信号 —— 那条路会把
本地/远端 sha 真正推成分叉。本机代理故障（`127.0.0.1:49707` 对 github.com 的 CONNECT
隧道 502）自 11-11 起已出现 4 次，每次要么原样重试即通，要么「已落盘但客户端报错」。

## v0.8.302 — 正确的过轴全剖不再被判成偏心弦（P0 回归）

0.8.291 的偏心判据把「非 kept 维收缩」当独立拒绝条件 → **圆形源视图竖剖必误杀**：

  `null` 不当作 0）；② kept 维判据不变；③ `source_size_mm` 两维相等（圆/方）时
  **跳过 off_axis 比对**（该维语义已变）。

  `source_kept_mm`/`section_kept_mm` 改中性名 `source_mm`/`section_mm`（原名装的是

## v0.8.303 — 角度尺寸不再被当成毫米（报告 §4 P0）

## v0.8.316 — 对外置的角度尺寸：不移动（D3）

- **成因**：`place_outside` 对线性尺寸正确（文字外移只是引线变长），但**角度尺寸的引线是

  「左下角大圆弧 + 斜引线从框外侵入」就是它。`place_outside` 本来就有安全区约束

  notes 写明「N 条未移动」。一个没被移动的尺寸不可能被移到框外。

  `skipped_angular: []`）。接槽零件才能验证图面效果；本轮只证明代码路径可执行。
