  `blockers` 提到 return 前只算一次（`_blockers`），一份数据喂两处。

## v0.8.299 — `ok` 与 `completeness` 同源（报告 2026-11-11 §5，P0）

**0.8.298 自己造了第六个「一个事实两个判官」**：`ok=(not _partial_steps)` 只看 partial，
而 `completeness` 还看 blockers → `ok:true + execution_ok:true + completeness:"incomplete"`。

- 三条真机可达路径：A `delivery_check` 返回 error dict（v0.8.229 崩溃）、
  B `do_hole_callouts=False` + 真实 blocker、C 任何非 `_CRITICAL` 步骤 `status="failed"`
  （C 更糟：`ok:true` + `"complete"`，无人命名失败）。
- 真机恰好落在 `PARTIAL only`，矛盾被掩盖 → 287 断言 + 61 check 全绿漏检。
- 改法：新纯函数 `_receipt_ok(status)` = `completeness == "complete"`，顶层 `ok`
  不再独立计算；`_delivery_status(..., failed_steps=())` 增加 `kind:"failed_step"`
  堵路径 C；回执新增 `failed_steps`；工具描述写明 `ok` 恒等于 `completeness`。
- 真机复现路径 A：`ok:false` / `execution_ok:true` / `completeness:"incomplete"` /
  `incomplete_reasons` 三条（blocker + partial_step + failed_step）/ `failed_steps:["delivery_check"]`。
- 旧断言 `ok=(not _partial_steps)` 重写为「ok 跟随同一份推导」（保留原意、不锁死旧公式）。
- 教训：**新增一个判据维度时，必须回头检查所有基于旧判据的字段**；守护必须把两个字段
  放进同一条断言 —— 分开断言时两边各自「正确」，组合却是错的。
