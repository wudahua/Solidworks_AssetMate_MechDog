# 断言盘点 · 2026-11-08

报告 6 的 P3 要求：「`regressions.py` 中同类『只测源码字符串』的断言做一次盘点，
标注哪些需要真机补测。」

**这不是一个新发现的缺陷，是给现有 230 条断言分类。**


## 分类结果


| 类别 | 数量 | 含义 |

|---|---|---|

| 调用工具模块 | **2** | 断言执行时真的进了 `tools/`，属于行为检查 |

| docstring 有实测数据、断言只查源码 | **73** | **最可疑的一类**：文档写着「实测 X 得 Y」，断言只验证源码里有某段字符串 |

| 格式/元数据检查 | **155** | 检查文档、签名、重复定义等，源码级是正确的 |

| 合计 | 230 | |


## 为什么 73 条「只查源码」不全是错的


`smoke.py` 有 **44 个用例**，覆盖 70 个工具的**主要路径**。
`smoke covers every tool` 这条断言强制每个工具至少被调用一次。


所以真正的风险不是「没有真机验证」，而是：
**smoke 覆盖不到的那条分支，只有一条源码断言守着它。**


## 已知的「smoke 覆盖不到」分支


| 分支 | 为什么 smoke 进不去 | 现状 |

|---|---|---|

| `sanity.verdict: no_hatch` / `identical_to_source` | 需要回转体（`door`、飞达动力轴都不是）。2026-11-08 已加 `revolved part section verdict` 用例，但零件不在时 skip | **有一条真机用例，夹具缺失时跳过** |

| `skipped: already_marked`（中心符号幂等） | 本机所有夹具 `GetCenterMarkCount == 0`，没有可标注的孔 | **只有源码断言** |

| `prefix_failed`（`SetText` 失败） | 需要有 build 上 `SetText` 不支持 | **只有源码断言** |

| `output_trash_failed` | 需要回收站策略拒绝删除 | **只有源码断言** |

| `duplicate_removed: false` | 需要删除失败 | **只有源码断言** |

| `_diff_computable: false` | 需要快照读取失败 | **只有源码断言** |

## 需要真机补测的清单（按价值排序）


1. **中心符号幂等**（P2-6）—— 缺一个带孔的夹具。任何一个有通孔的零件都行。

2. **公差三种形态的 PDF 识别** —— 已有 `add_dimension_tolerance` 真机用例？
   查 smoke：没有专门用例，`annotation writers` 只验「写进去了」。

3. **多页链路** —— `sheet tools` 用例覆盖了 `add_view_to_sheet`，
   但 `activate_sheet` 读回失败的分支没覆盖。


## 结论


- **155 条源码级断言不是缺陷** —— 元数据检查本来就该这么写

- **73 条「docstring 有实测、断言查源码」是真实的错位**，
  但其中大部分由 smoke 的行为用例兜底

- **已知没有守护的 6 条分支**列在上面。这个清单是「按代码读出来的」，
  **不是「按测试跑出来的」** —— 是否还有别的缺口，本盘点查不出来
