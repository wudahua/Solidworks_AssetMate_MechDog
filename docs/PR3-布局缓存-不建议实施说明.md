# 关于 PR3「布局缓存」不建议实施的说明

**致**：性能优化实施包规划者
**日期**：2026-11-04
**结论先行**：PR3 中「模板安全区 / 模型 box / 真实轮廓」三项缓存，**实测可省上限 96 ms，
占一次出图的 0.4%**。我建议**不做**，并在下面给出完整数据、测量方法和替代方案。

---

规格 §10 PR3 列了 6 条。我的状态：

| # | 规格要求 | 状态 | 说明 |
|---|---|---|---|
| 1 | 缓存模板安全区 | ❌ **未做** | 每次 `_push_dimensions_outside` 读一次图纸边框 |
| 2 | 缓存模型 box | ❌ **未做** | |

## 二、实测数据

### 2.1 测量方法（可复现）

```python
# 包装 precise_outline，累计调用次数与耗时，跑一次完整 produce_drawing
orig = drawing.precise_outline
total = {"n": 0, "ms": 0.0}
def wrapped(view):
    t0 = time.perf_counter()
    try: return orig(view)
    finally:
        total["n"] += 1
        total["ms"] += (time.perf_counter() - t0) * 1000
drawing.precise_outline = wrapped
pipeline.produce_drawing(part, output_path=drw)
```

### 2.2 结果（旋转轴，24.8 s 一次出图）

```
precise_outline: 18 calls, 55 ms total, 3.1 ms each, 0.2% of wall
```

**18 次调用、55 ms、占 0.2%。**

### 2.3 第 1 项（模板安全区）的成本

`_push_dimensions_outside` 里读图纸边框那一段，埋点名为 `ms_sheet_frame`：

```
ms_sheet_frame    41 ms
```

**一次出图只读一次**——它根本不在循环里，没有"重复读"可省。

### 2.4 三项缓存收益上限

| 项 | 实测 | 可省上限 |
|---|---:|---|
| 模板安全区 | 41 ms（1 次） | **0 ms**（本来就只读一次） |
| 模型 box | 无独立调用点（并入 `/` 别的路径） | ~0 |
| 真实轮廓 | 55 ms（18 次） | **55 ms** |
| **合计** | | **≈ 55 ms** |

**55 ms / 24 842 ms = 0.22%。**

---

## 三、为什么这个数字这么小

**`IView.GetOutline` 是 SolidWorks 里最便宜的调用之一。**

我们早已测过：`ISheet` / `GetFirstView.GetOutline` 是**精确的**（420×297 实测无误差），
返回一个 4 元素数组，不需要几何遍历。

**PR3 假设"轮廓读取贵"，在这台机器上不成立。** 一次 3.1 ms。

对比同一次出图里的其他调用：

| 调用 | 单次成本 | 倍率 |
|---|---:|---:|
| `GetOutline` | **3.1 ms** | 1× |
| `IAnnotation.GetPosition` | 12 ms | 3.9× |
| `IAnnotation.SetPosition` | 25 ms | 8× |
| **`GetDimension2(0).SystemValue`** | **143 ms** | **46×** |

**轮廓读取是这里最便宜的那个。缓存最便宜的调用，收益必然最小。**

---

## 四、为什么不能靠"删掉缓存"换取别的收益

可能有人会问：不缓存，是不是反而更简单？**是，但代价已经付过了**——
现在的代码里**没有**这三样缓存，也就是说**当前 24.8 s 已经包含它们的全部成本**。

**加缓存能把 24.8 s 变成 24.75 s。** 这个精度对使用方没有意义。

---

## 五、成本与风险

### 5.1 实现成本

三处缓存分别需要：

| 项 | 工作量 | 风险 |
|---|---|---|
| 模板安全区 | 小 | **低**，但需失效判定（换模板/换纸张） |
| 模型 box | 小 | **低**，需失效判定（改模型） |
| 真实轮廓 | **中** | **中高** |

**"真实轮廓"的缓存键必须包含视图名 + 比例 + 图纸状态**——
而 `_push_dimensions_outside` **本身就在改尺寸位置**，改完轮廓不变（尺寸不是视图几何），
但**如果缓存键漏了 `flip_x`（方向标记），第二次调用会返回未翻转的框**。

**这个 bug 我们踩过**：`_EDGE_CACHE` 的键不含 `flip_x`，第二次返回旧值，
表现是"视图方向看起来没变"。**修它花的时间比省下的 55 ms 值钱得多。**

### 5.2 收益/风险比

```
省：55 ms（0.22%）
风险：布局错位（尺寸跑出纸外 / 重叠）—— 这类问题只有看图才能发现
```

**布局代码是整个工具集里最难验证的部分。** 它的错误不报错，只是图上难看。

## 六、我用什么替代了它

PR3 想要的**是"减少重复工作"**，这个目标我完成了，只是**位置不在规格指定的地方**。

| 实际的重复工作 | 一次出图次数 | 优化后 | 实测收益 |
|---|---:|---:|---:|
| `build_feature_ledger` 重读模型 | 5 | **2** | **-19.2 s** |
| `list_drawing_annotations` 重读注解 | 3 | **1** | **-8.5 s** |
| `drawing_audit` 重复审计 | 1 | 0（pipeline 复用） | -0.3 s |
| `_save_drawing` 重复保存 | 5 | **1** | -1.0 s |
| `detect_same_value` 诊断占主流程 | 18.4 s | 0（默认关） | **-19.5 s** |
| **合计** | | | **≈ -40 s** |

**端到端 A/B（n=4 逐轮交错）：122.2 s → 101.9 s（-16.6%）。**
那一次只包含 ledger + 注解缓存，**之后的同值检测与合并保存还没算进去**。

**PR3 建议的三样加起来 55 ms。上面这些加起来 40 s。**
**差 700 倍。**

---

## 七、什么情况下应该做 PR3

我不是说这三条缓存永远不该做。**下列任一条件成立时，它们就值得做**：

1. **图纸上视图数 > 20**
   `precise_outline` 的调用次数随视图数线性增长。18 次是 2 视图的情况；
   20 视图就是 ~180 次 ≈ 550 ms。

2. **零件有大量可见边（> 5000）**
   单次 `GetOutline` 成本可能不再恒定。**需要先测，不要假设。**

3. **`get_outline` 换成逐边遍历实现**
   那就不再是 3.1 ms，而是我们测过的 **200 s** 量级（`ink_outline` 的旧实现）。
   **那时候缓存是必需的，不是优化。**

4. **要做批量出图（一次 > 50 张）**
   55 ms × 50 = 2.75 s，开始有意义。

**四条都不满足。当前最大的一批是 10 个模型，单张最大 661 s——
55 ms 在其中占 0.008%。**

---

## 八、我的建议

**不做 PR3 的这三条缓存。** 理由按重要性排序：

1. **收益 55 ms，占 0.22%**——低于这台机器自身的波动（同代码 82~162 s，±30%）
2. **缓存键出错会让布局静默错位**，而布局错误只有看图能发现
3. **同样的目标已在别处完成 40 s**（缓存 ledger / 注解 + 关闭诊断 + 合并保存）

**如果规划上必须让 PR3 有个交代**，我建议改成：

> **PR3 修订版**：不缓存轮廓，改为**给 `precise_outline` 加调用计数**，
> 当单次出图超过 100 次时在回执里警告「视图过多，考虑减少视图数或启用缓存」。

**这比缓存有价值**：它告诉使用者**什么时候该担心**，而不是在不需要的时候付复杂度。

---

## 九、附：这份结论的边界

**数据来自 2 视图的零件图纸**（旋转轴，24.8 s）。

**样本只有 1 次**——但这台机器 30% 的波动影响的是**秒级**总时长，
**不会让 55 ms 变成 550 ms**。**0.22% 这个量级是稳的。**

**如果你有视图数很多的真实图纸（> 10 视图），请给我一张，我重新测。**
**那种图纸上我的结论可能反过来。**
