# Solidworks_AssetMate_MechDog 项目规划

> 一个把 SolidWorks 操作暴露给 AI 智能体的小工具集（MCP 服务器），附带一份真实踩坑清单。
> 仓库名与 MCP 注册名固定为 `Solidworks_AssetMate_MechDog`。

## 1. 目标与非目标

**目标**

1. 让智能体能安全地读、改、导出 SolidWorks 装配体与零件，不靠人肉点界面。
2. 每个工具都带「实测过的坑」，降低后来者的试错成本——这是与普通 API 封装的区别。
3. 所有写操作可预演、可回退，COM 失败不产生假结果。

**非目标**

- 不做建模/特征创建（与 solidpilot 等建模类工具重叠，且风险高）
- 不做云端服务、不做跨平台（SolidWorks COM 只在 Windows）
- 不做图形界面；交互由 AI 对话与返回的 JSON 承担
- 不追求「支持所有 SolidWorks 版本」，先保证 2020–2024 主路径可用

## 2. 现状（v0.1.0，2026-10-26）

| 能力 | 状态 | 实测 |
|---|---|---|
| `recolor_assembly` 按零件上色 | 已发布 | 46 组件 / 19 种零件，46 件全部上色并落盘 |
| `get_assembly_tree` 组件树 | 已发布 | 46 组件，支持子装配递归 |
| `get_mass_properties` | 已发布（实验性） | 0.1266 kg，SI 单位 |
| `export_preview` | 已发布 | 1600×1200 BMP，4 s |
| 文档 | 已发布 | `docs/com-quirks.md` + 前后对比图 |
| 分发 | 已发布 | tag `v0.1.0` + Release 附件 |

已知限制：单层外观、无配置/显示状态切换、无撤销命令、缓存需手动 `refresh`、首次操作 2–3 分钟。

## 3. 用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 机械工程师 | 装配体按件分色出图、讲解 | 一次成功、颜色可复现 |
| AI 使用者 | 用自然语言操作 CAD | 返回结构化、错误可读 |
| 二次开发者 | 把 CAD 能力接入自己的 Agent | 安装简单、接口稳定 |
| 逆向工程流程（自有） | 读取组件/配合生成 IR | 拓扑与属性完整、可交叉验证 |

## 4. 路线图

| 版本 | 主题 | 新增工具/能力 | 验收标准 |
|---|---|---|---|
| **v0.2** | 工程师日常批处理 | `export_bom`（层级 BOM + 数量/材料）、`batch_export`（STEP/PDF/DXF）、`rename_components`、`check_interference` | 在 20+ 组件装配上导出结果与 SW 界面一致；改名后引用不断裂；干涉数与界面一致 |
| **v0.3** | 结构与配合读取 | `get_feature_tree`、`get_mates`、`get_component_transforms`、`list_configurations` | 与 `analyze_model` 拓扑比对一致；配合类型/引用件可完整还原 |
| **v0.4** | 安全与可运维 | `snapshot` / `restore_appearance`、操作日志、批量作业队列、超时与重连 | 任意写操作可一键回退；进程被杀后可恢复会话；日志含耗时与错误码 |
| **v1.0** | 稳定接口 | 工具签名冻结、版本协商、多配置/显示状态、面级外观（可选） | 连续 10 次真机回归全绿；语义化版本 + 升级说明 |

排序原则：先做「读多写少、结果可验证」的能力，再做破坏性写操作；每版最多 3–4 个工具，配一篇坑笔记。

## 5. 必须先补的工程能力（横跨各版本）

1. **超时与长任务**：单工具默认超时 300 s，`batch_export` 走后台任务 + `get_task_status` 轮询。
2. **COM 会话健壮性**：SW 崩溃/关闭后自动重连；禁止在未保存文档上 `CloseDoc`（会弹模态框卡死）。
3. **可观测性**：每个工具返回 `elapsed_ms`、`doc`、`warnings`；错误统一 `{ok:false, error, message, hint}`。
4. **无 COM 单测**：调色板校验、零件名归一化、JSON 结构、错误分支；真机回归单独跑。
5. **真机回归夹具**：固定一个公开可用的测试装配（当前为监视器固定支架，46 组件），命令化跑完整链路。
6. **缓存策略**：组件列表按文档路径缓存，结构变更后 `refresh`；禁止在循环里调 `GetComponents`。

## 6. 质量门（每个工具合并前）

- [ ] 真机跑通：dry-run → apply → 复核 → 落盘验证（`GetSaveFlag=false`）
- [ ] 失败路径：文件不存在、只读、同名文档冲突、SW 未启动，均返回结构化错误
- [ ] 性能记录：写入 `docs/com-quirks.md` 与 README 实测表
- [ ] 中文路径/中文零件名可用
- [ ] 不修改原始测试文件：一律在副本上跑

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| SW 版本差异（2020–2024） | 部分 API 行为不同 | 只承诺已验证版本；错误信息带版本提示；收集 issue |
| COM 弹窗阻塞（保存/覆盖提示） | 进程挂死 | 写前静默保存；禁用交互式 API；文档明确禁止 `CloseAllDocuments` |
| 大装配性能 | 工具超时 | 缓存 + 后台任务 + 明确耗时预期 |
| 破坏性写操作 | 用户数据损坏 | 默认 dry-run、快照原值、可回退、只在副本测试 |
| 模型隐私 | 用户不愿上传 | 全本地运行，不联网、不上传 |
| 单人维护 | 迭代中断 | 每版保持小；工具模板化；坑清单即知识备份 |
