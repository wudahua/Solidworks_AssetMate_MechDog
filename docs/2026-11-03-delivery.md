## 五、两条真活的入口

### ① 基准符号：圆圈 → 三角 + 方框

- **现行标准**：GB/T 1182-2018（等同 ISO 1101:2017）——**实心三角形贴在要素上** + 细实线引出 + **方框**内写字母
- **现在画的**：圆圈里写 A + 引线（GB/T 1182-**1996** 画法）
- **要先处理**：`git show c944cdd` —— 那个提交把"圆圈是对的"写成了权威结论，`com-quirks` 里也有。**推翻它之前，下一个动手的人会照着错的做**
- **实现路径**：`add_datum_feature` 目前用 `InsertDatumTag2`；三角要么用图纸草图（**不可用，见 §55**），要么找 `IDatumTag` 的三角选项

### ② GTol 引线穿框格

- **现象**：`bent + perpendicular` 时引线从框格**顶部**起笔、竖直穿过值格压在 `0.008` 上
- **要做**：先算框格 bbox，再从"四角/边中点中离目标最近且不穿 bbox"的那个起笔
- **已知**：`SetLeader3` 只给样式（`LeaderStyle` / `LeaderSide` / `Perpendicular`），**不给起点**。起点由 SW 自己按 `LeaderSide` 选，所以"不穿框"可能得靠**移动框格本身**（`SetPosition`）来规避
- **反馈的临时解**：把框移到目标的斜左下（`0.215, 0.197`）就干净了

## 八、smoke 抓到的那个回归（v0.8.100）

**跑完整 smoke 之前，这一轮所有验证都是离线和定向真机。**

第一次完整 smoke：**34 passed / 1 FAILED**。

失败的是 `reconcile ledger + delivery verdict`：
**"delivery_check reports 0 Ø dimensions while 5 rows have dimension_type==5"**。

**是我的断言在撒谎，不是代码在撒谎。**

smoke 原来这样数 Ø 尺寸：

```python
counted = int("".join(ch for ch in detail.split("+")[1] if ch.isdigit()) or 0)
```

它在**解析一句中文**。0.8.89 把那句改成「仅靠 5 处 Ø 尺寸覆盖（**没有孔标注对象**）」——
**没有 `+` 了**，`split` 抛异常，`counted` 变成 `-1`，于是报"0 个 Ø 尺寸"。

**而那份 payload 明明写着 `diameter_dimensions: 5`。**

改成读结构化字段。**这是这一轮唯一一次"测试本身有问题"**——
前面十几条都是代码问题，这条是**我在 0.8.89 改文案时打断了测试的解析**。

**留下的教训**：断言不要解析人类可读文本。**字段是契约，文案不是。**
